## 문구 검토 기준

humanize-korean의 보수적 윤문과 service-ux-principles를 함께 적용한다. 활동명·실제 소개글·날짜·집계 값·공식 출처는 수정하지 않는다. UI 문구의 명사 나열·시스템 표현·불필요한 반복을 정리한다. 예: `금월치지직 등록 일정` → `이번 달 치지직`, `자동 수집 완료` → `정보를 불러왔어요`. 새로운 다국어 키는 일본어·영어 문구도 함께 반영한다.

## 구현·검증 범위

공통 CSS와 현재 서비스에서 사용하는 포털·활동 통계 컴포넌트에 적용한다. 기존 변경 파일과 운영 데이터는 보존한다. 개발 전용 설정의 Worker·경로·별도 개발 DB를 확인한 뒤 빌드·타입 검사·기존 테스트를 실행한다. 개발 배포 후 공개 경로와 대표 상호작용, 가로 넘침·모바일 하단 가림·언어 전환을 실제 브라우저에서 확인한다.

비공개 관리자 화면은 로그인 이후 실제 데이터 화면에 접근하지 않고 공통 스타일 영향과 소스만 점검한다. 유효한 비공개 확인 키가 필요한 접수 결과 화면은 키 입력 전 화면과 기존 자동 테스트로 확인한다. 이 범위를 전체 기능 실사용 검증으로 표현하지 않는다.

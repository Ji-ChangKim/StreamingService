## 공개 처리와 데이터 보존

- 개발 DB의 원수집 `streamerChannel_info` 380행은 수정하지 않았습니다. 대상 9개의 원수집 행도 전후 완전히 일치함을 확인했습니다.
- 기존 자료 위에 적용되는 `portal_profiles` 정정본 9건과 `portal_profile_history` 변경 전후 이력 9건을 저장했습니다. 프로필 테이블은 6→15행, 이력은 0→9행입니다.
- SQL은 읽어 둔 원수집 값·기존 정정본이 여전히 일치하는 경우에만 저장하도록 구성했습니다. 실제 SQL을 메모리 DB에서 먼저 실행해 대상 밖 자료 보존과 재실행 중복 방지를 검증했습니다.
- 江口真好는 상세·구형 소개 API·배너 API에서 404이며, 공개 소개 목록과 데뷔 목록에서도 제외됐습니다. 관리자 원문과 변경 이력은 남아 있습니다.
- 나머지 8개에 `APPROVED`나 소유권 확인을 새로 만들지 않았습니다. 현재 작업공간에 이미 있던 **`source=EXISTING` 기본 공개 규칙**을 유지한 빌드입니다. 이 규칙이 이번 개발 배포에 포함되어 개발 공개 목록은 0→379개가 됐습니다. **379개가 콘텐츠·권리 검토를 모두 완료했다는 뜻은 아닙니다.** 해당 공개 정책 자체는 이번 정정 작업에서 수정하지 않았습니다.

## 실제 화면에서 발견해 함께 수정한 오류

실제 브라우저에서 검토 기록 없는 기존 소개를 열면 `contentReview.reviewedAt` 접근 때문에 상세 화면이 500 오류로 바뀌는 것을 발견했습니다. HTTP 초기 HTML 검사로는 드러나지 않았습니다.

`frontend/src/portal/CreatorProfile.tsx`에서 검토 기록을 선택적으로 읽고, 실제 검토일이 있을 때만 표시하도록 수정했습니다. 검토일을 임의로 만들지 않습니다. 실제 상세 컴포넌트를 렌더링하는 `frontend/tests/profileReviewDate.test.cjs`를 추가해 기록 없는 소개의 정상 렌더링·시간 미정·검토일 미표시, 승인 기록 있는 소개의 실제 날짜 표시를 검증했습니다. 수정 후 전체 테스트와 빌드를 다시 통과하고 최종 배포했습니다.

재현용 개발 설정·배포 명령:

```powershell
# 저장소 루트에서 기존 작업 설정을 보존한 개발 전용 설정 생성
node backend/scripts/prepareAdsenseDevConfig.cjs
# backend에서 개발 Worker만 배포
npx --yes --package=wrangler@4 wrangler deploy --config .cache/wrangler-p0-content.toml --env dev
```

첫 배포 시도는 Windows의 Workers Sites 절대 경로 결합 문제로 자산 업로드 전에 중단됐습니다. 정적 자산 경로를 설정 파일 기준 상대 경로로 수정해 해결했습니다. 이후 상세 화면 오류를 확인하고 한 차례 추가 배포했으며 위 표는 **오류 수정 후 최종 버전**입니다. DB 정정 SQL은 한 번만 적용했습니다.

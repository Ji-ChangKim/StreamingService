**예약은 실행됐습니다. 그러나 기존 후보 재확인에 조회 예산을 사용해 부분 종료했고, 사용자가 원하는 범용 검색·CSV 입력 등록 경로도 아직 구현되지 않았습니다. ‘서버 예약이 돈다’와 ‘요청한 자동화가 완성됐다’는 별개의 상태입니다.**

## 2. 무엇이 막혀 있나요?

### A. 기존 재확인이 새 공지 확인보다 먼저 예산을 씁니다

현재 `runner.ts`는 원천 목록을 읽고 기존·신규 후보를 같은 대기열에서 처리한 뒤 X 공지 본문 대기열을 확인합니다. 후보 검사에는 공식 채널·이미지·원문 등의 외부 요청이 필요합니다.

상세 검사 전 `net.requests > LIMITS.external - 3`이면 멈춥니다. 공지 본문 확인도 남은 요청량 조건을 통과해야 합니다. 외부 40회 한도 안에서 후속 검사를 위한 여유를 남기는 구조여서, 두 정기 회차 모두 39회 사용 뒤 상세 검사를 넘겼습니다. 상세 후보 상한 20명에 도달한 것이 아닙니다.

비용을 제한한 것은 필요합니다. 문제는 **신규 원문 확인에 쓸 몫을 따로 보장하지 않고 재확인과 경쟁시킨 것**입니다. 월 한도를 단순히 늘리는 것으로 해결할 일이 아닙니다.

### B. 공지 원문을 매일 다시 조사하는 구조도 아닙니다

DB의 X 공지 대기열은 16건이며, 확인 시점에 재처리 시각이 된 공지는 0건입니다. 마지막 원문 검사 시각은 11월 12일 13:56 KST이고, 그날 21시 이후 확인 기록은 없습니다.

코드는 원문 파싱이 끝난 공지를 결과와 관계없이 기본 7일 뒤로 미룹니다. 날짜·행사 범위를 확정하지 못한 HOLD도 같은 간격을 씁니다. 따라서 **이번 두 회차에서 즉시 처리할 원문이 있었는데 예산 때문에 전부 놓쳤다고 단정할 수는 없습니다.** 확인된 사실은 신규 공지용 예산이 따로 없고, 이미 본 공지의 재검사 주기도 임박 일정·보류 이유에 맞춰 나뉘지 않았다는 점입니다.

### C. 범용 웹 검색과 CSV 입력 등록은 미구현입니다

현재 서버는 정해 둔 SOOP 일정·공개 시트·X 계정·공식 공지를 읽습니다. 사람 이름 없는 검색어를 검색 서비스에 보내 인터넷의 새 공지를 넓게 찾는 기능은 연결되지 않았습니다.

현재 저장 경로는 후보 D1 → 검증 → 공개 D1입니다. 로컬 CSV는 별도 정리한 스냅샷이며 서버 CSV 보관함·CSV 입력 등록기는 없습니다. 사용자가 최종 정한 **검색 → CSV → 중복 검사 → DB 등록** 전체가 이미 운영 중인 상태는 아닙니다.

### D. 보류된 후보를 다음 단계로 넘기는 연결이 부족합니다

운영 DB에서 확인한 보류·실패 이유는 다음과 같습니다.

| 이유 | 후보 행 | 판단 |
| --- | --- | --- |
| 소속사 출처 일괄 보류 | 3 | `AGENCY_NOTICE`를 출처만으로 막는 현재 코드 결함. 제거 대상 |
| 연도·일시·행사 범위 미확정 | 2 | 카이리 시엔·히라네코 리에. 날짜 공란인 채로 유지 |

일정·신원이 모호할 때 보류하는 기준은 유지해야 합니다. 다만 필요한 원문을 더 찾는 절차, 이미 승인된 일정 재확인과 빈 프로필 보강의 구분, 출처만 보고 차단하는 결함 수정이 이어져야 합니다. 검증 기준을 낮춰 값을 만들어 넣는 해결은 하지 않습니다.

## 4. 고칠 순서

1. **기존 재확인·임박 일정·신규 발굴의 예산을 분리합니다.** 바뀌지 않은 기존 자료의 반복 조회를 줄이고 신규 원문 확인 몫을 남깁니다. 총 외부 요청 40회 제한은 유지하는 방향으로 설계합니다.
2. **보류 사유별 재검사 시점을 나눕니다.** 임박 일시 확인은 짧게, 운영자 충돌은 근거 변경이나 사람 판단이 있을 때 처리합니다. 모든 HOLD를 매번 비싼 전체 검사로 돌리거나 일괄 7일 미루지 않습니다.
3. **소속사 출처 일괄 보류를 제거합니다.** 개인·소속 신인을 동일한 이름·채널·행사·일시 근거로 판단합니다.
4. **범용 검색과 서버 CSV 입력 경로를 실제로 연결합니다.** 검색 공급자의 비용·허용 범위를 확정하고, 저장된 CSV에서만 신규 공개를 진행하도록 구현합니다.
5. **운영 상태를 확인할 수 있게 합니다.** 마지막 성공·부분 종료·보류·예산 사용·다음 처리 대상을 구분합니다. 새 외부 알림이나 이 대화 게시 기능은 현재 연결돼 있다고 설명하지 않습니다.

현재 한도를 풀거나 보류 후보를 강제 승인하지 않았습니다. 이번 요청은 원인 확인으로 처리했으며 운영 코드·예약·프로필·DB 값은 변경하지 않았습니다. 코드 변경 시험·배포·조사 강제 실행도 하지 않았습니다.

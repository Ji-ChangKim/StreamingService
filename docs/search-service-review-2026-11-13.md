# 신규 버튜버 발굴용 검색 서비스 도입 검토

**검색 서비스 선택 전 검토 기록입니다. 이후 Tavily 키 연결·로컬 실검색을 완료했습니다. 현재 기준은 [신규버튜버자동화 최종 계획](신규버튜버자동화.md), 실제 결과는 [Tavily 시험](tavily-pilot-2026-11-13.md)을 따릅니다. 본문의 ‘미신청·미시험’은 당시 상태입니다.**

2026-11-13 한국시간 기준. 비교 대상은 공개 원천 직접 조회, NAVER API HUB, Brave Search, Tavily Search입니다. 가입·카드 등록·유료 검색·실제 문의는 하지 않았습니다.

**검색 API는 자동화 전체의 필수품이 아닙니다. 정해진 목록 밖의 공지를 찾는 보조 수단입니다. 현재 설계에는 무료 여부보다 ‘출처를 DB에 오래 보관하고 광고 서비스에 사용할 수 있는가’가 중요합니다. 공식 자료 기준 우선 시험 후보는 Tavily이며, 네이버를 먼저 신청하자는 제안은 철회합니다. 실제 한국 신인 발굴 성능은 아직 비교하지 않았습니다.**

## 1. 왜 검색 서비스가 필요한가

현재 수집기는 SOOP 공식 일정과 지정된 시트·X 계정·공식 공지를 읽습니다. 그곳에 글이 올라오면 사람 이름을 몰라도 찾을 수 있습니다. 실제로 이번 서버 시험에서 기존 명단에 없던 슈리리_를 SOOP 공식 일정으로 발견했습니다. 이 과정에는 검색 API가 필요하지 않았습니다.

문제는 **우리가 등록해 둔 목록에 등장하지 않는 치지직 개인 신인**입니다. 본인의 X나 새 공식 공지에만 데뷔를 알리면 기존 원천 조회만으로는 놓칠 수 있습니다. 검색 API는 서버가 사람 이름 없이 키워드를 보내 인터넷에 색인된 공지의 주소를 찾게 해 줍니다.

검색 API는 다음을 대신해 주지 않습니다.

- 로그인·비공개 X 게시물 열람 권한.
- 데뷔일·시간·행사 종류의 사실 확정.
- 모든 신인을 빠짐없이 발견한다는 보장.
- 원문과 이미지의 복제·공개 권리.

일반 검색 화면을 프로그램이 반복해서 읽는 방식은 화면 구조·접근 제한·이용 조건에 영향을 받습니다. API는 정해진 형식과 호출량으로 결과를 받는 연결 방법입니다. 이 대화의 검색 도구가 Cloudflare에 자동 제공되는 것은 아닙니다.

## 2. 우리에게 생기는 이득과 남는 일

| 항목 | 현재 고정 원천 조회 | 검색 서비스 추가 시 |
| --- | --- | --- |
| 모르는 채널의 출발점 | 지정한 공식 목록에 등장해야 함 | 키워드에 잡히는 새 본인·공식 공지까지 확대 가능 |
| 사람의 사전 입력 | 목록에 없는 출처는 사람이 추가해야 함 | 인물 이름 없이 후보 URL을 찾아 전달 가능 |
| 반복 작업 | 원천별 화면·응답을 직접 관리 | 검색 결과는 공통 형식으로 받음. 원문 검증은 여전히 필요 |
| 재방문·서비스 가치 | 이미 확보한 일정·정보의 갱신 | 신규 정보가 실제로 추가될 경우 정보 범위가 넓어짐 |
| 한계 | 원천 밖 공지 누락 | 검색 색인 누락·지연·X 열람 제한은 남음 |

검색 결과가 100개 늘었다고 가치가 100배가 되지 않습니다. **기존 자료에 없고, 원문·채널·행사·일시를 확인할 수 있는 후보가 얼마나 추가됐는지**로 판단해야 합니다.

## 3. 실제 조사 순서

1. 매일 09시·21시 및 주간 회차에 조사 기간과 아직 검색하지 않은 묶음을 정합니다.
2. `치지직 버튜버 데뷔 2026 11월`, `버츄얼 첫 방송 11월 21일`, 다음 달 날짜 등의 검색어를 만듭니다. 인물 이름은 넣지 않습니다.
3. 검색 서비스에서 제목·링크·미리보기를 받습니다. 미리보기의 이름·날짜를 확정값으로 사용하지 않습니다.
4. 중복 URL을 제외하고 본인 X·공식 소속사·공식 방송국 공지를 우선 엽니다. 커뮤니티 글은 원문을 찾는 단서로 사용합니다.
5. 이름·고유 방송국 URL·날짜·시간대·첫 데뷔와 플랫폼 데뷔의 구분을 확인합니다.
6. 서버 CSV에 후보와 근거를 저장합니다. 기존 CSV·운영 DB·대기 채널을 대조합니다.
7. 조건을 통과한 정보만 프로필·방송국 연결·달력에 반영하고 공개 결과까지 맞으면 해당 제안을 T로 바꿉니다.

검색 결과와 실제 데뷔 정보는 분리합니다. AI가 만든 답변을 등록 데이터로 바로 사용하지 않습니다. 생일·소속·국적·데뷔 시간을 추측해서 채우지 않습니다.

## 4. 서비스별 비교

| 선택지 | 검색 범위·특징 | 초기 검색비 | 보관·광고 서비스 적합성 | 현재 판단 |
| --- | --- | --- | --- | --- |
| 기존 공개 원천 직접 조회 | SOOP 공식 일정·연결된 시트·지정 공지 | 별도 검색 API 비용 없음 | 원천별 허용 범위 안에서 사실 검증. 기존 기반 유지 | 주 수집 경로로 유지 |
| NAVER API HUB | 웹문서·블로그·카페 등 구분 검색 | 현재 한시 무료 | 검색 데이터 저장·가공·광고 수익 활용에 제약. 현재의 CSV·DB 축적 설계와 맞는지 확인 필요 | 기본 선택으로 추천하지 않음 |
| Brave Search | 독립 웹 검색 색인 | 1,000회당 $5, 월 $5 크레딧 | 기본 결과 보관 제한이 있어 저장 권한을 따로 확인해야 함 | 가격만 보고 선택하지 않음 |
| Tavily Search | 웹 검색, 원문 URL과 결과 메타데이터 | 월 1,000크레딧 무료, Basic 1회=1크레딧 | 공식 도움말에 무료 상업 이용·출처 URL 장기 보관·공개 활용 안내가 있음 | 우선 소량 시험 후보 |

이 표는 공식 문서의 기능·요금·사용 조건 비교입니다. 네이버나 Tavily 중 어느 쪽이 한국 신인 공지를 더 잘 찾는지 실측한 표는 아닙니다.

### NAVER API HUB를 먼저 권하지 않는 이유

공식 가이드는 한시 무료라고 안내합니다. 그러나 2026-09-20 시행 약관 개정 공지는 검색 결과 제공 목적, 저장·가공·제3자 제공·수익 활용에 제한을 둡니다. 이력용 서버 캐시 등 한정된 예외가 있으나, 그것이 우리 사이트의 영구 프로필 DB·광고 활용 전체를 허용한다는 뜻은 아닙니다. **키가 있다고 자동으로 켜면 안 됩니다.** [공식 요금·기능 안내](https://guide.ncloud-docs.com/docs/apihub-overview), [공식 약관 개정 공지](https://www.ncloud.com/support/notice/all/2243?language=KO)

### Brave가 당장 더 좋은 선택은 아닌 이유

검색 요금은 1,000회당 $5이며 월 $5 크레딧이 있습니다. FAQ에는 기본 API 데이터 보관 금지와 별도 협의 안내가 있습니다. 카드 등록이 필요하며, 선불 충전 0달러로 무료 크레딧을 쓰더라도 카드 확인용 임시 승인 금액이 생길 수 있습니다. 우리에게 필요한 저장 권한과 실제 가입 플랜을 먼저 확인해야 합니다. [공식 요금](https://api-dashboard.search.brave.com/documentation/pricing), [보관·카드·과금 FAQ](https://api-dashboard.search.brave.com/documentation/resources/help-feedback)

### Tavily가 우선 시험 후보인 이유

무료 Researcher 플랜의 상업·광고 지원 앱 이용을 공식 도움말이 허용하고, 출처 URL과 검색 메타데이터의 장기 보관도 안내합니다. 검색 자체를 재판매하거나 API 키를 사용자에게 넘기는 방식은 제외됩니다. 원문 저작권·접근 조건은 여전히 별도로 지켜야 합니다. 검색 결과 원본을 그대로 공동 캐시 서비스처럼 제공하려는 경우에는 플랜 조건을 추가 확인해야 합니다. [상업 이용 안내](https://help.tavily.com/articles/5880393096-permitted-use-customer-applications), [보관 안내](https://help.tavily.com/articles/1612400809-storing-caching-retaining-output), [공개·출처 표시 안내](https://help.tavily.com/articles/4025347510-displaying-publishing-output)

## 5. 월 검색비 계산

가정은 **회차당 검색 최대 4번 × 월 활성 조사 최대 70회 = 월 최대 280번**입니다. 한 번에 결과 10개를 받더라도 결과 10명 모두가 신인이거나 검증 가능한 사람이라는 뜻은 아닙니다.

| 월 검색 횟수 | NAVER 현재 무료 기간 | Brave 할인 전 / 월 무료 크레딧이 전부 남아 있는 경우 | Tavily Basic 무료 1,000크레딧 안 |
| --- | --- | --- | --- |
| 140회: 회차당 2번 | 0 | $0.70 / $0 | $0 |
| 280회: 회차당 4번 | 0 | $1.40 / $0 | $0 |
| 840회: 확장 시나리오, 현재 구현량 아님 | 0 | $4.20 / $0 | $0 |

Tavily는 카드 없이 월 1,000크레딧을 제공하며 Basic은 요청당 1크레딧입니다. Advanced는 2크레딧이므로 840번이면 1,680크레딧입니다. 유료 종량제를 사용하면 크레딧당 $0.008이지만 **우리 제안은 유료 전환·자동 충전 없이 무료 한도에서 중단**하는 방식입니다. [공식 크레딧·가격](https://docs.tavily.com/documentation/api-credits)

무료 크레딧은 해당 계정·워크스페이스의 다른 사용과 합산될 수 있습니다. 무료 정책은 바뀔 수 있으므로 영구 무료라고 보장하지 않습니다. NAVER의 향후 유료 단가는 현재 공식 한시 무료 안내만으로 확정하지 않습니다.

표는 검색 서비스 비용입니다. 기존 Cloudflare 실행·DB 사용량은 별도이며 기존 계정 포함량과 합산됩니다. 검색 4번도 기존 외부 요청 총 40회 안에 들어가고, 검색 서비스를 붙인다는 이유로 40회나 CPU·DB 제한을 늘리지 않습니다.

## 6. 홈페이지와 DB 부담

- 방문자가 페이지를 열 때 검색 서비스를 호출하지 않습니다. 서버 예약이 조사하고 홈페이지는 저장된 프로필만 읽습니다.
- 검색 요약·순위·긴 원문을 방문자에게 전부 전송하지 않습니다. 프로필 화면이 검색 결과 수만큼 무거워지는 구조가 아닙니다.
- 검색 결과 수백 건을 곧바로 프로필 수백 건으로 저장하지 않습니다. 중복 링크 제거와 검증을 거친 정보만 공개합니다.
- 현재 CSV는 별도 R2 가입 없이 기존 D1에 보관합니다. 회차별 CSV 쓰기량은 최대 4MiB, 월 최대 회차는 70회로 제한합니다. 과거 중간 버전은 90일 기준으로 정리하되 현재 정본과 참조 중인 검증 버전은 보호합니다.

## 7. 무엇을 시험한 뒤 결정할 것인가

현재까지 검증한 것은 **공개 원천 → CSV → 중복 검사 → DB·프로필·달력·T 처리**입니다. 실제 새 채널 슈리리_로 확인했습니다. 검색 서비스의 결과 품질 시험은 아직 아닙니다.

서비스를 선택하면 2주 동안 같은 조건으로 평가합니다. 아래는 계획이며 아직 실행하지 않았습니다.

| 측정 | 기록할 내용 |
| --- | --- |
| 검색 회수 | 이름 없는 검색어·조회 시각·대상 기간 |
| 새 링크 | 중복·재게시·이미 알고 있는 원문을 뺀 수 |
| 새 채널 | 기존 사이트·CSV·후보·심사대기에 없던 고유 ID |
| 정보의 질 | 본인 원문·방송국·행사·일시를 실제 확인한 수 |
| 발굴 효과 | 고정 원천만 읽었을 때보다 추가로 확보한 검증 후보 |
| 지연 | 공지 게시에서 발견까지 걸린 시간 |
| 비용 | 검색 크레딧·원문/이미지 요청·DB 읽기·쓰기 |

현재 명단 밖의 검증 가능한 정보를 실제로 추가하지 못하면 호출량부터 늘리지 않습니다. 한국어·날짜·도메인 조건을 조정하고, 그래도 효과가 없으면 해당 서비스 사용을 중단합니다. ‘몇 명을 더 찾는다’는 예상치를 실적처럼 제시하지 않습니다.

## 8. 권고와 현재 상태

**권고:** 기존 공식 원천 수집은 유지하고, Tavily 무료 Basic을 작은 범위의 키워드 발굴 시험 후보로 삼습니다. 검색 결과의 영구 저장과 광고 서비스 활용을 명시한 조건이 우리 구조와 더 잘 맞기 때문입니다. 한국 공지 검색 성능까지 우수하다고 확정한 추천은 아닙니다.

**현재:** 서비스 선택 대기입니다. Naver 시험용 연결 코드만 있으며, 운영은 `SEARCH_PROVIDER=PENDING_SELECTION`, `SEARCH_STORAGE_RIGHTS_APPROVED=false`로 잠갔습니다. Tavily 연결부는 아직 구현·활성화하지 않았습니다. 이 보고서는 가입이나 결제를 요청하는 문서가 아니라 사용자가 선택할 근거입니다.

선택 후에는 해당 서비스 연결부 구현, 서버 비밀키 등록, 무료·월 사용량 상한, 이름 없는 실제 검색 시험, 결과 비교 순서로 진행해야 합니다. 그 전에는 키워드 검색까지 완료됐다고 보고하지 않습니다.

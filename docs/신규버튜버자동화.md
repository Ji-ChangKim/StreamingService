# 신규버튜버자동화

운영·기술 정본 · 2026-11-18

**월·수요일에는 모르는 채널과 데뷔 공지를 찾고, 일요일에는 그 주 등록자의 빈 프로필을 조사한다. 확인된 정보만 방송국·프로필·달력에 연결한다.**

쉽게 말하면 **검색해서 소개 글 찾기 → 진짜 본인 글인지 읽기 → 조사 공책(CSV)에 쓰기 → 우리 명단과 비교 → 화면에 넣기 → 다시 확인하기**다. 사이트 방문자는 승인된 DB를 읽으며 검색이 끝날 때까지 기다리지 않는다.

최신 실제 결과는 [통합 수정·배포 보고서](automation-completion-2026-11-18.md)다. 모의 검사와 실제 운영 결과, 새 후보·DB 저장·공개 완료는 구분한다.

## 1. 현재 상태

- Cloudflare `vdebut-discovery` 정규 조사에 Tavily Basic을 연결했다. 서버 비밀값을 쓰며 브라우저에 키를 보내지 않는다.
- 실제 통합 검색 10회·10크레딧, 새 조사 주소 17행을 보관했다. 주소 수는 사람 수가 아니다.
- 기존 미처리 7건은 실제 프로필 재조사를 마쳤다. 새로운 공식 정보가 없는 빈 항목은 그대로다.
- 자동 발굴된 SOOP 후보 해짜:o·노니_의 방송국·공식 프로필·달력·CSV T를 확인했다. 수요일 F 6건도 재등록 없이 공개 확인을 복구했다.
- 실제 Tavily 검색을 통해 새로 공개된 치지직 신인은 이번 시험에서 0명이다. 지원 원문의 전체 공정은 모의 신규 채널로 검사했고, 실제로 원문 확정이 안 된 단서는 보류했다.
- 마지막 서버 시험은 `COMPLETED_WITH_HOLDS`, 오류·실패·현재 회차 미처리 0, 원문 보류 2건이다. 운영 전체 보류가 2건뿐이라는 뜻은 아니다.
- 공개 프로필·캘린더 456건의 유형·시각·방송국 링크가 일치했다. 기존 454건의 공개 내용은 보존했다.

## 2. 언제 무엇을 조사하는가

모두 한국시간이며 PC를 꺼도 Cloudflare 예약이 실행한다.

| 회차 | 역할 | 대상 기간·우선순위 |
| --- | --- | --- |
| 월요일 10시 | 신규 발굴·이번 주 일정·미완료 보강 | 30일 전~90일 후. 오래 기다린 보강·임박 일정 먼저 |
| 수요일 10시 | 신규 발굴·일정 변경 확인 | 7일 전~30일 후. 다음 회차까지 일정 포함 |
| 일요일 10시 | 그 주 기존 등록자 프로필 조사 전용 | 월요일~일요일 조사 시각까지 일정이 지난 기존 등록자. 신규 발굴 검색·목록 수집 없음 |

일요일 조사 시각 이후의 방송과 당일 시각 미정은 데뷔한 것으로 세지 않는다. 예정일이 지났다고 실제 방송 완료를 표시하지 않는다. 다음 회차 전 일정은 수→일의 4일 간격도 포함한다. 신규 공지·변경을 매일 즉시 반영하는 서비스나 데뷔자 전수 발견을 보장하지 않는다.

일요일 원문에서 명시된 생일·종족·신장·MBTI·팬덤명·오시 마크·팬아트 태그·주요 콘텐츠·방송 시간 등을 조사한다. 기존 값은 덮어쓰지 않고 빈 값만 확인된 사실로 보완한다. 치지직은 현재 채널 소개의 명시 정보 중심이며 SOOP은 본인 프로필/소개 게시물도 확인한다. 국적·소속·생일·캐릭터 제원을 추측하지 않는다.

## 3. 어디서 이름 없는 채널을 찾는가

| 원천 | 처리 |
| --- | --- |
| SOOP 웰컴버추얼 | 기존 공개 일정 응답에서 이름·행사 일시·고유 방송국·행사 종류 확인 |
| Tavily Basic | X 개별 게시물, 치지직 커뮤니티 개별 글, SOOP 개별 게시물을 날짜·플랫폼 키워드로 검색 |
| 기존 공개 시트·공지 계정·공식 소속사 | 새 일정과 본인 원문으로 가는 단서. 소속 신인도 포함 |

공식 페이지의 내부 일정 응답을 정식 상업용 개발자 API라고 표현하지 않는다. 치지직 전체 채널·모든 채팅은 수집하지 않는다.

`tavilyDiscoveryQueries()`는 오늘·2/4/7/14/21/30일 후·최근 누락 날짜와 원천을 순환한다. 날짜는 실행일을 기준으로 만들고 마지막 성공 커서를 `debut_automation_sources.cached`에 남긴다. 미래 데뷔일을 문서 게시일 필터로 쓰지 않는다.

검색은 `POST https://api.tavily.com/search`, `basic`, 결과 최대 10개, `auto_parameters=false`, `include_usage=true`다. 답변·원문 전체·이미지는 요청하지 않는다. 일반 위키·태그·목록 페이지는 공지 대기열에 넣지 않는다. 개별 글의 주소·짧은 제목만 내부 조사 CSV에 남기고 검색 요약은 공개 사실로 사용하지 않는다.

보강 대기가 8건 이상이면 검색 최대 2회, 20건 이상이면 1회로 줄인다. 평소 최대 4회다. 새 검색 단서 1개와 오래 기다린 원문 1개를 우선 읽는다. 커뮤니티/SOOP 글에서 본인 X 글을 발견하면 원문 대기열로 넘긴다. 작성자 관계·행사 범위를 확인하지 못한 글은 자동 공개하지 않는다.

## 4. 저장부터 공개 확인까지

1. 월 사용량·실행 슬롯·전역 잠금을 확보한다. 같은 슬롯은 다시 실행하지 않는다.
2. 기존 플랫폼 데뷔 프로필과 공개 달력의 계약을 먼저 검사한다. 틀리면 검색·신규 저장 전에 중단한다.
3. 검색과 허용된 고정 원천을 읽어 공지 대기열에 넣는다. 원문 확인 전에는 조사 F다.
4. 본인/공식 원문에서 누구·언제·어디서·어떤 행사를 확인한다. X 글은 작성자와 채널의 공식 관계도 대조한다. 날짜·시간·시간대·행사 범위가 모호하면 보류한다.
5. 서버 CSV를 저장하고 해시·재읽기로 확인한다. 공개 입력은 재읽은 검증 자료다.
6. 플랫폼+고유 채널 ID·대표/보조 채널·구형 목록·심사대기·기존 CSV를 대조한다. 이름만 없다는 이유로 신규로 판정하지 않는다.
7. 기존 미완료 보강을 신규 상세 조회보다 먼저 처리한다. 바뀌지 않은 공개 정보는 CSV 영수증과 묶음을 반복 저장하지 않는다.
8. 새 프로필·검증된 변경은 기존 저장 함수의 원자적 보호로 반영한다. 운영자 수정·심사대기·동시 변경과 충돌하면 보류한다.
9. 공개 프로필·방송국·이미지·행사 종류·시각·시간대·기본 활동권역·달력을 대조한다. 반영 확인 후 해당 CSV 제안만 T다.
10. 실패한 이전 공개 확인은 저장 영수증으로 이어받는다. 이미 저장한 프로필을 다시 만들지 않는다.

첫 버튜버 데뷔·플랫폼 데뷔·이적·프리데뷔·모델 공개를 섞지 않는다. 채널의 첫 방송 날짜 누락/null은 과거 활동이 없다는 근거가 아니다. 국적과 활동권역도 별개다.

## 5. DB·CSV와 변경 보호

| 저장소 | 역할 |
| --- | --- |
| `debut_automation_runs/months/control` | 실행·월 예약량·전역 잠금 |
| `debut_automation_sources` | 원천 상태·캐시·검색 커서·보강 대상 목록 |
| `debut_automation_notices` | 원문 주소·최초 발견·다음 확인·보류/실패 |
| `debut_automation_candidates` | 고유 채널·검증 상태·필드 근거·실제 확인 시각·보강 완료 주 |
| `debut_search_usage` | 월 검색 크레딧 선예약·보고 사용량·성공/실패 횟수 |
| `debut_csv_months/revisions/receipts` | CSV 원문·버전·해시·공개 반영 증명 |
| 기존 프로필·채널·변경 이력 | 사이트가 읽는 공개 승인 정보 |

별도 `debut_search_tasks` 테이블을 만들지 않고 기존 원천 커서와 공지 대기열을 재사용한다. API·비밀키는 Cloudflare secret에 보관한다. 로컬 월 CSV는 사본이며 PC 파일을 서버가 직접 읽는 구조가 아니다.

CSV는 신규 13열·수정 14열·조사 26열, UTF-8 BOM·CRLF다. 최초 작성일·기존 T/F를 보존한다. 변경 없는 의미의 일정은 확인시각만 바꾸려고 묶음을 다시 저장하지 않는다. 실제 조회 시각은 후보/실행 기록에 남긴다. [CSV 안내](../vtuber-list/README.md)

필드마다 실제 추출한 원문을 기록한다. 이전 자동 생성 행의 기본 데뷔 공지 주소가 잘못 들어간 경우에만, 현재 값 일치·충돌 없음·원래 기본 주소 확인 뒤 근거를 교정한다. 운영자가 별도 지정한 출처·최초 작성일·T/F는 덮어쓰지 않는다.

일요일과 월요일의 같은 주 보강은 `profile:시작일:종료일`로 합친다. 완료한 주의 중복 대기는 실제 확인시각을 꾸미지 않고 다음 정규 회차로 정리한다. 불명확한 게시물·단순 목록 부재·조회 실패만으로 공개 등록을 삭제하지 않는다.

## 6. 비용·자원 상한

| 항목 | 운영 제한 |
| --- | --- |
| Tavily | 정규 월 선예약 최대 64크레딧, 기존 앱 상위 280 방어 한도 유지. 같은 표의 시험·실패 예약 포함 |
| 검색량 | 월·수 회차 최대 4회, 보강량에 따라 2/1회. 일요일 0회 |
| 월 활성 실행 | 정규·시험·재실행 합계 최대 70회 |
| 외부 요청 | 회차 최대 40회, 동시 최대 3개. 실패·리디렉션 포함 |
| 원문/이미지 | 본문 최대 2MiB. 새 이미지 허용 CDN·래스터·크기 검사. 기존 승인 동일 URL은 HEAD 확인 |
| DB | 회차 호출 220회·읽기 30,000행·쓰기 700행. 소량 마감 기록 별도 |
| CSV | 월별 묶음 512KiB·회차 누적 쓰기 4MiB |
| 실행 | CPU 5초 설정·전체 150초 제한, 검증/마감을 위해 수집 단계에 여유 확보 |

키가 붙는 검색은 고정 HTTPS 호스트로 POST하고 자동 리디렉션하지 않는다. 크레딧을 요청 전에 원자적으로 예약하고 응답 불명·실패 예약은 임의 환불하지 않는다. 초과 시 중단·사유 기록이며 유료 검색으로 자동 대체하지 않는다.

월·수 정상 8~10회×최대 4검색으로 월 32~40크레딧을 예상한다. 재실행은 합산하며 월 64에서 차단한다. 이번 검증 후 예약 24·응답 보고 21크레딧이다. 계정 다른 사용량·청구액은 별도이며 종량제·자동 충전·결제 설정을 바꾸지 않았다. [Tavily 요금](https://docs.tavily.com/documentation/api-credits)

## 7. 보류·실패·완료의 뜻

- 작성자·날짜·시각·행사 범위 미확인: F와 사유. 다른 사람의 글을 본인 원문으로 바꾸지 않는다.
- 원문 차단·429·통신/크기 제한: 해당 원천의 실패/보류와 다음 확인을 기록한다. 미조사를 신규 0명 성공으로 표시하지 않는다.
- 운영자 수정·심사대기 충돌: 기존 값 보존. 자동 수정·삭제하지 않는다.
- 조회 한도: 커서·대상·실제 확인시각을 남겨 다음 회차가 이어받는다. 전체 40회보다 작은 개별 단계 때문에 보강이 계속 밀리지 않게 한다.
- 공개 검사 실패: F와 공개 확인 대기 유지. 다음 회차는 기존 영수증에서 복구한다.
- `COMPLETED_WITH_HOLDS`: 현재 처리 범위의 시도를 마치고 확정 못 한 건을 보류한 상태다. 인터넷 전체 조사·모든 빈 항목 충족·운영 전체 보류 해소를 뜻하지 않는다.

성과는 URL 수보다 새 고유 채널·공식 근거·검증 공개·빈 항목 수정·최고 대기시간·보류 이유·실제 사용량으로 판단한다. 지난 날짜를 실제 방송 완료로 추정하거나 원문 없는 정보를 채워 성과를 늘리지 않는다.

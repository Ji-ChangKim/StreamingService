진행 중인 다른 화면 개편 작업은 작업공간에 보존하고, 위 소스 기준을 별도 폴더에서 빌드했습니다. 격리 작업본은 검증된 현행 의존성을 참조했으며 원본 의존성이나 패키지 버전을 변경하지 않았습니다. 기존 소개에 검토일이 없을 때 상세 화면이 실패하던 문제를 수정한 버전과 해당 렌더링 회귀 테스트를 포함했습니다.

운영 전용 설정은 `backend/scripts/prepareAdsenseProductionConfig.cjs`가 읽기 전용 Cloudflare 설정 확인 자료로 생성했습니다. 실제 운영의 기존 사용자 도메인 `vdebut.live`, `dev.vdebut.live`, DB·KV 바인딩, workers.dev·미리보기 설정, 일반 환경 변수 이름과 수집 스케줄을 적용 전후 대조했습니다. 개발 Worker는 배포하지 않았고 개발 공개 API 379개 자료도 전후 일치했습니다.

기존 수집 스케줄 `*/10 * * * *`, `0 22 * * *`는 그대로 유지했습니다. 운영 사이트는 공개 경로의 색인을 허용하고, 관리·비공개·오류 페이지는 noindex를 유지했습니다. 광고 전역 설정은 `false`이며 GTM 자동 실행도 보류한 검증 버전을 반영했습니다. 직접 설치된 Google Analytics의 실제 계정 설정은 별도 확인 대상입니다.

실제 배포 명령은 저장소 루트에서 다음과 같습니다.

```powershell
npx --yes --package=wrangler@4 wrangler deploy --config .cache/wrangler-adsense-production.toml --env production
```

위 캐시 설정은 이번 격리 배포본과 사전 확인 설정을 가리킵니다. 다음 배포에서는 원래 설정 파일을 그대로 쓰기 전에 실제 도메인·DB·스케줄을 다시 대조해야 합니다. 대상 9건 복구 SQL은 데이터 복구용입니다. Worker 버전을 되돌릴 때는 정적 자산도 함께 맞춰 배포해야 합니다.

## 1. 결론

**이름을 몰라도 SOOP 공식 웰컴버추얼 일정에서 대상 기간의 채널을 발견할 수 있었다.** 공식 일정 11건 중 `debut` 9건, `transfer` 2건이었다. 이 가운데 데뷔 채널 **5개는 기존 조사 CSV에 없었다.** 그중 우디디디는 본인 프로필에 방송 시작일도 명시되어 있었다.

치지직에서는 날짜·데뷔 키워드 검색으로 후보를 찾은 뒤 본인 X와 채널 주소를 연결했다. 아먕·레오 퍄코·코바야시 후토의 일정과 채널은 재확인했지만, **이 3명은 기존 기록에 있던 인물이며 이번 신규 발굴 실적으로 세지 않는다.** 치지직의 미등록 신인을 새로운 확정 후보로 확보했다고 보고할 수는 없다.

‘SOOP 데뷔’는 모든 플랫폼을 통틀어 최초 버튜버 활동이라는 뜻과 다르다. 아래에서 본인 데뷔 공지 확인, 플랫폼 데뷔 확인, 최초 여부 보류를 구분했다. 본인 공지가 있어도 알려지지 않은 과거 활동까지 없다고 입증한 것은 아니다.

## 6. 기록 정정·비용·다음 작업

- 기존 조사 기록의 ‘치지직 `firstBroadcastDate=null`이므로 과거 방송 없음’이라는 해석은 근거가 부족했다. 이번 응답에서 아먕·레오 퍄코·후토의 해당 필드가 제공되지 않은 것을 과거 이력 부재로 단정하지 않는다. 검증 근거를 정정한 조사 행은 F로 되돌리고, 일정·채널이 같은 기존 신규 등록 CSV의 T는 유지했다. 서비스에서 등록을 취소하거나 변경한 것은 아니다.
- 이번 실행에서 신규 서버·DB·외부 유료 API를 개설하거나 결제하지 않았다. **추가 인프라·외부 API 결제 0원**. 기존 이용 도구 비용과 사람의 확인 시간을 제외한 값이며, 자동 운영의 월 비용을 실측한 결과는 아니다.
- 다음에 개발한다면 먼저 ‘발견 출처·원문 URL·공지일·행사 종류·채널 ID·일시·검수 상태’를 저장하는 후보함을 만들고, 운영 DB와 분리한다. 신규 여부는 이름 대신 채널 ID로 비교한다.
- 시간·연도·본인 채널 연결까지 일치한 후보만 검수로 보낸다. 첫 활동 범위가 모호한 경우는 보류한다. 승인 전 화면에는 노출하지 않는다.
- 이번 테스트는 수동 조사로 수집 흐름을 재현했다. 자동 수집 코드, 정기 실행, API 사용 권한·계약, 관리자 승인 화면, 실제 DB 반영 기능은 구현하지 않았다.

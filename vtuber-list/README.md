# VTuber List

버튜버 조사 자료를 지속적으로 갱신하는 프로젝트 정본 폴더다. 월별 CSV 3종을 유지하며, 조사할 때마다 별도 사본을 만들어 정본을 나누지 않는다.

## 폴더와 파일

폴더는 영문 소문자와 하이픈, 조사 대상 월은 `YYYY-MM` 형식을 사용한다.

```text
vtuber-list/
├── README.md
└── 2026-11/
    ├── new-debuts.csv
    ├── profile-updates.csv
    └── research-log.csv
```

| 파일 | 용도 |
| --- | --- |
| [2026-11/new-debuts.csv](2026-11/new-debuts.csv) | 공식 출처로 날짜·시각·채널을 확인한 신규 데뷔 등록 후보 |
| [2026-11/profile-updates.csv](2026-11/profile-updates.csv) | 기존 프로필의 수정 항목별 변경 전·후 값과 공식 근거 |
| [2026-11/research-log.csv](2026-11/research-log.csv) | 전체 후보의 출처·확인 시각·기존 등록 대조·보류 및 제외 사유 |

다음 달 조사는 같은 구조의 새 월 폴더에서 관리한다. 기존 월의 일정이나 프로필을 재확인하는 작업은 해당 월의 CSV를 갱신한다. 이전에 전달한 Codex 시각화 폴더의 사본 대신 이 폴더를 기준으로 작업한다.

## 작성일과 업데이트 상태

모든 CSV의 A열은 `작성일`, 마지막 열은 `업데이트 여부 T/F`다.

| 항목 | 규칙 |
| --- | --- |
| 작성일 | 이 목록에 최초로 추가한 한국시간 날짜, `YYYY-MM-DD`. 재조사하거나 내용을 정정해도 유지한다. |
| F | 해당 행의 등록·수정 제안을 아직 시스템에 반영하지 않은 상태. 신규 행의 기본값이다. 보류·제외 행도 F로 남긴다. |
| T | 해당 행의 등록·수정 내용을 실제 시스템에 반영했음을 확인한 상태. CSV 작성·검증만으로 T로 바꾸지 않는다. |

기존 행의 내용이 같으면 작성일과 T/F를 보존한다. T인 행에 새로운 정정 사항이 생기면 작성일은 보존하고 F로 되돌린다. 공식 출처를 다시 확인한 시각은 조사 기록의 `확인시각`에 따로 기록한다. 기존 등록 여부와 출처 검증 여부는 T/F와 구분한다.

## 같은 목록을 갱신하는 절차

1. 먼저 해당 월의 CSV 3종을 읽고 기존 후보·내용·작성일·T/F를 확인한다.
2. 공식 본인 채널, 공식 X 게시물, 소속사 공지, 플랫폼 공식 캘린더를 확인한다. 검색 결과나 재게시 자료만으로 값을 확정하지 않는다.
3. 아래 식별 기준으로 기존 행을 찾아 갱신한다. 새 후보만 행을 추가하고, 추가 당일 날짜와 F를 기록한다.
4. 확인된 값만 채운다. 미공개 정보는 공란으로 두고, 근거가 상충하거나 일정·시간대가 불명확하면 조사 기록에 사유를 남긴다.
5. 시간 미정·연기·취소 등으로 신규 등록 조건을 충족하지 못하게 된 후보는 신규 등록 CSV에서 제외하고 조사 기록을 보존한다. 재데뷔·아바타 공개·이적을 첫 데뷔로 합치지 않는다.
6. 기존 프로필 수정은 한 행에 한 항목을 기록한다. 변경 전 값은 조회 시점의 시스템 값이며, 이전 조사 파일의 값을 현재 시스템 값으로 단정하지 않는다.
7. 파일별 행 수, 중복, 열 순서, 작성일, T/F, 출처 및 날짜·시간을 확인하고 변경 사항을 보고한다.

| 파일 | 기존 행 식별 기준 |
| --- | --- |
| new-debuts.csv | 플랫폼 + 정규화한 채널 ID/채널 URL |
| profile-updates.csv | 프로필식별자 + 수정항목 |
| research-log.csv | 후보ID. 채널 주소 별칭이 바뀌어도 동일 채널이면 기존 ID를 유지한다. |

이름만으로 동명이인을 병합하지 않는다. 확인된 채널 URL은 추적 인자와 주소 별칭을 정규화해 비교한다. 채널을 모르는 후보가 나중에 확인되면 기존 조사 행을 보완하고 중복 후보를 새로 만들지 않는다.

## CSV 형식과 현행 업로더

- UTF-8 BOM, 쉼표 구분, CRLF 줄바꿈을 유지한다. 쉼표·따옴표·줄바꿈을 포함한 셀은 CSV 규칙에 맞게 인용한다.
- 신규 등록 CSV는 기존 등록 열을 유지하고 작성일과 T/F만 앞뒤에 둔다. 현재 13열이며 A열은 작성일, M열은 T/F다. 수정 제안은 14열(A/N), 조사 기록은 26열(A/Z)이다.
- 신규 등록 CSV의 날짜는 `2026-11-07 (KST)`처럼 저장한다. 현행 업로더의 날짜 자동변환을 피하기 위한 표기이며, 업로더는 실제 날짜를 `2026-11-07`로 읽는다. 시작 시간은 `HH:mm`이다.
- 업로더는 시간 공란을 `19:00`으로 바꾸므로 시간 미정 후보를 신규 등록 CSV에 넣지 않는다.
- 소속·국가 공란도 업로더에서 각각 `개인세`, `KR`로 바뀐다. 미확인 값을 기본값으로 확정하지 않도록 반영 전에 확인한다.
- 업로더는 작성일과 T/F를 시스템에 저장하거나 T/F로 행을 자동 필터링하지 않는다. 실제 업로드가 요청되면 반영할 행만 별도로 추출한다. T인 행까지 포함한 정본 전체를 반복 업로드하지 않는다.
- 파일을 갱신하는 작업은 서비스·DB 등록, 승인, 배포를 포함하지 않는다. 실제 반영은 별도 요청과 반영 결과 확인을 거친다.

이 폴더에 자동 조사 일정이나 자동 DB 반영 기능은 연결되어 있지 않다. 기존 보고 전용 조사 기능의 범위는 [운영 절차](../docs/debut-investigation-runbook.txt)를 참고한다.

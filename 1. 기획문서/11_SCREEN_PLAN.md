## 1. 계획의 기준

각 화면을 **URL / 설명 / 핵심 전달 내용**으로 정의한다. 설명은 화면의 역할이며, 핵심 전달 내용은 방문자가 화면을 보고 이해해야 할 가치다. 핵심 전달 내용은 실제 화면에 그대로 넣을 홍보 문구가 아니다.

메인은 월별 데뷔 캘린더를 유지한다. 통계는 팬의 콘텐츠 탐색과 버튜버의 활동 판단을 함께 지원한다. 개인 소개는 버튜버의 특징을 알아보는 중심 화면으로, 직접 등록은 자신의 데뷔와 특징을 알리는 참여 경로로 삼는다. 전체 버튜버 조회는 장기 통합 비전으로 확장한다.

> [!NOTE]
> 아래 ‘기존 URL’은 2026-10-11 작업 공간의 화면·라우팅 코드를 기준으로 확인했다. 미배포 변경이 포함될 수 있으며, 표의 핵심 전달 내용은 PRD에 맞춰 완성할 화면 목적이다. 현재 서비스에서 모든 내용이 제공된다는 뜻이 아니다. ‘추가 URL안’은 미구현 제안이며 상세 설계에서 확정한다. `{slug}`, `{channelKey}`, `{submissionId}`는 실제 대상의 식별값으로 바뀌는 자리다.

| `https://vdebut.live/submissions/{submissionId}` | 신청 상태·결과 확인 화면. 접수·검토·보완 요청·공개 결과와 공개된 소개 주소를 신청자가 확인한다. | **내 데뷔 신청이 어디까지 진행됐고 다음에 무엇을 해야 하는지** 알 수 있다. 공개가 끝나면 팬에게 전달할 소개 페이지로 이동한다. |

신청 상태 확인은 PRD의 P0 요구다. 위 주소는 제안이며, 계정 또는 별도의 안전한 조회 수단을 먼저 정한다. 주소를 아는 것만으로 신청 정보와 관리 권한을 얻는 구조로 만들지 않는다. 접수 완료·보완 요청·공개 완료는 이 화면의 상태로 다루며 각각 별도 페이지를 늘리지 않는다.

기간·카테고리·검색어 등은 필요에 따라 기존 URL의 조회 조건으로 유지한다. 한 화면의 필터·탭·팝업을 모두 새 URL로 분리하지 않는다. 현재 개발용 경로 `/updatepage`, `/upadepage`와 API 주소는 공개 화면 목록에서 제외한다.

## 7. 화면 연결과 PRD 대응

| 이용 흐름 | 화면 연결 | PRD 요구사항 |
| --- | --- | --- |
| 데뷔자를 만나는 팬 | 메인 캘린더 → 개인 소개 → 대표 콘텐츠·공식 방송 | VDB-01, 04, 05, 09 |
| 콘텐츠로 찾는 팬 | 방송 통계 → 카테고리·방송 탐색 → 개인 기록·확인된 버튜버 소개 → 공식 방송 | VDB-04, 06, 08, 14 |
| 직접 홍보하는 신인 | 데뷔 등록 → 접수·상태 확인 → 공개된 소개 → 공유 | VDB-02, 03, 05, 09, 10 |
| 활동 방향을 검토하는 버튜버 | 전체·플랫폼 통계 → 시간대·콘텐츠 조건 → 개별 방송 기록 | VDB-06, 07 |
| 기존 페이지를 관리하는 본인 | 전체 조회·기존 소개 → 본인 확인 → 소개 관리·홍보 결과 | VDB-11, 12, 15 |
| 다시 찾아오는 팬 | 관심 목록 → 개인 소개·이후 활동 → 관련 버튜버 | VDB-13, 14 |

P1 화면이 필요한 흐름은 해당 확장 단계에서 완성한다. P0에서는 현재 확보된 조회·소개·방송 연결과 직접 등록의 기본 흐름을 우선 검증한다.

## 8. 화면 검토 기준과 근거

- 각 화면에서 방문자가 이해할 핵심 내용과 다음 행동이 일치해야 한다.
- 캘린더는 신규 데뷔, 통계는 인기·콘텐츠·시간, 개인 소개는 특징과 만날 곳을 중심으로 구성한다.
- 확보한 대상·지원 지표·국가·방송 플랫폼 범위를 실제보다 넓게 표현하지 않는다.
- 국가와 방송 언어를 구분하고, 팬의 현지 시각으로 일정을 이해할 수 있게 한다.
- 동일 인물의 소개와 채널별 기록을 연결하되, 확인되지 않은 대상을 임의 병합하지 않는다.
- 공유 주소로 직접 들어와도 해당 인물·일정·조회 맥락을 이해할 수 있어야 한다.
- 모바일·키보드 사용과 상세에서 이전 탐색으로 돌아가는 흐름을 확인한다.

기존 URL 근거는 `frontend/src/App.tsx`, `frontend/src/components/analytics/ActivityDashboard.tsx`, `shared/activitySeo.ts`, `backend/src/services/activityPageService.ts`다. 화면의 역할과 확장 범위는 [PRD v3.0](./01_PROJECT_PRD_MVP.md)을 따른다. 이 문서는 화면 목적 계획이며, 실제 문구·레이아웃·컴포넌트·권한·새 주소의 구현은 후속 설계에서 확정한다.

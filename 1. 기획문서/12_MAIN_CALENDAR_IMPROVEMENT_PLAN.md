## 1. 화면의 목적

**월별 달력을 바탕으로 누가 언제 어디서 신규 데뷔하는지 알아보고, 관심 있는 버튜버의 소개와 실제 방송으로 이어지는 화면**으로 만든다. 데뷔를 준비하는 버튜버에게는 자신의 소식을 직접 등록할 수 있는 곳임을 알린다.

| 사용자 | 알아야 할 내용 | 핵심 행동 |
| --- | --- | --- |
| 팬·방문자 | 어떤 버튜버가 어느 날짜·시간에 어떤 플랫폼에서 데뷔하는가 | 날짜·예정자 선택 → 소개 확인 → 일정 저장 또는 공식 방송 방문 |
| 데뷔 준비생·신입 | 나도 데뷔 소식과 소개를 등록할 수 있는가 | 데뷔 등록 진입 → 다음 등록 화면에서 신청 |

상단의 핵심 전달 문구는 **“신규 버튜버 데뷔 캘린더”**로 한다. 방문자가 페이지의 제공 내용을 바로 이해하고 검색에서도 같은 주제를 전달하도록 정의한다. 서비스 슬로건 **“버튜버와 팬의 소개팅”**은 브랜드 보조 문구로 유지한다. 메인에 전체 버튜버 정보·통계·사업 기능을 모두 펼치지 않고 데뷔 발견이라는 역할을 중심으로 구성한다.

## 2. 현재 관찰과 개선 과제

2026-10-11 운영 메인의 로딩 전후 화면 및 작업 공간 코드를 확인했다. 아래는 이번 확인 범위의 관찰이며, 이용률·전환율 저하가 실제로 측정됐다는 뜻은 아니다.

| 현재 관찰 | 개선 과제 |
| --- | --- |
| 상단 소개·수치 카드·플랫폼별 쇼케이스가 달력보다 앞에 있으며, 확인한 PC 첫 화면에서는 날짜 격자가 보이지 않았다 | 소개 영역을 간결하게 하고 달력을 상단의 주된 콘텐츠로 배치 |
| 쇼케이스 기본 플랫폼이 SOOP로 고정돼 있고, 해당 대상이 없는 상태에서도 큰 빈 영역이 먼저 나타났다. 다른 플랫폼에는 대상이 있었다 | 전체 플랫폼을 기본으로 탐색하고, 실제 대상이 없으면 빈 대형 쇼케이스를 유지하지 않음 |
| 쇼케이스 플랫폼 탭과 달력의 플랫폼 필터가 분리돼 있다 | 메인 탐색 조건을 한곳에서 선택하고 달력·예정자·미정 목록에 일관되게 적용 |
| 플랫폼 탭 숫자는 현재·향후 일정, 상단 숫자는 해당 월 일정 등 서로 다른 범위를 사용한다 | 선택한 기간·조건을 쉽게 이해하게 하고, 의미가 다른 수치를 같은 모집단처럼 배치하지 않음 |
| 달력은 플랫폼·시각·이름을 보여주지만 쇼케이스 카드에는 방송 특징을 이해할 소개가 부족하다 | 달력은 간결하게 유지하고 예정자 카드에서 실제 소개 한 줄을 제공 |
| 데스크톱 달력의 조작 영역에는 이름 검색과 현재 시간대가 드러나지 않는다 | 데뷔자 이름 검색과 시간대 확인·변경 진입 제공 |
| 국가 선택에 KR·JP와 EN이 함께 있고 미국 국기로 EN을 표시한다 | 국가와 언어를 구분하고 영어권을 한 국가로 표시하지 않음 |
| 로딩 초기에 0과 ‘일정 없음’이 보이고 이후 실제 결과로 바뀌었다. 코드에 총인원 123 대체값도 있다 | 로딩·실패·실제 0을 구분하고 임의 인원 대체값을 제거하는 요구 정의 |
| 코드의 LIVE 판별은 일정 시작 후 4시간 범위를 사용한다 | 실제 방송 상태 확인이 없으면 ‘방송 중’으로 단정하지 않도록 상태 표현 수정 |

## 3. 개선 방향

### 3.1 화면 배치 순서

| 순서 | 영역 | 정의 |
| --- | --- | --- |
| 1 | 공통 헤더 | 로고·데뷔 일정·방송 통계·언어 선택·데뷔 등록 진입을 유지 |
| 2 | 간결한 소개 | ‘신규 버튜버 데뷔 캘린더’를 핵심 제목으로 표시하고 데뷔 날짜·시간·방송 플랫폼을 확인할 수 있다는 짧은 안내 제공. 슬로건은 보조 문구로 사용. 큰 무대 배경·다수 집계 카드가 달력을 밀어내지 않게 구성 |
| 3 | 달력 조작·조건 | 선택 월·이전/다음·오늘·월간/주간, 플랫폼·국가·이름 검색·시간대 |
| 4 | 데뷔 달력 | PC는 월간 격자를 기본으로 날짜·시각·플랫폼·이름을 보여줌 |
| 5 | 예정자 소개 | 선택한 월·조건에 맞는 가까운 데뷔자를 간결한 카드로 소개. 기존 대형 쇼케이스의 역할을 이 영역으로 재구성 |
| 6 | 일정 미정 | 해당 월의 날짜·시간 미정 대상을 확정 일정과 구분해 소개 |
| 7 | 등록 안내 | 등록하면 소개와 일정이 공개된다는 실제 제공 가치를 설명하고 신청으로 연결 |
| 8 | 푸터 | 서비스 소개·가이드·문의·정책 연결 유지 |

장식과 색상은 기존 브랜드를 바탕으로 검토한다. 핵심 변경은 정보의 순서와 밀도이며, 새 색상·그래픽·픽셀 배치는 실제 시안 단계에서 정한다.

### 3.2 상단 핵심 문구·SEO 표현과 등록 진입

- 상단은 서비스의 제공 내용을 명확히 설명한다. 주제는 **신규 버튜버·데뷔 일정·캘린더**로 맞추고, 슬로건은 핵심 제목을 대체하지 않는다.
- 아래 문구를 화면과 검색 메타 정보의 정의안으로 사용한다. 실제 구현 시 제공 기능과 일치하는지 확인한다.

| 용도 | 문구 정의 |
| --- | --- |
| 화면 핵심 제목(H1) | **신규 버튜버 데뷔 캘린더** |
| 제목 아래 설명 | 신규 버튜버의 데뷔 날짜·시간·방송 플랫폼을 확인하고, 관심 있는 버튜버의 소개를 만나보세요. |
| 페이지 제목(title) | 신규 버튜버 데뷔 캘린더 · 데뷔 일정과 소개 \| VDébut |
| 검색 설명(meta description) | 신규 버튜버의 데뷔 날짜·시간·방송 플랫폼을 캘린더에서 확인하세요. 관심 있는 버튜버의 소개를 살펴보고, 나의 데뷔 소식도 직접 등록할 수 있습니다. |
| 브랜드 보조 문구 | 버튜버와 팬의 소개팅 |

- 제목·설명은 실제 페이지 텍스트로 제공하는 요구로 정의한다. 슬로건을 더 크게 강조하거나 장식 이미지 안에만 핵심 제목을 넣지 않는다.
- 슬로건을 표시한다면 핵심 제목·설명 다음의 보조 위치에 둔다. 키워드를 반복하기 위해 상단 설명을 길게 늘리지 않는다.
- 헤더와 하단 등록 안내의 버튼 명칭은 **“데뷔 등록하기”**로 맞춘다. 일정을 모르는 사람도 신청할 수 있다는 안내는 등록 진입 가까이에 제공한다.
- 하단 안내 문구안: **“데뷔 소식과 나의 소개를 등록해 보세요.”**
- 홍보 효과·팬 증가·처리 속도를 보장하지 않는다. 실제 측정하지 않은 ‘10초 등록’ 표현은 사용하지 않는다.

### 3.3 달력과 탐색 조건

- 기본 조건은 **전체 플랫폼·전체 국가·현재 월**로 한다. 현재 월·오늘의 기준은 사용자가 선택한 시간대를 따른다.
- PC는 월간을 기본으로 하고 기존 주간 전환을 유지한다.
- 플랫폼 조건은 달력·예정자 소개·미정 목록에 함께 적용한다. 쇼케이스만 별도 플랫폼을 선택하는 중복 조작은 통합한다.
- 국가 조건에는 확인된 국가만 사용한다. 기존 EN 분류를 특정 국가로 임의 변환하지 않고 기존 자료의 국가·언어 의미를 먼저 확인한다.
- 방송 언어가 별도 확보되기 전에는 국가를 언어 필터처럼 안내하지 않는다. 정식 방송 언어 필터는 후속 데이터 설계와 함께 추가한다.
- 이름 검색은 선택 월·조건 안의 데뷔자를 찾는 기능이다. 사이트의 전체 버튜버 검색으로 표현하지 않는다.
- 현재 시간대를 표시하고 변경 진입을 제공한다. 날짜·시각·오늘·월/주 경계·집계에 같은 시간대를 적용한다.
- 월 이동·필터 변경·상세 확인 후 복귀 시 탐색 조건을 유지한다. 사용자가 고른 조건을 빈 결과라는 이유로 자동 변경하지 않는다.

### 3.4 달력 항목과 소개 연결

- 날짜 셀에는 **시각·플랫폼·활동명**을 우선 표시한다. 작은 셀에 긴 소개와 여러 특징 태그를 모두 넣지 않는다.
- 오늘과 선택 날짜를 구분하고 색상 외에도 표시를 제공한다.
- 항목이 많은 날짜에는 숨겨진 일정이 있다는 표시와 전체 목록 진입을 제공한다. 일부만 표시하면서 전체처럼 보이지 않게 한다.
- 날짜 선택은 기존 날짜별 목록·상세 패널로 이어진다. 목록에서 선택한 버튜버의 개인 소개와 공식 방송으로 이동할 수 있어야 한다.
- 날짜 상세 패널의 내부 배치와 카드 디자인은 **다음 화면 개선 과제**에서 별도로 정의한다. 이번에는 진입·복귀·표시 정보의 계약만 정한다.

### 3.5 예정자 소개 영역

| 정보 | 표시 기준 |
| --- | --- |
| 이미지·활동명 | 공개된 실제 프로필 사용. 이름 선택으로 개인 소개 이동 |
| 데뷔 일시 | 선택 시간대로 변환. 날짜·시간 미정은 확정값으로 표시하지 않음 |
| 방송 플랫폼 | 공식 로고·이름을 사용하며 임의 가공하지 않음 |
| 한 줄 소개 | 본인 작성 또는 출처가 확인된 소개가 있을 때 표시. 내용이 없으면 생략 |
| 주요 콘텐츠·방송 언어 | 확인된 정보만 선택 표시. 국가·이름·이미지로 특징을 추정하지 않음 |
| 행동 | ‘소개 보기’를 기본으로 하고 유효한 ‘방송 채널’·‘일정 저장’ 연결 제공 |

- 단순히 ‘공식 데뷔 방송입니다’라고 생성된 안내를 방송 특징처럼 강조하지 않는다.
- **현재·미래 월**에서는 선택 월 안의 오늘 이후 확정 일정을 가까운 순서로 소개한다. 영역 제목은 ‘다가오는 데뷔’로 한다.
- **과거 월**에서는 ‘이달 데뷔자’ 등 선택 월의 기록임을 알리는 제목과 시간순 목록을 사용한다. 종료된 일정을 다가오는 데뷔로 부르지 않는다.
- 같은 시각의 대상은 안정적인 기준으로 정렬한다. 인기도나 임의 점수를 노출 우선순위로 사용하지 않는다.
- 후보가 일부만 보이면 전체 후보를 찾아볼 경로를 제공한다. 대형 입체 카드나 필수 자동 회전으로 내용을 숨기지 않는다.
- 실제 방송 상태를 확인할 수 있을 때만 LIVE를 표시한다. 일정 시간이 지났다는 사실만 확인되면 ‘예정 시각 지남’ 등 일정 상태로 구분한다.
- 미래 확정 일정이 없으면 간결한 안내와 월 이동·필터 초기화·등록 경로를 제공한다. 명시적으로 선택한 플랫폼을 몰래 바꾸지 않는다.

### 3.6 일정 미정과 데이터 상태

- 날짜 확정·시간 미정과 날짜 자체 미정을 구분한다. 날짜를 아는 대상까지 ‘날짜 미정’으로 묶지 않는다.
- 확정 날짜가 있는 시간 미정 대상은 해당 날짜에 ‘시간 미정’으로 식별할 수 있어야 한다. 별도 목록과 함께 보여도 집계에서 중복 계산하지 않는다.
- 예정 월만 있는 대상은 별도 미정 영역에서 보여주고 가짜 날짜에 배치하지 않는다.
- 월·플랫폼별 숫자를 유지한다면 ‘선택한 조건의 일정 수’ 또는 ‘고유 데뷔자 수’ 중 실제 의미와 일치하는 명칭을 사용한다. 서로 다른 집계는 구분한다.
- 전체 등록 수치를 보여주려면 전체 대상의 실제 고유 집계를 확보한다. 필터된 결과를 전체로 표시하거나 데이터가 없을 때 123 같은 대체값을 사용하지 않는다.
- 로딩 중에는 자리표시자·불러오는 상태를 제공한다. 오류에는 재시도, 실제 빈 결과에는 조건 초기화·인접 기간 탐색을 제공한다.
- 데이터가 적어도 큰 빈 카드와 과도한 여백이 달력을 밀어내지 않게 한다.

## 4. PC·모바일 기준

| 구분 | 정의 |
| --- | --- |
| PC | 월간 달력을 기본으로 한다. 첫 화면에서 선택 월·요일·날짜 격자의 시작을 확인하고 바로 날짜 탐색을 시작할 수 있게 배치한다. 예정자 카드는 달력 다음의 보조 탐색으로 둔다. |
| 모바일 | 기존 주간 날짜 스트립+선택일 목록을 읽기 쉬운 기본안으로 유지한다. 월 선택·월간 보기 접근은 별도로 제공하는 방향으로 시안을 검토한다. PC 월간 격자를 단순 축소하지 않는다. |
| 공통 | 상단 소개가 일정 탐색을 밀어내지 않게 하고, 헤더·달력 조작·등록 진입이 중복 고정돼 내용을 가리지 않게 한다. |

모바일 현재 동작의 전체 검증은 아직 하지 않았다. 위 내용은 모바일 코드 기반의 시안 요구다. PC 1280×800, 모바일 390×844와 좁은 320px 폭을 검토 기준으로 사용한다. 이 크기는 시안 검토 환경이며 실사용 성능을 측정한 수치가 아니다.

## 5. 범위와 개선 순서

| 순서 | 작업 묶음 | 이번에 정의한 범위 |
| --- | --- | --- |
| 1 | 정보 우선순위 | 간결한 소개, 달력 상단 배치, 예정자 쇼케이스 재구성 |
| 2 | 탐색 일관성 | 플랫폼 조건 통합, 이름 검색, 국가/언어 구분, 시간대 표시 |
| 3 | 만남과 등록 | 예정자 한 줄 소개, 개인 소개 연결, 등록 가치·버튼 정리 |
| 4 | 상태·정확성 | 로딩/실패/0, 미정 분류, 인원 집계, LIVE 확인 기준 |
| 5 | 반응형·복귀 | PC·모바일 시안, 키보드 조작, 상세 복귀 조건 유지 |

이번 문서는 메인 화면의 개선 정의다. 실제 코드 수정, 그래픽 시안 제작, 등록 폼·개인 소개·통계 화면의 세부 개편은 포함하지 않는다. 필요한 소개·언어·실시간 상태 자료가 없다면 빈 정보를 만들지 않고 해당 항목을 생략하거나 후속 작업으로 남긴다.

## 6. 수용 기준과 검증

| ID | 확인 항목 | 완료 판단 |
| --- | --- | --- |
| MAIN-01 | 상단 전달·달력 우선순위 | 핵심 제목이 ‘신규 버튜버 데뷔 캘린더’이며 제목·설명·검색 메타 정보가 페이지의 제공 내용을 일관되게 설명. PC 검토 크기의 첫 화면에서 선택 월·요일·날짜 격자의 시작이 보이고 등록 진입을 찾을 수 있음 |
| MAIN-02 | 플랫폼 기본값 | 전체를 기본으로 하며 다른 플랫폼에 일정이 있을 때 특정 기본 탭의 빈 화면으로 가리지 않음 |
| MAIN-03 | 조건 일치 | 월·플랫폼·국가·이름 검색의 적용 범위가 달력·예정자·미정 목록에서 일치 |
| MAIN-04 | 일정 이해 | 오늘·선택일·확정·시간 미정·날짜 미정을 구분하고 같은 시간대로 표시 |
| MAIN-05 | 소개 연결 | 예정자에게 확보된 소개가 보이고 개인 소개·공식 방송·일정 저장으로 이동 가능 |
| MAIN-06 | 수치·상태 | 임의 인원·초기 가짜 0·일정 시각만으로 표시한 LIVE가 없고 실패와 빈 결과를 구분 |
| MAIN-07 | 등록 이해 | 신규 버튜버가 등록 진입을 찾고 어떤 정보가 소개되는지 이해. 미정 신청 가능 여부 확인 |
| MAIN-08 | 복귀·접근성 | 상세에서 조건을 유지해 돌아오며 키보드로 날짜·필터·주요 행동을 조작 가능 |
| MAIN-09 | 모바일 | 390px·320px 폭에서 주요 일정·행동이 가리지 않으며 대형 쇼케이스가 탐색을 밀어내지 않음 |

사용자 확인 과제는 ‘이번 주 데뷔자 찾기’, ‘플랫폼을 골라 특정 날짜의 소개 열기’, ‘시간 미정 대상 찾기’, ‘나의 데뷔 등록 시작하기’로 한다. 과제 성공과 막힌 지점을 확인하고, 출시 후에는 PRD의 소개 도달·방송 링크 이동·등록 시작/접수 지표를 같은 정의로 비교한다. 아직 측정되지 않은 전환 상승률은 목표 숫자로 단정하지 않는다.

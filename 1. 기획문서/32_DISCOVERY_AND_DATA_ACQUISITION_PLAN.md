## 1 결론과 초기 사업 범위

**사용자가 적은 초기에는 VDébut가 먼저 신인을 발굴하고 소개를 채운다. 이후 본인 등록과 팬 제보도 같은 인물·근거·갱신 구조로 받는다.** 자발적 등록을 기다리거나 인물마다 별도의 수작업 소개를 제작하는 방식을 성장 전제로 삼지 않는다.

첫 집중 대상은 한국 치지직·SOOP의 데뷔 준비·최근 활동 시작 버튜버다. YouTube·공식 X·소속사 사이트는 인물과 작품을 확인하는 보조 출처로 연결한다. 다른 국가·플랫폼의 기존 정보는 보존하되 신규 전수 발굴을 동시에 약속하지 않는다. '최근'은 최초 방송을 입증한 인물에만 일률 적용하지 않고 공지된 데뷔·첫 발견·기존 활동 여부를 따로 기록한다.

우선 개발할 결과는 **후보를 찾아 기본 정보를 자동 확보하고, 공개 가능한 정보와 보완할 정보를 나누며, 이후 바뀐 정보만 갱신하는 체계**다. 추천·게임·채팅 분석은 이 체계의 선행 조건이 아니다.

| 경로·우선순위 | 확보할 내용 | 자동화할 부분 | 직접 다룰 부분·실패 시 대안 |

치지직의 전체 신규 버튜버를 열거하는 API가 확보됐다고 가정하지 않는다. SOOP 일정도 해당 일정에 실린 사람만 포착한다. 따라서 어떤 경로도 전수 발굴망이 아니며, 소스별 마지막 성공·대상 기간·누락 가능성·신규 발견 성과를 관리한다. 기존 인물의 팔로워·영상 갱신만 성공한 것을 신규 발굴 성과로 세지 않는다.

### 3.1 공식 일정·공개 시트 밖의 치지직 신인 발굴

**이미 아는 채널의 보강과 모르는 채널 ID의 첫 발견을 분리한다.** 활동 중인 미등록 인물은 치지직 방송 목록·채널 키워드 검색에서 찾고, 아직 방송하지 않은 준비생은 접근 가능한 외부 공개 홍보·지정 공식 공지에서 채널 주소를 찾는다.

현재 로컬 `broadcastStatisticsSources.ts`는 인기순 최대 2페이지×50개, `externalPlatformSearchService.ts`의 채널 검색은 offset=0 첫 페이지를 읽는다. 수집/검색 기반은 있으나 장기적인 신규 발굴 처리 체계나 전체 신인 목록이 아니다. 웹 서비스가 쓰는 공개 응답과 공식 개발자 API 계약을 구분하며, 현재 응답·검색 범위·페이지 지원·권한/할당량은 새로 확인하지 않았다.

| 경로 | 처음 얻는 단서 | 자동 처리 가능한 범위 | 직접 할 일·놓치는 범위 |
| --- | --- | --- | --- |
| P0 치지직 방송 목록 | 미등록 채널 ID·주소, 방송 ID·제목·제공 태그·분류·관측 시각 | 허용된 페이지/커서를 따라 조회, 기존 등록·대기·차단 대조, 명시적인 버튜버 표현을 후보 단서로 추출 | 인기 상위만 보면 소규모 채널이 누락됨. 방송하지 않는 인물·조회 상한 밖·짧은 방송은 놓칠 수 있음 |
| P0 채널 키워드 검색 | 검색 결과의 채널 ID·주소·이름·이미지 참조·제공 상태 | 이름 대신 버튜버/버추얼/버츄얼/VTuber/신입/신인/데뷔/첫방송 등 검색어 묶음을 정기 실행, 지원 범위 내 페이지 조회·중복 제거 | 검색 대상 필드·복합어 처리·페이지 지원 확인. 채널 소개/방송 제목 전체가 검색된다고 가정하지 않음 |
| P1 외부 공개 홍보 검색 | 치지직 주소가 포함된 방송 준비·데뷔 공지, 게시물·작성자·발행일 | 접근 가능한 검색 API 연결 시 결과의 명시적 채널 주소 추출·후보 생성 | 유료 검색은 첫 출시 필수 제외. 연결이 없으면 직접 발견한 공식 링크 입력. 게시물 작성자와 채널 동일성 확인 필요 |
| P1 지정 공식 공지 | 소속사/팀 신규 멤버·공식 프로필에 실린 새 채널 | 허용된 피드·구조화 자료의 링크 변경 탐지 | 출처 등록·구조 변경 대응. 지정 출처 밖의 개인세를 전부 포착하지 못함 |
| 보완 공식 자료의 외부 연결 | 확인된 합방·팀 소개에서 연결한 다른 채널 | 명시된 새 채널 주소를 후보로 추가 | 출연/연결 사실이 버튜버·신인임을 입증하지 않음. 별도 채널 근거 필요 |

방송 목록의 단순 인기순 탐색 확대만으로 최하위 시청자 구간까지 닿는다고 보장하지 않는다. 버튜버 관련 필터·정렬은 실제 지원·접근 범위가 확인된 경우에만 적용한다. 최신순·시청자 적은 순이 있다고 가정해 설계하지 않는다. 회차마다 새 커서로 시작하고 조회 상한·중복·잘림·관측 시간대를 기록한다. 일부 페이지만 읽은 결과를 플랫폼 전체 조사 완료로 표시하지 않는다.

### 3.2 첫 발견부터 사람 판단까지의 처리

예시: 방송 목록에서 `[신입 버튜버] 오늘 처음 켰어요`라는 제목과 VTuber 태그를 가진 미등록 채널을 발견했다면, 채널 ID·원문 방송·제목/태그·발견 경로·확인 시각을 보관한다. 정규 채널 키로 중복 대조 후 기존 채널 조회로 공식 소개·연결을 보강한다. 제목의 단어와 태그는 후보 단서이며 신규 인물/최초 데뷔의 확정 근거가 아니다.

- **자동:** 소스 실행·커서·부분 수집 상태, 채널 ID 추출/중복 대조, 근거와 관측 시각 저장, 제공 프로필·자료 보강, 조건 충족 공개, 이후 변경 감지.
- **직접:** 첫 소스·허용 항목·검색 규칙 선정, 일반 방송의 단순 키워드 언급인지 모호한 사례, 재데뷔/부계정/이적·동일 인물 판단, 공식 작성자-채널 연결·주요 사실 충돌, 표본·삭제/권리 요청·장애 대응.
- **미확인 유지:** 우리 사이트가 처음 본 날과 첫 방송일을 분리한다. 팔로워/시청자가 적거나 `신입` 표현이 있다는 이유로 데뷔일·신인 상태를 확정하지 않는다.

내부 분류는 `새로 발견한 미등록 채널 / 버튜버 근거 확보 / 신인 주장·확인 대기 / 데뷔 근거 확인`을 각각 관리한다. 기존 통계 코드의 키워드 신인 판정 결과를 그대로 도감의 사실 항목에 복사하지 않는다.

### 3.3 초기 탐색 상한과 중복 저장 방지

| 작업 | 초기 가정 | 월 외부 요청 상한(재시도 전) |
| --- | --- | --- |
| 방송 목록 탐색 | 하루 6회×최대 20페이지, 페이지당 최대 50항목 가정 | 3,600회 |
| 채널 키워드 검색 | 8개 검색어×최대 2페이지×하루 3회, 페이지당 최대 20항목 가정 | 1,440회 |
| 합계 | 실제 지원/쿼터 범위에서만 실행, 끝 페이지면 조기 종료 | 5,040회 |

이는 현재 지원 보장이나 전수 탐색 범위가 아닌 계획 상한이다. 응답 슬롯은 최대 208,800개/월(방송 180,000+검색 28,800) 가정이지만 같은 채널이 반복 포함된다. 이를 후보 208,800명이나 동일한 DB 저장 행으로 계산하지 않는다. 제목·태그의 정형 단서와 회차 내 ID 중복 제거·짧은 재확인 캐시 후 제한된 묶음으로 DB 대조한다.

비용 시나리오는 DB 대조/관측 처리 K=월 6,000회(초기)·12,000회(확장), 발견 후보 I=600/2,400건·최초 보강 C=90/450건을 별도 가정한다. K는 월 유일 인물 수가 아니며 같은 채널의 다른 회차 재대조도 포함한다. 이 값은 실제 적중률이 아니고 한도 초과 시 후속 큐·다음 실행 이월 및 지연/누락 범위를 기록한다. 원시 응답 전체·반복 썸네일을 저장하지 않는다.

추가 논리 실행 H=월 900건(방송 180회+검색어별 720회)을 상태 기록 단위로 잡는다. 여러 검색어를 한 예약 실행에 묶을 수 있으므로 H나 외부 HTTP 요청 수를 Worker 유료 호출 수와 동일시하지 않는다. 기존 통계와 공유 가능한 응답은 재사용하되 아직 공유가 검증되지 않아 예산 계산에서는 차감 0으로 둔다.

기존 목록 F의 10/30개 소스에는 위 치지직 방송/검색을 포함하지 않는다. 새 D=5,040회는 별도 추가다. 보강 증가·재시도까지 포함한 새 총량과 DB/저장 비용은 [24번](./24_ADVANCEMENT_BACKLOG_AND_COST.md)으로 통일한다. 준비생을 찾는 유료 외부 검색·추가 본문 페이지 수집은 이 상한에 포함하지 않는다.

## 4 자동화의 끝과 사람이 판단할 경계

기존 '보고 전용' 코드를 몰래 자동 쓰기로 바꾸는 계획이 아니다. 향후 개발에서 반영기를 별도 모드로 만들고, 기본 보고 전용을 유지한 채 허용된 출처·항목만 명시적으로 실행 모드에 연결한다. 이번 작업에서 그 설정이나 실행은 하지 않는다.

| 처리 | 자동화 범위 | 예외 처리 |
| --- | --- | --- |
| 후보 발견·수집 | 허용 출처를 정기 확인해 발견 기록·근거 참조 저장 | 검색 미연결·한도·페이지 잘림을 소스 상태로 기록. 발견 0명과 실패를 구분 |
| 동일 채널 대조 | 플랫폼+정규 채널 ID를 등록·대기·보류·중복 별칭 전체에 대조 | 이름 유사성으로 병합 금지. 복수 채널·재데뷔·이적은 동일 인물 근거가 있어야 연결 |
| 기본 보강 | 공식 채널의 제공 필드, 명확한 날짜·영상 메타데이터, 근거 있는 특징 후보 추출 | 모르는 소속·국가·시간은 unknown. 이미지/닉네임만 보고 버튜버·언어·성향을 확정하지 않음 |
| 기본 소개 작성 | 확인된 정형 항목으로 공통 템플릿 조합 | 빈 내용을 AI로 창작하지 않음. 외부 AI·OCR을 필수로 두지 않음 |
| 새 인물 자동 공개 | 아래 조건 전부 충족한 허용 출처만 최소 소개 자동 공개 | 불명확·충돌·민감한 내용은 공개 보류. 모든 후보를 무조건 수동 결재하는 구조로 고정하지 않음 |
| 기존 값 갱신 | 같은 공식 채널의 허용된 낮은 위험 항목, 명시적 최신성·우선순위가 있는 값 | 사람이 확정·잠금한 값은 제안만 생성. 공식 채널·소속·데뷔일·동일 인물 병합 등 주요 변경은 직접 검토 |
| 활동 축적 | 허용된 원문의 키로 중복 제거, 공개일·확인일 구분 | 과거 첫 수집은 NEW 제외. 만료·철회·실패와 실제 활동 종료를 구분 |
| 이후 참여 | 등록·제보도 동일 항목별 근거 및 변경 제안 처리 | 본인 입력이라고 무조건 인증·우선 덮어쓰기하지 않음 |

### 4.1 최소 소개 자동 공개 조건

1. 해당 출처와 항목에 대해 수집·저장·공개 범위 및 갱신·삭제 정책이 설정돼 있다. 미확인 출처는 후보 확보까지만 한다.
2. 공식성이 확인된 발신자가 버튜버임을 명시하고, 공개하려는 채널을 연결한다. 프로필 사진과 검색어 적중만으로 통과하지 않는다.
3. 채널이 존재하고 고유 ID가 일치하며, 기존 공개·대기·보류·삭제/재수집 차단 기록과 충돌하지 않는다.
4. 활동명·공식 채널·짧은 확인된 소개·근거가 있고, 허용된 이미지가 없으면 공통 기본 이미지로 대체한다. 작품·소속·데뷔일 미확인 자체로 인물 후보를 버리지 않는다.
5. 공개 검토·악성 링크·성인/부적절 콘텐츠 차단 등 기존 운영 기준을 통과한다. 기존 보호 정책을 자동 승인으로 우회하지 않는다.
6. 후보 버전·근거 지문·변경 전후가 고정된 반영 계획으로 저장되고, 직전 상태 재확인·중복 제약·재실행 안전성·복구 기록이 적용된다.

새 출처는 예를 들어 **첫 20건을 병행 검토**한 뒤 해당 출처의 정형 항목부터 자동 공개 모드로 전환한다. 20건은 운영 초기안이며 통계적 정확성 보증이 아니다. 동일 인물 충돌·공식 채널 오연결·허위 일정이 한 건이라도 발생하면 해당 규칙의 자동 반영을 중지하고 원인을 수정한다. 통과 이후에도 일일 반영 상한·표본 확인·즉시 중지 기능을 둔다.

### 4.2 인물 공개와 캘린더 등록의 분리

인물 소개 공개는 일정 확정을 요구하지 않는다. 일정은 별도 행사로 보관하며 FIRST_DEBUT / PLATFORM_DEBUT / REDEBUT / MODEL_REVEAL / RETURN / UNKNOWN 등을 구분한다. 공지가 말하는 종류 이상으로 최초 활동을 추론하지 않는다.

기존 캘린더에는 검증된 날짜·시간대·시각을 가진 지원 일정만 연결한다. 시간 미정은 인물 소개에서 미정으로 유지하며 19:00으로 만들어 넣지 않는다. 조사 README에 기록된 기존 업로더의 시간·소속·국가 기본값 문제를 새 반영 경로에서 방지한다. 기존 메인 화면과 캘린더 디자인·동작은 변경하지 않는다.

### 5.1 등록 수와 정보 품질을 분리

기본 소개 공개는 정보 확보의 시작이다. 활동명·채널·짧은 사실만 채운 인물을 '입문 정보가 충분한 인물'로 집계하지 않는다. 내부적으로 다음 수준을 구분하되 이용자에게 임의 점수나 운영 상태 코드를 노출하지 않는다.

| 내부 정보 수준 | 갖춘 내용 | 활용 |
| --- | --- | --- |
| 실체 확인 | 공식 인물/채널 연결·활동명·기본 소개·근거 | 이름/채널 검색과 기존 소개 주소 제공. 충실한 추천 후보라고 취급하지 않음 |
| 입문 가능 | 어떤 콘텐츠/콘셉트인지 확인되고, 소개/작품 또는 공식적으로 안내된 준비 활동을 볼 수 있음 | 입문 자료 보유율에 포함. 근거에 맞는 목록·탐색·검색 미리보기 활용 |
| 지속 확인 | 입문 정보에 더해 허용된 경로로 활동/일정/변경을 갱신 | 이후 관심 변화·활동 탐색의 기반 |

내용이 거의 같은 최소 페이지를 대량 생성해 검색 노출·광고 승인 성과로 삼지 않는다. 검색 색인 확대는 독립적인 입문 정보가 있는지 기준을 정해 적용한다. 출처는 많이 발견하지만 입문 가능 인물이 늘지 않는다면 데이터 보강 경로를 우선 개선한다.

## 6 운영 주기·장애·검토량

초기 제안: 발굴 목록 하루 2회, 데뷔 전후/최근 변경 채널 하루 2회, 장기간 변화 없는 채널 주 1회. LIVE 상태·기존 방송 통계 수집 주기를 이 제안으로 변경하지 않는다. 무변화 채널은 점진적으로 간격을 늘리고 일정 임박·사용자 수정은 우선 처리한다.

동시 실행 잠금, 실행 ID, 소스별 커서·최종 성공, 페이지/호출 상한, 지수 재시도와 상한, 실패 격리를 둔다. 401/403·권한 철회·계약 한도는 자동 우회하지 않으며 해당 소스만 중지한다. 방문자가 상세를 열 때 전체 수집을 실행하지 않는다. 실행기 후보는 기존 Worker 예약 작업이며 기존 보고 작업과 수집을 이중 실행하지 않도록 단일 실행 소유자를 정한다.

| 직접 할 일 | 빈도 초기안 | 자동화로 줄일 반복 작업 |
| --- | --- | --- |
| 출처 선정·공식성/허용 항목·대표작 정책 | 최초와 출처 변경 때 | 출처 설정·규칙·예시 재사용 |
| 동일 인물 충돌·출처 상충·주요 변경 판단 | 예외 발생 때 | 차이·근거·기존 값·제안 값만 묶어 제시 |
| 자동 공개 표본·소스 실패 확인 | 초기 주간 점검, 문제 출처는 중지 후 확인 | 정상 무변화 건을 검토 목록에서 제외 |
| 파서 구조 변경·할당량·비용 대응 | 장애/한도 발생 때 | 상태·원인·영향 범위만 요약. 사이트별 무제한 파서 유지 금지 |
| 정정·삭제·재등록 차단 요청 | 접수 때 | 기존 정정·역사·차단 이력 재사용 |

처리량 예시: 신규 후보 100건/주 중 80건이 정형 처리되고 20건이 예외라고 가정하면 20건×3분+표본/소스 확인 30분=주 90분이다. **자동화율·소요시간은 실측이 아닌 작업량 예시**다. 같은 후보량에서 예외가 50건이면 180분이므로, 출처 확대보다 실패 규칙·중복·정보 추출을 먼저 고친다. 정상 정형 건도 매번 3분씩 사람에게 요구하는 설계는 피한다.

| 순서 | 개발 묶음 | 산출물·완료 기준 |
| --- | --- | --- |
| D0 | 기존 후보·현재 필드·출처 정책 정리 | 정본/기존 DB/보고 구조 매핑, 최소 공개 기준, 모르는 값·잠금 항목·반영 권한 정의 |
| D1 | 인물·채널 식별 및 근거/후보 저장 | 기존 slug 보존, 채널 유일성·대기 포함 중복 방지·항목별 근거·후보 버전 관리 |
| D2 | 첫 수집 연결 | 기존 CSV/보고 읽기, 허용된 공식 일정·공개 시트와 치지직 방송/채널 검색 탐색 연결. 쿼리·커서·신규 채널·변경/실패/잘림 기록. 외부 원문 테스트는 실행 허용 단계에서만 수행 |
| D3 | 채널 보강·입문 자료 연결 | 기존 플랫폼 조회·미디어 재사용, unknown 유지, 공식 링크·최근/대표 자료 구분 |
| D4 | 후보 공개 판정·반영·복구 | 보고/초안/자동 반영 모드 분리, 규칙별 허용, 직전 값 비교, 중복·재실행·부분 실패·보호값·차단 검증 |
| D5 | 지속 갱신·운영 요약 | 변경분만 저장, 잠금·상한·커서·백오프·예외 큐·표본 확인·삭제/철회 반영 |
| D6 | 기존 도감·상세 노출 | 확인된 정보·작품·원문 제공. 빈 데이터/조회 실패 구분. 기존 메인·공통 구성 보존 |
| 다음 | 추가 공식 소스·본인/팬 참여·관심 변화 | 같은 처리 체계에 연결. 오늘의 발견은 정보량·특징 근거가 충분할 때 개발 |

D0~D6가 첫 출시 범위다. D6의 데이터 계약은 D1 이후 설계할 수 있지만 실제 자동 공개는 D4~D5 보호 장치와 함께 켠다. 기존 코드가 보고 전용이라는 사실을 완료 기능으로 바꿔 적지 않는다. 인건비를 제외해도 개발·운영 판단 시간이 필요하며 날짜 납기는 이번에 확정하지 않는다.

## 8 비용·DB·사이트 성능

금액과 계산 상세는 [24 비용 계획](./24_ADVANCEMENT_BACKLOG_AND_COST.md)을 정본으로 한다. 초기 100개 관리 인물 시나리오에서 수집 약 14,800회/월, DB 읽기 112,512행/월·쓰기 35,384행/월, 신규 저장 예산 0.05~0.15GB를 잡는다. **기존 서비스 사용량에 더할 설계 가정**이며 실제 측정·청구 수치가 아니다. 1,000개 확장 시나리오와 재시도·인덱스·조회 가정은 같은 문서에 명시한다.

기존 플랜 잔여량으로 수용하면 추가 정액 계약 없이 시작한다. 기존 내부 초기 순증 월 1만원·확장 월 3만원은 검토 기준선으로 남기되, 추가 탐색 반영 후 수용 여부가 미확인임을 표시한다. 요금표 기반 견적·청구 상한·실제 청구액으로 표현하지 않는다. 기존 기본료·사용량·과금 단가를 확인할 수 없는 현재에는 정확한 월 실비를 확정하지 않는다. 인건비·외주 아트·외부 AI·X 유료 검색·SSAPI·전용 상시 서버는 필수 비용에 넣지 않는다.

공통 템플릿·허용된 이미지 참조·원문 링크로 소개를 구성한다. 이미지/영상 원본 대량 복제·AI 그림 제작·방문별 LLM 호출·채팅 저장은 하지 않는 설계다. 수집·보강은 화면 밖에서 실행하고 화면은 마지막 정상 공개 데이터를 읽는다. 전체 인물의 미디어를 첫 화면에 내려받거나 사용자별 외부 API 반복 호출을 하지 않는다.

## 9 이후 자발 등록으로 전환되는 모습

초기에는 우리가 먼저 만든 소개가 검색·공유·공식 활동 이동의 입구가 된다. 본인은 기존 등록/정정 경로로 빠진 소개와 작품을 보완하고, 팬은 출처 있는 기록을 보탠다. 제출된 정보는 새 인물을 중복 생성하지 않고 같은 인물·항목·근거에 연결한다.

자발 등록이 늘어도 수집을 폐기하지 않는다. 자동 수집은 누락 발견·최근 자료 갱신을 맡고, 본인·팬은 소개의 깊이·대표작·정정을 보완한다. 본인이 확정한 값을 이후 수집이 덮어쓰지 않게 보호하며 새 소유권 관리 화면·회원 체계는 별도 결정 전까지 신설하지 않는다. 방문자가 늘면 자발 등록이 반드시 발생한다고 예측하지 않고 제출·반영 실적을 확인한다.

## 10 앞으로의 숙제와 성공 판단

| 숙제 | 담당 제안 | 결과물·판단 기준 |
| --- | --- | --- |
| 기존 후보·필드 매핑 | 사용자 + Codex | 어떤 데이터가 있고 무엇이 부족한지, 오래된 행과 미반영 제안을 구분한 대응표 |
| 첫 출처 묶음과 자동 공개 규칙 | 사용자(서비스 기준) + Codex(설계) | 허용 출처·항목·모드·예외·중지 조건의 설정안 |
| 실행 단계의 접근 범위·단가 확인 | 개발 착수 이후 사용자 + Codex | 이용 가능 수집 방식·쿼터·실제 기존 청구/잔여량. 현재는 미실행 |
| 개발 D1~D6 | 사용자 + Codex | 재실행·중복·상충·삭제·실패·복구 및 기존 화면 보존 확인표 |
| 운영 결과 확인 | 운영 시작 이후 사용자 + Codex | 유효 새 인물/주, 출처별 발견 기여·중복률, 입문 자료 보유율, 발견→공개 시간, 오래된 정보율, 예외 처리 시간, 실제 호출/DB/청구 |

첫 목표는 임의의 등록 인원 달성이 아니라, **새 후보가 들어오고 확인된 정보가 공개되며 변경이 따라오는 과정이 반복되는 것**이다. 30명 정도의 제한된 묶음으로 전체 과정을 점검할 수 있으나 신규 30명 확보를 보장하거나 전수 포착률·자동화율을 성과처럼 발표하지 않는다. '대표 자료 보유'는 대표 지정 근거가 있는 소개/작품 기준으로 측정하고 최근 영상 보유율과 분리한다.

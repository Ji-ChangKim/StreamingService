# VDébut PRD 잔여 항목 점검

- **문서명**: PRD 대비 구현 현황과 잔여 과제
- **버전**: v1.1
- **최종 수정일**: 2026-10-11
- **작성자/담당**: Codex 작성 · 프로젝트 담당자 검토
- **상태**: 코드·배포 기록·LIVE 공개 데이터 대조 완료. 아래 후속 기능은 미구현 또는 부분 구현이며 이번 점검에서 서비스 변경·배포는 하지 않음.

> **후속 구현 현황:** 사용자 진행 요청에 따라 우선순위 **1~3번을 개발 사이트에 구현·배포했다**. [등록·중복 방지·관리자 정정 구현 결과](./18_REGISTRATION_AND_ADMIN_IMPROVEMENTS.md) 참조. 아래 LIVE 기준 감사 결과는 최초 점검 기록이며, 해당 세 과제를 개발 미구현으로 해석하지 않는다. LIVE 반영은 아직이다.

## 1. 판단 기준

[PRD v3.0](./01_PROJECT_PRD_MVP.md)의 요구사항을 현재 포털 코드, [구현 기록](./13_DEV_PLATFORM_IMPLEMENTATION.md), [LIVE 배포 결과 v1.7](./16_LIVE_RELEASE_READINESS.md)와 대조했다. 최신 LIVE 배포 기록은 `560522d1-f044-4e3b-9965-38497319f7a7`이다.

‘기반 완료’는 명시한 지원 범위에서 주요 기능이 구현됐다는 뜻이다. 전체 버튜버 수집이나 모든 브라우저의 종합 검증 완료를 뜻하지 않는다. ‘부분’은 화면이 있어도 PRD의 수용 기준 또는 실데이터가 부족한 경우다. 부분 구현을 임의의 완료율로 환산하지 않는다.

사용자 확정 사항이 이전 PRD 본문보다 우선한다.

- 내 등록 관리·소유권 신청·본인 소개 수정·데뷔 신청 상태 조회 화면은 **현재 범위 제외**다. 미완료 과제로 되살리지 않는다.
- 등록은 관리자 접수·검토 후 공개한다. 정보 정정은 문의로 접수하며 문의 답변 조회는 유지한다.
- 기존 VDébut 브랜드와 CHZZK·SOOP·YouTube·Twitch 공식 아이콘을 유지한다.
- 국가·시간은 한·일·미 범위, UI 언어는 한국어·일본어·영어를 유지한다.
- 등록 화면의 URL → 프로필 → 일정이라는 세 구역 구조를 유지한다.
- 새 기능은 기능·동작·결과를 보고한 뒤 진행한다. 이 문서는 후속 구현 전 검토 자료다.

## 2. 이미 갖춰진 기반

- 메인 월·주 캘린더, 플랫폼·국가·시간대 선택, 데뷔 카드와 하이라이트, 일정 저장.
- URL로 방송국 정보 조회, 실패 시 수동 입력, 데뷔·소개 등록 접수, 관리자 검토 후 공개.
- 버튜버 목록·개별 소개·방송 채널 이동·주소 복사·브라우저 관심 저장.
- SOOP 실제 배너·소개 조회와 기존 VDébut 배경 대체 표시.
- CHZZK·SOOP 방송 활동 통계, 기간·카테고리·시간대 탐색, 개인 방송 기록.
- 소개·안내·문의·정책·관리자 화면, 3개 UI 언어, 공개 페이지 SEO 기본 정보.
- 초기 화면·캐시·통계 쿼리 최적화 및 관련 자동 검증. 실제 브라우저 성능 종합 측정은 별도 잔여 검증이다.

## 4. 먼저 처리할 잔여 항목

아래 순서는 다음 작업 제안이며 새 개발 일정의 확정이 아니다. 새 대형 화면보다 기존 등록·운영·발견 흐름을 완성하는 순서다.

| 순서 | 할 일 | 동작과 결과 | 완료 확인 |
| --- | --- | --- | --- |
| 1 | 등록 정보 보완 | 기존 세 구역 안에서 한·일·미 국가·시간대와 본인/대리/팬 제보 구분. 짧은 소개 확인 | 선택한 현지 시각이 UTC 저장·캘린더 표시까지 일치. 신청 역할을 본인 인증과 구분. 빈 소개 검증 |
| 2 | 접수·채널 중복 방지 | 같은 제출의 재시도는 기존 접수로 처리. URL 별칭이 달라도 플랫폼 채널 식별자로 대조 | 응답 유실 후 재시도·동시 승인·SOOP 주소 별칭에서 중복 접수/공개를 통제 |
| 3 | 관리자 정정 반영 | 문의 내용을 검토하고 기존 소개·일정을 편집. 변경 전후 이력과 복구 경로 확보 | 답변 완료 처리와 실제 공개 정보 갱신을 구분. 기존 공개 URL 유지 |
| 4 | 통계와 새 프로필 연결 | 기존 채널과 신규 포털 승인 채널을 같은 채널 식별자로 조회 | 새 등록자가 통계 → 본인 소개로도 이동하며 동명이인과 오연결되지 않음 |
| 5 | 특징·대표 콘텐츠 | 주요 콘텐츠·방송 언어·대표 영상/클립 원문 링크를 선택 입력하고 소개·탐색에 사용 | 실제 입력·확인된 정보만 표시. 빈 항목 임의 생성 금지. 대표 링크 열기 가능 |
| 6 | 변경·취소 표시 | 운영자가 일정 변경·취소를 기록하고 캘린더와 소개에 반영 | 취소가 확정 데뷔처럼 노출되지 않고 기존 일정/변경 이유 확인 가능 |
| 7 | 성장 흐름 계측 | 등록 시작 → 유효 접수 → 최초 공개 → 소개 조회 → 방송 이동, 공유 유입 기록 | 서버 확인 접수·공개, 고유 일정·신청 역할·출발 영역 연결. 중복/봇/운영 제외 기준 적용 |

7번은 PRD VDB-15의 크리에이터용 성과 화면 전체보다 먼저, PRD 8장의 서비스 성장 검증에 필요한 최소 계측부터 진행할 수 있다. 1번의 신청 역할 구분이 있어야 ‘본인 직접 등록 비율’을 구할 수 있다.

## 5. 구체적인 점검 근거

### 5.1 등록과 데이터

- 실제 등록은 `frontend/src/portal/PortalRegistrationForm.tsx`다. 기존 `ProfileForm.tsx`의 입력 필드가 남아 있어도 현재 등록 화면 지원으로 세지 않았다.
- 현재 등록 초기값은 `countryCode: ''`, `timezone: 'Asia/Seoul'`다. 등록 폼에는 국가·시간대 선택이 없고 KST 입력을 안내한다. **캘린더 시간대 선택 완료와 등록 시간대 입력 완료는 다르다.**
- 소개 입력은 가능하지만 현재 화면과 서버 모두 빈 소개를 필수 오류로 처리하지 않는다. 본인·대리·팬 역할 필드도 없다.
- 2026-10-11 점검 시점 [LIVE 공개 프로필 API](https://vdebut.live/api/v1/portal/profiles)의 공개 대상은 346개다. `tags`가 있는 대상 0개, `languages`가 있는 대상 0개였다. 전체 콘텐츠·언어 필터의 선택지를 실데이터로 제공하지 못한다. UI 언어 전환과 방송 언어 데이터는 별개다.
- 대표 콘텐츠 링크는 `shared/portal.ts`의 현 프로필 모델에 없다. 공지 링크와 대표 영상·클립 링크는 목적이 다르다.

### 5.2 운영과 연결

- `backend/src/services/portalService.ts`의 접수는 요청마다 새 UUID를 생성한다. 버튼의 전송 중 비활성화·요청 횟수 제한은 있지만 서버 제출 재시도 식별자는 없다.
- 승인 시 이미 공개된 채널의 중복은 URL 끝의 `/`만 제거해 비교한다. 동일 채널의 플랫폼 주소 별칭·다른 표현까지 식별자로 통합하지 않는다. 같은 신청의 중복 승인 방어는 별도로 존재한다.
- `PortalAdmin.tsx`는 승인·보완 사유·문의 답변을 처리한다. 기존 CMS는 삭제를 지원한다. 공개 프로필을 관리자 권한으로 편집하는 전용 처리 경로는 현재 확인되지 않았다. 문의 승인/답변만으로 프로필이 갱신되지는 않는다.
- `backend/src/services/broadcastActivityService.ts`의 소개 식별자 조회는 `streamerChannel` / `streamerChannel_info`를 사용하며 `portal_profiles`를 함께 조회하지 않는다. 신규 포털에만 등록된 대상의 통계 → 소개 연결은 미완성으로 판단한다.
- 새 포털 프로필의 일정 상태는 확정·시간 미정·날짜 미정·일정 없음이며 변경·취소 상태가 없다. 통합 일정 변환도 공개 상태로 생성한다.
- PRD 8장의 이벤트명과 일반적인 클라이언트 계측 호출을 소스에서 검색했으나 해당 성장 흐름 기록을 확인하지 못했다. 기존 방송 수집과 구분하여 미구현으로 분류한다.

## 6. 기능 구현과 별도로 남은 검증

- **운영 등록 전체 흐름:** 실제 사용자 등록 → 관리자 검토 → 공개 → 링크 공유 → 방송 이동까지 통제된 종합 검증. 기존 보고서의 접수·승인 데이터 보존 및 로컬 격리 검증을 운영 실접수 검증으로 대체하지 않는다. 이번 감사에서 시험 접수·승인·Discord 메시지를 생성하지 않았다.
- **플랫폼별 등록:** CHZZK·SOOP·YouTube·Twitch의 정상/잘못된 URL, 조회 실패, 수동 입력, 재시도 확인. SOOP 실제 배너·소개 검증과 네 플랫폼 등록 전체 검증은 별개다.
- **현지 시간:** 한·일·미 날짜 경계, 미국 서머타임과 존재하지 않거나 중복되는 시각, 미정 일정을 포함한 확인.
- **브라우저 사용성·성능:** 모바일·키보드 이동, 느린 네트워크, LCP·INP·CLS 실측, 장시간 탐색 시 메모리·DOM 증가 확인. [최적화 보고](./15_PERFORMANCE_OPTIMIZATION.md)의 자동 검사와 HTTP 측정만으로 종합 완료를 선언하지 않는다.
- **신규 데이터 연결:** 기존 346개뿐 아니라 신규 포털 승인 프로필로 목록·캘린더·통계·관심·삭제 동작 확인.

## 7. 이후 확장과 문서 정리

- 활동 시간 기반 디렉토리 탐색, 실제 특징 기반 관련 버튜버 연결, 관심 대상의 이후 활동·선택 알림.
- 동일 인물의 복수 플랫폼 채널과 여러 데뷔/재데뷔 일정 연결, 출처·이름/주소 변경 이력. 현재 프로필의 단일 채널·단일 일정 구조를 전체 위키 규모로 확장할 때 필요하다. 확인 없는 자동 병합은 하지 않는다.
- 개인별 공유 이미지, 크리에이터 홍보 결과 화면. 먼저 유효 데이터와 제외 기준을 확보한다.
- PRD 9장과 화면 계획서에는 이전 구현 상태가 남아 있다. 현재 판정은 이 점검표를 따르며, 후속 기획 때 제외된 개인 관리 화면과 이미 완료한 목록·관심 화면 표현을 동기화한다.
- MCN·회사 운영, 전 국가 수집, YouTube·Twitch 방송 통계 확대는 현재 출시의 필수 잔여 작업으로 잡지 않는다.

현재 가장 큰 제품 차이는 **‘데뷔 정보를 볼 수 있음’에서 ‘특징으로 발견하고 방송으로 이동하며, 그 결과를 확인함’까지 아직 완성되지 않았다는 점**이다. 등록·운영의 정확성을 먼저 갖추고 특징 데이터와 계측을 연결해야 플랫폼 성장 여부를 판단할 수 있다.

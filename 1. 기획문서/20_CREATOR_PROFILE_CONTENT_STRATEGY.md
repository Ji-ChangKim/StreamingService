# 데뷔 버튜버 상세페이지 콘텐츠 구성과 플랫폼 활용 조사

- **문서명**: 데뷔 버튜버 상세페이지 콘텐츠 구성과 플랫폼 활용 조사
- **버전**: v1.0 기획안
- **최종 수정일**: 2026-10-15 KST
- **작성자/담당**: Codex 콘텐츠 기획 · 프로젝트 담당자 검토

치지직·SOOP에서 데뷔하는 버튜버의 상세페이지는 **누구인지 알아보기 → 취향 확인하기 → 첫 방송 만나기 → 다음 방송에도 찾아오기** 순서로 구성한다. 첫 화면에는 활동명·개인 이미지·데뷔 일정·방송 채널을 놓고, 이어서 개인 대표 콘텐츠와 짧은 장면을 보여준다. 각 플랫폼의 콘텐츠는 목적에 따라 모으되, 화면에서는 처음 방문한 팬이 선택하기 쉬운 분량으로 편집한다.

플랫폼 지원 여부는 공식 개발 문서·고객센터·공지를 기준으로 정리했다. 아래 배치 순서, 카드 수, 갱신 주기와 운영 방식은 VDébut에 적용할 **기획 제안**이며, 전환 효과가 실측된 결과는 아니다. 이번 작업 범위는 조사·기획 문서이며 서비스 화면과 운영 데이터는 변경하지 않는다.

## 1. 상세페이지의 정보 위계

| 순서 | 방문자가 해결할 질문 | 화면 구성 | 사용할 정보와 자료 | 대표 행동 |
| --- | --- | --- | --- | --- |
| 1 | 누구인가? | 개인 이미지·활동명·한 줄 소개 | 개인 프로필, 공식 배너 또는 캐릭터 이미지, 주 방송 플랫폼, 소속·기수 | 관심 버튜버로 저장 |
| 2 | 언제 어디서 만나는가? | 데뷔 일정 또는 현재 방송 안내 | 확정 일시·시간대, 공식 공지, 확인된 방송 상태, 주 방송 채널 | 캘린더에 저장 / 방송 보러 가기 |
| 3 | 내 취향에 맞는가? | 처음 만나는 영상 | 개인 자기소개·커버곡·개인 티저 중 편집자가 선정한 대표 콘텐츠 | 대표 영상 재생 |
| 4 | 실제 방송에서는 어떤가? | 짧게 먼저 만나보기 | 치지직 클립, SOOP 유저클립·Catch, YouTube Shorts·하이라이트 | 짧은 장면 재생 |
| 5 | 어떤 방송을 하는가? | 방송 취향과 소개 | 본인 공개 주요 콘텐츠, 게임·노래·토크 등, 방송 언어, 공개된 정기 일정 | 다음 방송 확인 |
| 6 | 첫 만남을 놓쳤다면? | 첫 방송 다시보기 | 플랫폼 첫 방송 VOD, 공식 YouTube 재업로드, 검수한 챕터 | 전체 방송 / 소개 구간 보기 |
| 7 | 최근 소식은 무엇인가? | 일정·주요 공지 | 선택한 X 게시물, 플랫폼 공지, 공식 카페·소속사 공지 | 공지 원문 보기 |
| 8 | 팬으로 어떻게 참여하는가? | 팬 가이드 | 공식 팬명·호칭·해시태그·팬아트 지침·방송 규칙·공식 커뮤니티 | 해시태그 복사 / 커뮤니티 방문 |
| 9 | 누구와 함께 데뷔하는가? | 같은 팀·기수 | 공식 연결한 멤버, 릴레이 일정, 공통 PV | 멤버 상세페이지 방문 |
| 10 | 더 보고 싶다면? | 영상 모음·공식 채널·활동 기록 | 전체 미디어 목록, 목적별 채널, 확인된 방송 활동 기록 | 더 보기 / 채널 방문 |

짧은 소개는 첫 화면에 포함하고, 긴 세계관·취향 소개는 영상 뒤에 둔다. 중요 일정 변경은 7번 공지 영역에만 남겨두지 않고 2번에도 반영한다. 첫 방송이 아직 없으면 6번은 숨기며, 자료가 없는 섹션 때문에 팬에게 빈 화면을 연속해서 보여주지 않는다.

플랫폼 팔로워 수·조회수·시청자 수보다 **개인의 목소리·성격·콘텐츠·만날 시간**에 위계를 준다. 통계가 필요한 방문자는 하단 활동 기록으로 이동하게 한다. 소속 규모나 인기도가 첫 방문자의 콘텐츠 선택 순서를 결정하지 않도록 한다.

## 2. 데뷔 단계별로 달라지는 첫 화면

| 상태 | 최상단 핵심 정보 | 가장 강한 버튼 | 먼저 보여줄 미디어 | 다음 행동 |
| --- | --- | --- | --- | --- |
| 일정 미정 | 개인 소개·주 방송 채널·공식 소식 경로 | 방송 채널 보기 | 자기소개·개인 티저 | 관심 저장·공식 소식 확인 |
| 데뷔 예정 | 확정 날짜·시간·시간대 | 내 캘린더에 저장 | 자기소개·데뷔 커버·티저 | 채널 방문·관심 저장 |
| 데뷔 당일, 방송 전 | 오늘의 데뷔 시각·원문 공지 | 방송 채널 보기 | 짧은 소개·대표 영상 | 일정 확인 |
| 실제 방송 중 확인 | 방송 중 표시·현재 방송 제목 | 지금 방송 보기 | 확인된 현재 라이브 진입 카드 | 원 플랫폼에서 시청·채팅 |
| 예정 시각 경과, 시작 미확인 | 공지된 시각·채널·변경 공지 | 방송 채널 보기 | 기존 대표 콘텐츠 | 최신 공지 확인 |
| 첫 방송 종료, VOD 미공개 | 첫 방송 기록·후속 일정 중 확인된 것 | 방송 채널 보기 | 공식 하이라이트·대표 영상 | 공개 소식 확인 |
| 첫 방송 VOD 공개 | 첫 방송 보기·확정된 다음 일정 | 첫 방송 다시보기 | 개인을 소개하는 하이라이트와 첫 방송 | 다음 방송 저장 |
| 데뷔 후 활동 중 | 현재 라이브 또는 다음 확정 일정 | 지금 방송 보기 / 방송 채널 보기 | 처음 온 팬에게 좋은 장면 | 다음 방송·공식 채널 방문 |

**예정 시간이 지났다는 사실과 실제 방송 시작·종료는 별개다.** 시각만으로 LIVE, 데뷔 완료, 다시보기 공개를 표시하지 않는다. API 조회 실패나 일부 목록에서의 누락도 곧바로 오프라인의 증거로 사용하지 않는다. 확인하지 못한 방송 상태에서는 채널 방문 버튼을 유지한다.

일정은 UTC와 원래 시간대를 보관하고, 한국어 화면에서는 KST를 명확히 표시한다. 날짜만 확정되면 시간 미정으로, 일정이 연기되면 변경된 공지와 함께 표시한다. 첫 방송 시간·정기 방송 시간·영상 공개 시간은 서로 다른 일정으로 관리한다.

## 3. 치지직에서 활용할 수 있는 것

| 자료 | 공식 확인 범위 | 상세페이지 활용 | 수집과 운영 조건 |
| --- | --- | --- | --- |
| 채널 기본 정보 | 공식 채널 API에서 채널 ID·이름·이미지·팔로워 수·플랫폼 인증 여부 제공 | 개인 식별·채널 연결 | 애플리케이션 Client 인증 필요. 플랫폼 인증과 VDébut 소유권 인증은 별개 |
| 진행 중 라이브 | 공식 Live API에서 라이브 목록·제목·썸네일·시작 시각·태그·카테고리·연령 제한 등 제공 | 방송 중 진입 카드 | 채널 ID로 연결. 목록 조회의 일부 결과만 보고 방송 종료로 판단하지 않음 |
| 클립 | 고객센터에서 URL 공유와 iframe 퍼가기 지원을 명시 | 짧은 매력 소개·대표 장면 | 공유 가능한 공식 클립 URL을 등록하고 해당 클립의 실제 퍼가기 결과 확인 |
| 첫 방송·최근 다시보기 | 채널에서 공개된 다시보기 활용 | 첫 방송 기록·장시간 방송 진입 | 원문 링크를 기본으로 제공. 외부 삽입은 해당 영상에서 공식 공유 기능을 확인한 경우 사용 |
| 채널 공지·소개 | 본인 채널과 공식 공지 원문 | 데뷔 일정 근거·방송 규칙·다음 일정 | 운영자·본인 등록부터 지원하고 변경 시 원문과 대조 |

근거: [CHZZK 채널 API](https://chzzk.gitbook.io/chzzk/chzzk-api/channel), [CHZZK Live API](https://chzzk.gitbook.io/chzzk/chzzk-api/live), [치지직 클립 이용 안내](https://help.naver.com/service/23946/contents/23258?lang=ko&osType=COMMONOS).

클립의 **외부 삽입 지원**과 클립·VOD 목록의 **공식 자동 수집 API 제공**은 다른 문제다. 이번에 확인한 공식 채널·Live 문서만으로 클립·다시보기 전체 목록 자동 수집을 확약하지 않는다. 우선 URL 등록과 편집자 선정으로 구성하고, 목록 자동화는 공식 지원 범위를 추가 확인한 뒤 분리해 진행한다. 라이브 영상도 API에 재생 메타데이터가 있다는 이유만으로 외부 플레이어 삽입이 보장된다고 가정하지 않는다.

치지직의 공개 다시보기는 등급과 영상 시청 조건에 따라 보관 기간이 달라진다. 고객센터의 2025-11-05 이후 기준에서 루키는 기본 30일이며, 시청자 수 100명 미만 영상은 7일까지다. 따라서 신입의 첫 방송 URL을 영구 기록으로 취급해서는 안 된다. 만료 여부를 점검하고, 본인이 공식 YouTube에 다시 올린 경우 같은 첫 방송의 대체 시청 주소로 연결한다. [라이브 영상 저장 및 보관 안내](https://help.naver.com/service/30044/contents/22593?lang=ko&osType=COMMONOS)

## 4. SOOP에서 활용할 수 있는 것

| 자료 | 공식 확인 범위 | 상세페이지 활용 | 수집과 운영 조건 |
| --- | --- | --- | --- |
| 현재 방송 목록 | `broad/list`는 Public. 방송 제목·스트리머·썸네일·시작 시각 등 제공 | LIVE 카드·방송 진입 | 개발자 등록·클라이언트 식별 필요. 전체/카테고리 목록에서 대상 식별 |
| 특정 유저 방송 상태 | `validate/live/status`는 Consent | 확인된 현재 방송 상태 | 심사 대상 권한과 유저 접근 토큰 필요 |
| 라이브 외부 플레이어 | 공식 방송 시청 문서에서 임베디드 플레이어 안내 | 선택 시 페이지 안에서 라이브 시청 | 원 채널 방문을 함께 제공. 개별 방송의 제한·설정 확인 |
| VOD 외부 삽입 | `oembed/oembedinfo`는 Public. 제목·작성자·작성자 URL·iframe 정보 제공 | 다시보기·편집 영상의 삽입 카드 | 공식 문서의 요청 규격과 응답 사용. 모든 종류의 URL이 같은 방식으로 된다고 가정하지 않음 |
| VOD 소유권·유효성 | `validate/vod/owner`는 Consent | 잘못 연결한 영상 방지·등록 검증 | 심사 대상 권한·접근 토큰 필요 |
| 방송별 다시보기 목록 | `broad/review/list`는 Consent | 해당 방송의 분할 VOD 연결 | 접근 토큰과 방송 번호 필요. 모든 채널의 모든 VOD를 무인 수집하는 API로 해석하지 않음 |
| 유저클립·Catch | 공식 서비스에서 제공하는 짧은 콘텐츠 | 짧은 매력 소개·방송 본편 연결 | 원문 URL 등록부터 지원. 개별 URL의 공유·삽입 여부 확인 후 플레이어 연결 |
| 채널 게시판·캘린더 | 공식 채널에서 확인되는 공지·일정 | 새 소식·방송 일정 | 본인·운영자 검수 등록, 공식 원문 연결 |

근거: [SOOP 시작하기](https://developers.sooplive.com/docs/api/getting-started), [SOOP 방송 시청 API](https://developers.sooplive.com/docs/api/broad-watch), [SOOP VOD API](https://developers.sooplive.com/docs/api/vod). SOOP 개발자 문서는 브라우저의 실제 문서 본문으로 확인했다. Public은 개발자 등록 없이 모든 요청이 가능하다는 뜻이 아니며, Consent 범위는 별도 심사 조건을 확인해야 한다.

SOOP 공식 설명에서는 유저클립·다시보기·Catch와 Catch 스토리의 Full 영상 연계를 구분한다. 상세페이지에서도 짧은 콘텐츠를 보고 마음에 들면 본편으로 넘어갈 수 있게 원본 방송 관계를 저장한다. [SOOP VOD 및 숏폼 서비스 설명](https://corp.sooplive.com/esg/2024/index.php?page=corevalue)

SOOP의 2026-04-15 보관 정책 공지는 2026-06-01 적용 기준으로 일반 스트리머 다시보기를 기본 90일, 순수 조회수 50회 이상이면 1년 저장으로 안내한다. 이 변경은 업로드 VOD·클립·Catch에는 적용되지 않는다고 구분한다. 다시보기의 가용 기간은 영상별로 확인하며, 재생되지 않는 본편을 계속 대표 영상에 남기지 않는다. [SOOP 다시보기 보관 정책 공지](https://sotong.sooplive.com/?b_no=9621&board_type=servicenotice&work=view)

YouTube는 IFrame Player API로 삽입·재생 상태·오류 처리를 지원한다. 영상 리소스에서 제목·썸네일·길이·삽입 가능 상태 등을 확인할 수 있고, 채널의 uploads 재생목록과 `playlistItems.list`를 연결해 공개 업로드 후보를 수집할 수 있다. 후보 전체를 대표 콘텐츠로 자동 승격시키지 않고 목적에 맞게 선정한다. 삽입 허용 상태여도 추가 제한으로 재생되지 않을 수 있으므로 원본 보기 버튼을 유지한다. X는 개별 게시물과 공개 계정·공개 리스트의 타임라인 삽입을 지원한다. 상세페이지 기본 구성은 **중요 게시물 1~3개 선정**으로 하고, 계정 전체 타임라인은 선택 확장으로 둔다. 임베드 기능을 최신 게시물 자동 수집 API와 동일시하지 않는다. 로딩이나 표시가 실패해도 제목·날짜·원문 링크로 소식을 확인할 수 있게 한다. [게시물 삽입](https://help.x.com/en/using-x/how-to-embed-a-post), [공개 타임라인 삽입](https://help.x.com/en/using-x/embed-x-feed)

## 6. 영상 편집과 선정 원칙

### 개인을 소개하는 자료와 팀을 소개하는 자료

개인 대표 영상은 1개를 크게 보여주고, 보조 콘텐츠는 2개 안팎의 카드로 시작한다. 개인 커버곡을 등록해도 단체 PV를 삭제하지 않는다. 공통 PV는 팀·기수 자료로 따로 보관하고 같은 팀의 각 프로필에서 참조한다.

대표 영상은 최신순이나 조회수순만으로 고르지 않는다. 본인이 대표로 정한 자료를 우선 검토하고, 처음 보는 사람이 목소리·성격·주요 방송을 이해할 수 있는 것을 선정한다. 노래 중심이면 커버곡, 게임 중심이면 실제 플레이·리액션, 토크 중심이면 대화 장면, 방송 전 자료가 적으면 개인 인사·티저를 우선 검토한다. 모든 버튜버에게 커버곡을 필수 항목으로 요구하지 않는다.

### 짧은 장면

첫 목록은 3~6개를 제안한다. 제목은 원래 제목을 보관하면서 별도의 짧은 소개를 붙일 수 있다. 노래·게임·토크 등 서로 다른 매력을 보여주고, 비슷한 장면이나 같은 영상의 플랫폼별 복사본이 화면을 채우지 않게 한다. 공식 업로드와 팬 제작 클립은 구분하고 팬 제작자는 원문에 맞게 표시한다.

클립 제작자와 원본 방송자는 서로 다를 수 있으므로 두 관계를 확인한다. 이름이나 해시태그가 같다는 이유만으로 다른 버튜버의 클립을 연결하지 않는다. 팬 제보는 검수 대기열로 받고 검수 후 공개한다.

### 첫 방송 다시보기

전체 방송 링크와 함께 실제 확인한 자기소개·주요 콘텐츠 소개 등 구간으로 안내한다. 긴 방송이 여러 VOD로 나뉘면 동일 방송 아래 1부·2부로 연결한다. 방송 시간만으로 챕터를 추측하지 않는다. 타임스탬프 이동은 해당 플레이어의 지원이 확인된 경우만 사용한다. YouTube는 `start` 파라미터로 지정 시각 재생을 지원한다. [YouTube 플레이어 파라미터](https://developers.google.com/youtube/player_parameters)

### 재생 경험

처음에는 썸네일을 보여주고 선택한 플레이어만 불러온다. 여러 영상의 동시 자동재생과 소리 겹침을 피하고, 한 영상에서 다른 영상으로 넘어가면 이전 재생을 멈출 수 있게 설계한다. iframe의 내부 재생 제어·오류 감지는 제공자별 지원 범위를 확인한다. 모든 플레이어를 같은 API로 제어할 수 있다고 가정하지 않는다.

삭제·비공개·연령·지역 제한·퍼가기 제한은 서로 구분한다. 삽입만 실패하면 원문 보기로 전환하고, 공개 원문도 사라졌으면 추천 영역에서 제외한다. 공식 재업로드가 확인되면 같은 콘텐츠의 다른 시청 경로로 제공한다. 실패한 URL을 정상 재생 영상으로 표시하거나 다른 팬의 재업로드로 임의 교체하지 않는다.

모바일은 개인 식별 → 일정·주 행동 → 대표 콘텐츠 순서를 유지한다. 긴 설명으로 영상을 밀어내지 않고, 존재하는 콘텐츠만 바로 이동 메뉴에 표시한다. 하단에는 현재 단계의 주 행동 하나를 유지하는 방식을 제안한다. 데스크톱은 넓은 콘텐츠 영역과 일정·채널 보조 영역으로 구성하되 모바일과 정보 우선순위를 같게 한다.

팬에게 보이는 ‘관심 저장’은 VDébut 내 저장이며, 치지직·SOOP 팔로우나 YouTube 구독과 구분한다. 방송 시청, 팔로우, 채팅, 유료 구독·후원은 원 플랫폼으로 연결한다. 공식 인증 마크, VDébut 소유권 확인, 소속사 정보도 같은 배지로 합치지 않는다.

## 9. 자료를 모으고 유지하는 구조

현행 [PortalProfile](../shared/portal.ts)은 대표 영상 `videoUrl`·`videoTitle`·`videoKind`와 별도의 `debutVideoUrl`을 보관한다. [영상 주소 검증](../shared/profilePresentation.ts)은 YouTube 주소를 대상으로 하며, [상세페이지 플레이어](../frontend/src/portal/CreatorProfile.tsx)도 YouTube 영상을 재생한다. 따라서 치지직·SOOP URL을 기존 입력란에 넣는 것만으로 해당 플랫폼의 클립·다시보기를 함께 재생할 수는 없다.

향후에는 영상 한 개를 하나의 콘텐츠 항목으로 보관하고 프로필·팀과 연결한다. 아래는 개발에 전달할 정보 요구사항이다.

| 정보 묶음 | 필요한 항목 | 목적 |
| --- | --- | --- |
| 연결 | 개인/팀 식별자, 원본 방송자, 게시자·클립 제작자 | 잘못된 인물 연결 방지·공통 PV 공유 |
| 콘텐츠 분류 | 제공 플랫폼, 개인 소개/커버/티저/단체 PV/클립/첫 방송/최근 방송 | 플랫폼과 콘텐츠 역할을 독립적으로 관리 |
| 원문 | 공식 URL, 제공자 콘텐츠 ID, 원제목, 게시 시각 | 중복 제거·출처 확인·변경 추적 |
| 표시 | 편집 제목, 썸네일, 확인된 재생 길이·비율, 소개 문구 | 카드와 목록 구성 |

| 편집 | 대표 선정, 노출 순서, 대상 데뷔 단계, 본인 추천·운영 선정 구분 | 개인별 위계와 편집 유지 |
| 검수 | 출처, 연결 확인, 공개 상태, 검수 이력 | 팬 제보와 공개 콘텐츠 구분 |

등록 흐름은 **공식 채널 연결 → URL 등록 또는 공식 API 후보 수집 → 인물·유형·가용성 확인 → 편집·검수 → 공개**로 제안한다. 외부 메타데이터 갱신이 대표 영상 선정이나 검수 결과를 임의로 바꾸지 않게 한다.

운영 주기는 초기 제안으로, 예정자 자료는 매일·공지 변경 시 확인하고, 방송 상태는 페이지 이용 중 제공자 허용 범위 내에서 짧게 갱신한다. 첫 방송 VOD는 방송 종료 확인 후 공개 여부를 확인하고, 등록된 영상은 정기적으로 유효성을 점검한다. 구체적인 간격은 제공자 제한·응답 비용·운영량을 확인한 뒤 정한다. 일시적인 네트워크 오류 한 번으로 콘텐츠를 삭제하지 않는다.

## 10. 적용 순서와 확인할 성과

| 단계 | 작업 | 완료 판단 |
| --- | --- | --- |
| 1 | 대표·보조·팀 영상 분리, 여러 콘텐츠 저장, 첫 방송 주소의 제공자 확장 | 커버곡·공통 PV·첫 방송이 함께 남고 각각 올바른 인물에 연결됨 |
| 2 | 데뷔 단계별 안내·버튼, 개인 소개·팬 가이드·공지, 자료 없는 영역 생략 | 시간 경과만으로 LIVE가 되지 않고 각 단계에서 다음 행동이 명확함 |
| 3 | 치지직 클립·SOOP VOD/Catch 등록과 제공자별 재생·원문 이동 | 지원되는 콘텐츠만 삽입되며 실패해도 공식 원문으로 이동 가능 |
| 4 | YouTube 공개 업로드 후보·SOOP 허용 범위 등 공식 API 연동 | 권한 범위대로 수집하고 잘못된 인물·중복·삭제 자료를 처리함 |
| 5 | 첫 방송 챕터·공식 재업로드 연결·팀 공통 자료 재사용 | 만료된 본편을 방치하지 않고 첫 만남의 기록을 찾을 수 있음 |

성과는 관심 저장, 대표 콘텐츠 선택, 실제 재생 시작을 확인할 수 있는 제공자의 재생 시작, 공식 방송 채널 클릭, 캘린더 파일 다운로드, 첫 방송 다시보기 진입, 재방문으로 본다. 숫자의 의미를 유지한다. 채널 클릭을 팔로우 성공으로, iframe 클릭을 실제 시청으로, 캘린더 다운로드를 외부 캘린더 저장 완료로 집계하지 않는다. 플랫폼이 다른 시청자 수·팔로워 수를 더해 인기도 점수로 만들지 않는다.

최초 적용에서는 데뷔 예정·방송 중·시각 경과 미확인·VOD 대기·VOD 공개·자료 없음의 화면을 검증한다. 모바일 접근, 키보드 재생 선택, 제목·재생 버튼의 읽기 순서, 원문 이동, 영상 삭제·삽입 실패, 공식 공지 변경과 첫 방송 분할도 수용 기준에 포함한다.

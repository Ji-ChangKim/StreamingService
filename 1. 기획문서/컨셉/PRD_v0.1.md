# 제품 요구사항 정의서 (PRD v0.1)

- **서비스명**: 치지직 후원 룰렛 서비스 (가칭)
- **작성 버전**: v0.1 (Draft)
- **작성일**: 2026-06-13
- **문서 상태**: Draft (초안 작성 중)

---

## 1. 서비스 개요
본 서비스는 치지직(Chzzk) 스트리머가 자신의 채널 세션을 연동하여, 시청자의 후원(도네이션) 이벤트를 실시간으로 감지하고 이에 대응하는 룰렛 콘텐츠를 방송 화면(OBS 오버레이)과 스트리머 관리 대시보드에 실시간으로 표시해 주는 완전 자동화 웹 서비스입니다. 
기존의 수동식 리액션 룰렛이 가졌던 번거로움을 해결하고, 시청자와 스트리머 간의 실시간 인터랙션을 극대화하여 방송의 재미와 후원 유도를 돕는 것을 목적으로 합니다.

---

## 2. 문제 정의
1. **스트리머의 수동 운영 리스크**: 후원이 들어왔을 때 스트리머가 매번 수동으로 웹 화면을 조작하거나 주사위를 굴려 룰렛을 실행해야 하므로 게임 플레이나 방송 진행의 흐름이 끊깁니다.
2. **실시간성 및 시각적 피드백 부재**: 시청자가 후원을 보낸 후 방송 화면에 룰렛이 돌아가는 물리적인 액션과 결과 표시까지 지연이 발생하거나 자연스럽지 않아 후원 참여의 재미가 반감됩니다.
3. **투명성 및 공정성 시비**: 룰렛의 당첨 확률이 투명하게 설정되었는지 시청자가 신뢰하기 어렵고, 실제 확률대로 공정하게 추첨이 이루어졌는지 검증할 수 있는 이력 저장 및 로그 확인 수단이 부족합니다.
4. **연속 후원 처리의 한계**: 동시에 여러 명의 시청자가 후원을 할 경우, 화면에서 룰렛 연동이 겹치거나 일부 후원이 누락되어 시청자의 불만을 야기합니다.

## 3. 사용자 정의 (Target Audience & Persona)

### A. 인터넷 방송 스트리머 (Primary User)
- **특징**: 치지직 플랫폼에서 주 3회 이상 방송을 진행하는 스트리머.
- **핵심 니즈**: 
  - 복잡한 설정 없이 치지직 계정 연동만으로 실시간 후원 연동 룰렛을 켜고 싶음.
  - 후원 금액별로 서로 다른 룰렛(예: 1,000원 룰렛, 5,000원 룰렛 등)을 쉽게 구성하고 가중치(확률)를 유연하게 편집하고 싶음.
  - 후원 결과 이력을 한눈에 볼 수 있는 로그 대시보드가 필요함.

### B. 시청자 (Secondary User)
- **특징**: 스트리머를 후원하며 방송에 직접 참여하고 리액션을 즐기는 능동적 시청자.
- **핵심 니즈**:
  - 내 후원이 방송 화면에 즉각적으로 반영되어 룰렛이 작동하는 모습을 보고 싶음.
  - 룰렛의 당첨 결과가 공정하게 나왔는지 확인하고 싶음.

---

## 4. 핵심 가치 (Core Values)
- **완전 자동화 (Seamless Automation)**: 후원 수신부터 추첨, 송출까지 어떠한 수동 개입도 필요 없는 매끄러운 자동화 흐름을 보장합니다.
- **실시간 인터랙티브 (Real-time Engagement)**: 지연 시간을 최소화하여 시청자가 후원한 직후 즉각적인 시각적 리액션을 전달합니다.
- **공정성 및 투명성 (Fairness & Logs)**: 모든 룰렛 결과는 가중치 기반으로 공정하게 도출되며, 백엔드 DB에 영구 기록되어 언제든 로그로 투명하게 조회 가능합니다.

---

## 5. 핵심 시나리오 (Core Scenario Flow)
1. **온보딩 및 설정**:
   - 스트리머는 서비스를 방문하여 치지직 계정 및 세션 연동을 마칩니다.
   - 스트리머는 룰렛을 생성합니다. (예: '벌칙 룰렛' - 매칭 금액 1,000원, 아이템: 리액션 20%, 꽝 80%)
   - 제공된 고유 OBS 오버레이 URL을 복사하여 OBS 방송 프로그램의 '브라우저 소스'에 추가합니다.
2. **후원 및 룰렛 트리거**:
   - 시청자가 방송을 보던 중 1,000원(치즈)을 스트리머에게 후원합니다.
   - 백엔드 수신 엔진이 실시간으로 이벤트를 감지하고 후원 금액(1,000원)을 판별합니다.
   - 금액과 일치하는 '벌칙 룰렛'을 매칭하여 가중치(확률) 기반 알고리즘을 통해 결과('리액션')를 즉시 도출하고 DB에 로그를 남깁니다.
3. **실시간 송출**:
   - 도출된 결과 데이터가 실시간 통신 채널을 통해 OBS 오버레이 화면으로 전송됩니다.
   - 방송 화면(OBS 오버레이)에 화려한 룰렛 회전 애니메이션이 재생된 후 결과('리액션')가 화면에 크게 표시됩니다.
   - 동시에 스트리머 관리 대시보드 내 실시간 로그 창에 후원 정보와 룰렛 결과가 실시간으로 기록됩니다.

## 7. 기능 요구사항 (Functional Requirements)

### 7.1. 스트리머 온보딩 및 계정 설정
- 스트리머는 치지직 OAuth 로그인을 통해 서비스에 가입 및 로그인할 수 있어야 한다.
- 로그인 성공 시 스트리머의 치지직 채널 ID, 채널명, 채널 프로필 이미지를 자동으로 연동하고 데이터베이스에 등록한다.
- 스트리머의 Access Token 및 Refresh Token은 안전하게 관리되어야 하며 만료 시 백엔드에서 자동으로 갱신을 시도해야 한다.

### 7.2. 룰렛 콘텐츠 구성 (CRUD)
- 스트리머는 원하는 수만큼 룰렛을 생성할 수 있다.
- 룰렛 생성 시 필수 입력 필드:
  - 룰렛 이름 (예: 애교 룰렛)
  - 트리거 금액 (최소 후원 금액 설정, 예: 2,000원)
  - 활성화 여부 (On/Off 토글)
- 각 룰렛은 여러 개의 '아이템'을 가질 수 있으며, 각 아이템마다 이름과 '가중치(확률)'를 정수로 입력한다.
  - 예: 아이템 A(가중치 10), 아이템 B(가중치 90) -> 아이템 A 당첨 확률 10%, 아이템 B 당첨 확률 90%로 자동 환산 및 결과 도출.

### 7.3. 실시간 후원 수신 및 룰렛 처리 엔진
- 시스템은 연동된 치지직 세션을 통해 시청자의 후원 이벤트를 실시간(1초 이내)으로 감지해야 한다.
- 감지된 후원의 금액을 분석하여, 스트리머가 활성화해 둔 룰렛 중 해당 금액에 부합하는 룰렛을 매칭한다.
- 매칭된 룰렛의 아이템 가중치를 바탕으로 당첨 결과를 백엔드에서 공정하게 무작위 추출하고, 이를 DB(후원 로그 테이블)에 영구 저장한다.

### 7.4. OBS 오버레이 화면 송출
- 스트리머별 고유 식별 토큰이 포함된 OBS 오버레이 URL을 발급한다. (예: `/overlay/roulette?token=uuid-xyz`)
- 해당 URL은 OBS 웹 브라우저 소스로 등록이 가능해야 하며, 배경이 투명한 웹 뷰로 렌더링되어야 한다.
- 백엔드에서 결과가 확정되어 실시간 통신(WebSocket 등)으로 데이터를 수신하면, 오버레이 화면에서 룰렛 회전 애니메이션이 3~5초간 재생된 후 최종 결과 텍스트와 이미지, 그리고 후원자의 닉네임과 메시지가 노출되어야 한다.

### 7.5. 후원 로그 및 대시보드
- 스트리머는 관리자 대시보드에서 역대 룰렛 실행 이력(날짜/시간, 후원자명, 후원 금액, 적용된 룰렛명, 당첨 결과)을 표 형태로 조회할 수 있어야 한다.
- 날짜 필터, 후원자 이름 검색, 룰렛 콘텐츠 필터링 기능을 제공한다.

## 8. 정책 요구사항 (정책 정의표)

| 정책 ID | 정책 항목 | 상세 정책 정의 및 처리 방안 |
| :--- | :--- | :--- |
| **POL-01** | **후원 이벤트 매칭** | - 후원이 수신되면 활성화된 룰렛들의 '트리거 금액'과 정확히 일치하는 룰렛을 실행한다.<br>- 일치하는 금액의 룰렛이 없을 경우, 해당 후원은 일반 리액션용 알림으로만 처리하거나 무시한다.(룰렛 실행 안 함) |
| **POL-02** | **중복 이벤트 방지** | - 치지직 후원 API가 제공하는 고유 후원 트랜잭션 ID(`transaction_id` 또는 `event_id`)를 고유 식별자로 지정한다.<br>- 수신된 모든 후원 ID는 백엔드 캐시(Redis/Cloudflare KV 등)에 저장하고, 중복 수신된 ID인 경우 처리를 즉시 스킵하여 룰렛이 2번 돌아가는 현상을 방지한다. |
| **POL-03** | **후원 연속 발생 (큐)** | - 한 번에 여러 후원이 몰릴 경우, 오버레이 화면 및 백엔드 엔진은 **FIFO(선입선출) 큐** 구조로 이벤트를 처리한다.<br>- 이전 룰렛 애니메이션 재생이 완전히 끝난 시점에 큐에서 다음 후원 이벤트를 꺼내어 룰렛을 구동한다. |
| **POL-04** | **익명 후원 처리** | - 시청자가 닉네임을 비공개로 후원한 경우, 화면 및 로그에는 `익명의 후원자`로 표시한다.<br>- 단, 데이터의 정합성을 위해 내부 시스템에서는 고유 비회원 식별 ID를 생성하여 로그에 바인딩한다. |
| **POL-05** | **실패 이벤트 대응** | - 네트워크 끊김 등으로 룰렛 애니메이션 송출이 실패했거나, 실시간 통신 연결이 끊겼던 유실 후원에 대응하기 위해 스트리머 대시보드 로그 내에 `수동 재송출` 버튼을 제공한다.<br>- 스트리머가 버튼을 누르면 해당 로그의 데이터를 기반으로 OBS 오버레이 화면에 룰렛이 재실행된다. 단, 결과는 중복 산출되지 않고 기존에 저장된 결과를 그대로 송출한다. |
| **POL-06** | **보안 및 토큰 유출 방지** | - OBS 오버레이 URL에 포함되는 토큰이 방송 화면에 노출되거나 타인에게 유출된 경우를 대비해, 스트리머 설정 페이지에서 원클릭으로 토큰을 파기하고 재발급할 수 있는 기능을 제공한다. |

## 9. 비기능 요구사항 (Non-Functional Requirements)
- **성능 및 지연 시간**: 시청자의 후원 시점부터 OBS 오버레이 화면에 룰렛 애니메이션이 시작되는 시점까지의 총 대기 시간(지연)은 평균 1.5초를 초과하지 않아야 한다.
- **안정성 (High Availability)**: Cloudflare Workers 및 Durable Objects 아키텍처를 도입하여 대규모 트래픽 분산 처리를 구현하며, 서버 다운타임을 최소화한다.
- **보안**: 
  - 스트리머의 개인 정보 및 치지직 OAuth 토큰은 데이터베이스 저장 시 반드시 양방향 암호화 알고리즘(AES-256 등)을 적용해 안전하게 보호되어야 한다.
  - 모든 API 통신은 HTTPS/WSS 보안 프로토콜을 필수로 한다.
- **사용성 (Responsiveness)**: 스트리머 관리 대시보드는 모바일 및 태블릿 브라우저에서도 설정 관리가 용이하도록 반응형 웹 디자인으로 제작한다. (단, OBS 오버레이 화면은 방송 표준 해상도인 1920x1080 및 1280x720 렌더링에 최적화한다.)

## 10. 성공 지표 (KPIs)
1. **실시간성 만족도**: 실시간 이벤트 지연 시간(E2E Latency) 평균 1.2초 이내 달성.
2. **세션 재연결 성능**: 치지직 세션 끊김 발생 시 3초 이내에 끊김 없는 자동 재연결에 성공하는 비율 98% 이상 확보.
3. **오버레이 정상 송출율**: 후원 트리거 건수 대비 OBS 오버레이 룰렛 애니메이션의 누락 없는 실행 성공률 99.9% 이상 유지.

## 11. 제외 범위 (Out of Scope)
- 숲(SOOP), 유튜브(YouTube) 등 치지직 외 타 인터넷 방송 플랫폼 동시 연동 기능은 MVP 범위에서 제외하며, 추후 확장 모델로 구성한다.
- 룰렛 휠의 개별 스킨 디자인 커스터마이징(CSS 업로드 등) 및 커스텀 이미지/사운드 파일 직접 업로드 기능은 서버 저장 공간 부담을 최소화하기 위해 MVP에서 배제하고, 기본 프리셋 테마 및 사운드 세트 중에서 선택하는 방식으로 대체한다.

## 12. 리스크 분석 및 완화 방안 (Risks & Mitigations)

| 리스크 내용 | 발생 가능성 | 영향도 | 완화 방안 |
| :--- | :---: | :---: | :--- |
| **치지직 비공식 API 변경** | 높음 | 매우 높음 | - 치지직의 세션 및 후원 수신 API의 구조가 갑작스럽게 변경될 수 있으므로, 이벤트 파싱 로직을 서비스 아키텍처 상 모듈로 완전 분리(Decoupling)하여 신속하게 패치할 수 있는 구조로 개발한다.<br>- 향후 치지직 공식 OpenAPI가 출시되면 즉시 마이그레이션이 가능하도록 설계한다. |
| **후원 폭주로 인한 큐 버퍼링** | 보통 | 보통 | - 스트리머의 대형 방송 진행이나 이벤트성 리액션 시 일시적으로 수백 건의 후원이 밀릴 수 있으므로, 브라우저 사이드(오버레이 뷰어)와 서버 사이드 모두에 메세지 큐 버퍼링 장치를 마련하여 유실 없이 순차 렌더링을 보장한다. |
| **오버레이 URL 도용** | 보통 | 높음 | - 타인이 오버레이 주소를 탈취하여 불법 송출이나 조작을 가하지 못하도록, 오버레이 URL은 무작위 난수(UUIDv4) 토큰 기반으로 하고 유효하지 않은 요청은 서버 단에서 즉시 차단하며 실시간 갱신 기능을 지원한다. |

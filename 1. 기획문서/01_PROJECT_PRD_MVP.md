## 1. 제품 정의와 방향

### 1.1 무엇을 만드는가

VDébut는 국가와 방송 플랫폼에 흩어진 버튜버의 정보·특징·일정·활동 기록을 연결하여, 팬이 자신에게 맞는 버튜버를 알아보고 실제 방송으로 찾아갈 수 있도록 돕는 통합 플랫폼이다.

장기적으로 유명 버튜버부터 소규모·신입 버튜버까지 폭넓게 조회할 수 있는, 위키처럼 정보가 축적되는 플랫폼을 지향한다. 데뷔 여부·방송 규모·직접 가입 여부만으로 조회 대상을 제한하지 않는다. 실제 조회 범위는 확보한 정보와 지원 플랫폼에 따라 단계적으로 넓힌다.

신규 버튜버가 홍보를 위해 **“나 데뷔합니다”를 직접 등록하는 행동**을 현재의 핵심 성장 목표로 삼는다. VDébut는 각자의 주 방송 플랫폼 밖에서 자신을 소개하고 새로운 팬과 만날 접점을 제공한다.

### 1.2 사용자가 써야 하는 이유

| 사용자 | 이용 이유 | 얻어야 할 결과 |
| --- | --- | --- |
| 팬·시청자 | 여러 플랫폼의 버튜버를 특징·콘텐츠·시간으로 알아보고 싶다 | 관심 있는 사람을 발견하고 소개를 확인한 뒤 방송으로 이동한다 |
| 데뷔 준비생·신입 버튜버 | 기존 팔로워 밖에 데뷔 소식과 내 특징을 알리고 싶다 | 직접 등록한 소개와 일정이 공개되고, 공유할 수 있는 주소를 얻는다 |
| 활동 중인 버튜버 | 나를 소개하고 활동 정보를 관리하며 방송 환경을 살펴보고 싶다 | 자신의 소개를 보완하고 시간대·콘텐츠 자료를 계획과 회고에 참고한다 |
| 정보를 보완하는 팬·제보자 | 누락되거나 바뀐 공개 정보를 알리고 싶다 | 출처와 함께 제보하고 반영 결과를 확인한다 |

### 1.3 장기 비전과 현재 목표

| 구분 | 방향 |
| --- | --- |
| 장기 제품 비전 | 국가·플랫폼·규모를 넘어 버튜버 정보와 활동이 축적되고 탐색되는 플랫폼 |
| 현재 성장 목표 | 신규 버튜버가 자신의 홍보를 위해 자발적으로 데뷔를 등록하는 곳 |
| 팬에게 제공할 핵심 가치 | 누가 언제 어디서 데뷔하는지, 어떤 특징과 콘텐츠를 가진 사람인지 알아보고 방송으로 연결 |
| 버튜버에게 제공할 핵심 가치 | 외부 홍보 접점과 소개 관리, 활동 시간·콘텐츠 판단에 참고할 실제 자료 |
| 장기 사업 선택지 | MCN·버튜버 회사 등으로 사업을 확장할 가능성. 현재 제품의 필수 조건이나 개발 일정으로 확정하지 않음 |

## 2. 해결할 문제와 제품 목표

### 2.1 해결할 문제

1. 국가와 방송 플랫폼마다 데뷔와 활동 정보가 흩어져 있어 존재 자체를 모르는 버튜버가 많다.
2. 이름·이미지·플랫폼만으로는 방송의 특징과 분위기를 이해하거나 시청 여부를 판단하기 어렵다.
3. 데뷔 공지를 발견해도 시각·방송 주소·일정 변경을 한곳에서 확인하기 어렵다.
4. 인기 카테고리를 확인한 다음 실제 버튜버와 방송을 찾아가는 연결이 부족하다.
5. 버튜버는 자신의 활동 시간과 콘텐츠를 고민할 때 참고할 방송 환경과 사례가 필요하다.
6. 운영자가 정보를 채우는 것만으로는 전체 버튜버의 정보를 지속적으로 관리하기 어렵다.

### 2.2 제품 목표

| ID | 목표 | 확인할 사용자 행동 |
| --- | --- | --- |
| G-01 | 데뷔 발견 | 캘린더에서 데뷔자·일시·플랫폼을 확인하고 개인 소개 또는 방송으로 이동 |
| G-02 | 특징을 통한 만남 | 콘텐츠·소개·언어·활동 시간 등을 확인한 뒤 관심 있는 방송으로 이동 |
| G-03 | 자발적인 홍보 등록 | 버튜버가 직접 데뷔를 신청하고 공개된 소개 페이지를 공유 |
| G-04 | 활동 판단 지원 | 버튜버가 시간대·카테고리·방송 기록을 살펴보고 계획·회고에 참고 |
| G-05 | 정보 축적과 관리 | 동일 인물의 정보가 연결되고 본인·운영·출처 있는 제보로 갱신 |
| G-06 | 지속적인 관계 | 팬이 관심 있는 버튜버의 이후 활동을 다시 확인하고 새로운 사람도 탐색 |

### 2.3 검증할 가설

- 특징과 대표 콘텐츠를 보여주면 일정·순위만 제공할 때보다 개인 소개와 방송 링크로의 이동이 늘어난다.
- 등록 결과물이 홍보에 유용하면 크리에이터가 자발적으로 등록하고 공유한다.
- 같은 콘텐츠·활동 시간·소속 등 관련성이 있는 연결이 다른 버튜버의 발견으로 이어진다.
- 소개와 활동 정보가 갱신되면 데뷔 이후에도 재방문할 이유가 생긴다.

위 내용은 검증 대상이며 이미 입증된 효과가 아니다. 등록·클릭을 실제 팬 증가나 체급 성장으로 표현하지 않는다.

## 3. 제품 구조와 사용자 흐름

### 3.1 네 가지 핵심 영역

| 영역 | 답해야 하는 질문 | 다음 행동 |
| --- | --- | --- |
| 메인 데뷔 캘린더 | 누가 언제 어디서 데뷔하는가? | 소개 확인, 일정 저장, 방송 방문, 직접 등록 |
| 방송 통계 | 어떤 방송과 콘텐츠가 현재 인기 있으며 시간에 따라 어떻게 활동하는가? | 카테고리·시간대 탐색, 개별 방송·개인 기록·소개 확인 |
| 버튜버 소개·정보 | 어떤 사람이고 무엇을 방송하며 언제 어디서 만날 수 있는가? | 대표 콘텐츠 확인, 공식 채널 방문, 공유, 이후 활동 확인 |
| 등록·정보 관리 | 내 데뷔와 특징을 어떻게 알리고 최신 정보로 유지하는가? | 등록, 검토 상태 확인, 수정 요청, 본인 확인 후 관리 |

메인은 캘린더를 유지한다. 전체 버튜버 검색과 정보 축적은 캘린더의 날짜 구조에 종속시키지 않는다. 통계는 팬의 콘텐츠 탐색과 버튜버의 활동 판단을 모두 지원한다.

### 3.2 대표 시나리오

| ID | 사용자 과제 | 성공 결과 |
| --- | --- | --- |
| S-01 | 팬이 이번 주 데뷔자를 찾는다 | 현지 시각과 방송 플랫폼을 확인하고 특징을 알아본 뒤 방송 주소 또는 일정 저장으로 이동 |
| S-02 | 팬이 인기 카테고리에서 취향을 찾는다 | 해당 카테고리의 방송을 탐색하고 버튜버 소개·대표 콘텐츠·실제 방송을 확인 |
| S-03 | 팬이 알고 있는 버튜버를 검색한다 | 생방송 여부와 무관하게 확보된 개인 정보와 활동 기록을 찾음 |
| S-04 | 신인이 자신의 데뷔를 홍보한다 | 등록 신청, 접수 확인, 검토 결과, 공개 페이지, 공유까지 이어짐 |
| S-05 | 날짜나 시간이 아직 정해지지 않았다 | 미정 상태로 신청하고 확정 후 같은 소개와 일정에 반영 |
| S-06 | 활동 중인 버튜버가 방송 방향을 검토한다 | 플랫폼·기간·시간대·콘텐츠 조건으로 실제 자료와 방송 사례를 확인 |
| S-07 | 기존 페이지의 본인이 찾아온다 | 본인 확인을 거쳐 기존 소개를 보완하며 불필요한 중복 페이지를 만들지 않음 |
| S-08 | 팬이 일정 변경이나 정보 오류를 발견한다 | 출처를 첨부해 제보하고 검토·반영 상태를 확인 |
| S-09 | 팬이 관심을 둔 버튜버를 다시 찾는다 | 같은 주소에서 최신 소개와 확보된 이후 활동을 확인 |

### 3.3 성장 흐름

**직접 등록 → 소개·일정 공개 → 크리에이터의 공유 → 팬의 특징 확인 → 방송 방문 → 이후 활동 확인 → 관련 버튜버 탐색 → 다른 크리에이터의 등록**

검색·캘린더·통계도 팬의 유입 경로다. 크리에이터가 가져온 방문과 VDébut 내부에서 발생한 발견을 구분하여 홍보 가치를 평가한다. 유명 버튜버 방문자가 자동으로 신인을 찾을 것이라고 가정하지 않는다.

## 4. 범위와 우선순위

### 4.1 우선순위 정의

- **P0 / 다음 핵심 개선 범위**: 데뷔 등록·소개·발견·방송 연결의 기본 경험과 운영 신뢰성을 완성한다. 기존 기능의 존재를 검증하고 부족한 부분을 보완한다.
- **P1 / 후속 확장**: 전체 조회, 본인 관리, 구조화된 특징 탐색과 재방문 경험을 확장한다.
- **장기**: 생태계·사업 확장. 이용자 수요와 운영 가능성을 확인한 뒤 별도 PRD로 구체화한다.

우선순위는 구현 완료 상태나 이미 제공 중인 기능의 제거 지시가 아니다. 구체적인 배포 묶음과 일정은 구현 차이·리소스 확인 후 정한다.

### 4.2 현재와 장기 범위의 구분

| 주제 | P0 | P1 | 장기 |
| --- | --- | --- | --- |
| 캘린더 | 월·주 탐색, 플랫폼·국가, 미정·변경 상태, 개인 소개 연결 | 추가 행사 유형과 탐색 개선 | 생태계 전반의 행사 연결 |
| 직접 등록 | 데뷔 신청, 접수·검토·공개 상태, 공개 주소, 수정 요청 | 본인 관리, 활동 중 버튜버 등록 | 검증된 대리 관리 확대 |
| 소개 | 기존 정보와 본인 소개, 방송 특징, 공식 채널, 대표 콘텐츠 링크 | 언어·특징·활동 시간별 탐색 | 출처 있는 정보·관계·활동 이력 확장 |
| 통계 | 기존 현황·기록 유지, 범위 명시, 콘텐츠·시간 탐색과 소개 연결 | 확보 가능한 시청·활동 자료와 비교 개선 | 수요가 검증된 고급 분석 |
| 전체 조회 | 현재 확보한 공개 대상의 검색과 연결 | 일정 없는 버튜버 등록·조회, 국가·플랫폼 확장 | 규모에 제한 없는 통합 정보 플랫폼 |
| 관심·재방문 | 고정 주소와 최신 정보 확인 | 관심 저장, 알림·기존 디스코드 연동 개선 | 팬 활동과 커뮤니티 확장 검토 |

### 4.3 이번 핵심 개선의 범위에 포함하지 않는 것

- MCN·버튜버 회사 설립·직접 운영, 전속 계약, 인재 선발 사업.
- 후원 결제·정산, 유료 카드팩·모의 주식, 굿즈 커머스, 자체 대규모 커뮤니티.
- 근거 없는 성공 확률·체급 상승 예측·최적 시간 점수·인물 가치 등급.
- 모든 국가·방송 플랫폼의 완전 수집을 전제로 하는 출시 약속.
- 확인되지 않은 인물 병합, 외부 공개 정보 전체의 무조건 수집.

기존 사업 확장 제안의 아이디어는 장기 참고 자료로 유지한다. 기존 문서의 유입·매출·수익률·생존율 수치는 검증된 기준선이나 본 PRD의 확정 목표로 승계하지 않는다.

### 5.1 등록과 수정의 상태

권장 제품 흐름은 **입력 → 접수 → 검토 → 보완 요청 또는 공개 → 수정·취소·정정**이다. 접수만으로 공개나 본인 확인이 완료된 것으로 취급하지 않는다. 검토 방식과 자동 처리 조건은 운영·권한 설계에서 확정한다.

- 날짜·시간 모두 확정, 날짜만 확정, 예정 월만 있는 일정을 구분한다. 모르는 일시를 임의로 확정해 노출하지 않는다.
- 신청 결과를 다시 확인할 수단을 제공한다. 조회 권한 없는 사람에게 신청 내용·관리 기능을 공개하지 않는다.
- P0의 정보 수정은 검토 가능한 요청 경로로 지원한다. 확인된 본인의 직접 관리는 VDB-11에서 완성한다.
- 같은 버튜버의 재데뷔·이적 등 추가 사건은 기존 소개와 연결한다. 사건 유형별 공개 정책은 별도 정의한다.

### 5.2 소개에 필요한 정보

| 정보 | 등록·입력 정책 | 공개·탐색 정책 |
| --- | --- | --- |
| 활동명·공식 방송 주소 | 데뷔 신청 필수. 확인 가능한 채널 식별 정보 사용 | 동명이인 구분, 공식 방송 연결 |
| 일정·시간대·미정 상태 | 데뷔 신청 필수. 미정 상태 허용 | 현지 시각과 확정 여부 표시 |
| 짧은 자기소개 | 직접 신청 시 필수. 제보·수집 대상은 없을 수 있음 | 본인이 직접 소개한 내용인지 구분 |
| 주로 하는 콘텐츠 | 선택 입력 후 점진적 보완 | 본인 설명과 관측된 방송 카테고리 구분 |
| 방송 분위기·특징 | 선택 입력. 본인이 설명하는 표현 사용 | 목소리·성격·매력을 시스템이 임의 평가하지 않음 |

| 소속·팀·공식 SNS | 선택 입력·공개 출처 확인 | 확인된 관계와 공식 링크 연결 |

선택 정보를 모두 채워야 등록할 수 있는 구조로 만들지 않는다. 사진·영상·문구는 공개 가능한 자료를 사용하며 출처와 수정 요청 경로를 유지한다.

### 5.3 통계의 두 가지 사용 목적

**팬**은 인기 콘텐츠와 현재 방송에서 출발해 취향에 맞는 버튜버를 찾아간다. **버튜버**는 자신의 활동 시간·콘텐츠를 실제 방송 환경과 비교하여 계획과 회고에 참고한다.

- 전체 인터넷 방송의 현황을 제공하는 기존 통계 목적을 유지한다. 전체 방송 통계를 버튜버만의 통계라고 부르지 않는다.
- 전체 방송·확인된 버튜버·VDébut 등록 대상의 범위를 구분한다. 분류가 불명확한 채널을 자동으로 버튜버 소개 대상에 편입하지 않는다.
- 인기 판단에 쓰는 지표를 명시한다. 시청자 수, 방송 채널 수, 방송 시간·횟수는 다른 지표다.
- 플랫폼·기간의 수집 범위가 다르면 동일한 전체 집계처럼 비교하지 않는다. 누락·미지원은 0과 구분한다.
- 시간대별 활동 채널 수만으로 유입 기회·예상 시청자 수·체급 상승을 계산하지 않는다.
- 유사 규모 비교 등은 비교 가능한 자료와 표본이 확보된 뒤 제공한다. 불가능한 분석은 후속 과제로 남긴다.
- 인기 방송 탐색과 신인 발견을 모두 지원한다. 인기 순위를 유일한 발견 방식으로 삼지 않는다.
- 현재 통계 공개 범위는 SOOP·치지직을 기준으로 한다. YouTube·Twitch 등 데뷔 등록과 통계의 지원 범위는 따로 관리한다. 기존 통계 문서의 플랫폼 제한을 임의 해제하지 않는다.

세부 지표 정의와 집계 계약은 [방송 통계 PRD](./방송통계페이지%20문서/02_PRD.md)와 최신 구현 보고서를 따른다. 이 개정으로 기존 통계 PRD의 미완료 요구가 완료 처리되거나 삭제되지는 않는다.

## 6. 정보 축적과 운영 원칙

### 6.1 인물·채널·일정의 구분

- 버튜버 한 명은 여러 방송 플랫폼과 채널에서 활동할 수 있다.
- 한 명에게 여러 일정·기념일·방송 기록이 연결될 수 있다.
- 동일 인물임이 확인되지 않은 채널을 이름·이미지가 비슷하다는 이유로 병합하지 않는다.
- 이름·플랫폼이 바뀌어도 기존 정보와 공유 주소의 연결을 가능한 한 유지한다.
- 물리적인 DB 구조·식별자·이관 방식은 현행 스키마를 확인한 뒤 별도 기술 설계로 정한다.

### 6.2 정보 성격과 관리 주체

| 정보 성격 | 주된 관리 주체 | 관리 원칙 |
| --- | --- | --- |
| 공개 기본 정보 | 운영자·확인된 수집 | 공식 출처와 확인 시점 유지 |
| 본인 작성 소개 | 확인된 버튜버·허용된 대리인 | 본인 작성 영역과 수정 이력 구분 |
| 방송 활동 기록 | 검증된 수집·집계 | 관측 시각·범위·누락 관리 |
| 팬의 제보 | 제보자·운영 검토 | 출처 첨부 후 검토·반영 |

위키형 축적을 지향하지만 누구나 즉시 공개 내용을 덮어쓰는 권한을 전제로 하지 않는다. 정보 충돌·중복·오류를 처리할 담당과 이력을 둔다. 직접 가입하지 않아도 확보된 공개 정보를 기반으로 기본 페이지를 제공할 수 있고, 본인이 확인 후 보완하는 방식으로 확장한다.

### 6.3 공개 범위

공개 활동 정보와 서비스 목적에 필요한 자료를 중심으로 다룬다. 비공개 신상·추측성 동일인 정보·사적 연락처를 소개 확장의 기본 항목으로 삼지 않는다. 신청 연락처·권한 확인 자료는 공개 소개와 분리한다. 정정·삭제 요청은 연결된 기록과 공개 범위를 검토하여 처리한다.

### 7.2 사용성·문구·브랜드

- 모바일과 키보드로 탐색·검색·등록·소개 확인·공식 채널 이동이 가능해야 한다.
- 회원 가입 없이 공개 일정·소개·지원 통계를 조회할 수 있어야 한다. 관리 권한 확인은 별도 설계한다.
- 긴 설명보다 특징·일정·방송 주소를 쉽게 확인하게 한다. 정보가 적은 페이지도 실제 확보한 내용과 보완 경로를 제공한다.
- 상세에서 돌아오면 이전 탐색 조건을 유지한다.
- 시간대를 적용하고 언어·국가·방송 플랫폼을 서로 다른 조건으로 다룬다.
- 개발자 관점의 설명, 검증되지 않은 홍보 효과·추천 점수·성공 확률을 사용자 문구에 넣지 않는다.
- 확인 시각·미정·자료 없음·조회 실패 등 판단에 필요한 상태는 쉬운 말로 알린다.
- 로딩·오류·결과 없음·미공개를 구분하고 재시도 또는 다음 행동을 제공한다.
- 공식 플랫폼 브랜드 자산은 원형을 유지한다.
- 별도 슬로건을 추가하지 않는다. **“버튜버와 팬의 소개팅”**을 유지한다.

## 8. 성공 지표와 측정 기준

### 8.1 핵심 성장 지표

**본인 직접 신청으로 공개된 신규 데뷔 등록 수와 비율**을 현재의 핵심 성장 지표로 삼는다. 등록 증가와 함께 팬의 특징 확인·방송 이동·재방문을 확인하여 공급만 쌓이는 상태를 구분한다.

| 지표 | 정의 | 해석 시 구분 |
| --- | --- | --- |
| 본인 직접 등록 수 | 기간 내 처음 공개된 고유 데뷔 일정 중 본인이 직접 신청한 건수 | 운영 수집·팬 제보·대리 신청·재신청 제외. 본인 확인 여부 별도 집계 |
| 본인 직접 등록 비율 | 같은 기간의 본인 직접 등록 수 / 전체 신규 공개 데뷔 일정 수 | 일정 기준으로 계산. 고유 버튜버 수 별도 기록 |
| 등록 완료율 | 해당 기간에 시작한 신청 집단 중 정해진 관찰 기간 내 유효 접수를 마친 신청 수 / 시작 신청 수 | 접수와 공개 구분. 중복 시도 제거 |
| 공개 소요 시간 | 유효 접수부터 최초 공개까지 소요 시간의 중앙값과 상위 구간 | 보완 요청·미공개·반려 별도 추적 |
| 소개 도달률 | 소개 진입 세션 / 해당 탐색 영역 이용 세션 | 캘린더·통계·검색별 집계 |
| 대표 콘텐츠 확인률 | 대표 콘텐츠가 있는 소개를 본 세션 중 재생 또는 원문 이동 세션 비율 | 재생 시작·클릭을 시청 완료로 간주하지 않음 |
| 방송 링크 이동률 | 소개를 본 세션 중 공식 방송 링크를 누른 세션 비율 | 직접 방송 이동은 출발 화면별 별도 집계. 실제 시청과 구분 |
| 신인 노출 분포 | 노출된 신인 중 유효 소개 조회·방송 클릭을 받은 인원 비율과 집중도 | 총 클릭만으로 편중을 숨기지 않음 |
| 이후 활동 재방문율 | 소개 조회 집단 중 관찰 기간 내 같은 인물을 다시 찾은 비율 | 관찰이 끝난 집단만 비교. 식별 범위 명시 |
| 정보 관리 참여 | 본인·제보자의 유효 보완 건수와 갱신된 고유 페이지 수 | 빈 수정·자동 갱신과 사용자 참여 구분 |

공유 버튼 클릭은 외부 게시 완료를 의미하지 않는다. 공유 링크에서 발생한 방문과 크리에이터가 확인해 준 공유 여부를 함께 평가한다.

### 8.2 계측 요구

최소 계측 대상은 `registration_start`, `registration_submit_success`, `registration_published`, `creator_profile_view`, `representative_content_open`, `broadcast_link_click`, `share_action`, `shared_link_visit`, `profile_correction_submit`이다. 구현 시 명칭은 조정할 수 있지만 의미를 유지한다.

- 접수·공개는 서버에서 확인된 처리 결과로 기록한다.
- 소개·방송 이동에 출발 영역, 인물/채널/일정 식별자, 시각을 연결한다.
- 신청 출처, 신청자 역할, 본인 확인 상태를 별도로 관리한다.
- 중복·봇·운영 조회 제외 정책과 관찰 기간을 지표 정의서에 기록한다.
- 사적 연락처·채팅 원문 등 불필요한 개인정보를 분석에 넣지 않는다.

### 8.3 기준선과 목표

이 문서에서 실제 분석 데이터의 기준선은 확인하지 않았다. 트래픽·전환율·매출의 확정 숫자를 제시하지 않는다. 계측을 점검하고 정상 운영 데이터를 확보한 뒤 기간·분모·제외 기준을 고정한다. 같은 기준의 전후 행동과 사용자 과제 수행 결과로 개선안을 검증한다.

## 9. 현재 구현과 요구사항의 차이

> **LIVE 배포 후 최신 점검:** [2026-10-11 PRD 잔여 항목 점검](./17_PRD_GAP_CHECKLIST.md)을 현재 판정으로 사용한다. 아래 표는 포털 전체 화면 배포 이전의 점검 기록이며, 이후 구현된 목록·관심·일정 없는 소개 등록 등을 미구현으로 판단하는 근거로 사용하지 않는다. 제외된 개인 관리·데뷔 신청 상태 조회에는 문서 상단 사용자 확정 변경을 적용한다.

2026-10-11 작업 공간의 코드와 문서에 근거한 점검이다. 미배포 변경이 포함되어 있으므로 운영 사이트 전체의 완료 판정으로 사용하지 않는다. 지원 플랫폼별 실제 조회·등록·권한 동작은 후속 검증이 필요하다.

### 12.1 이번 개정의 제품 결정 근거

- 사용자 지정 슬로건: **“버튜버와 팬의 소개팅”**.
- 현재 성장 목표: 신규 버튜버가 홍보를 위해 **“나 데뷔합니다”를 직접 등록**하는 사이트.

## 1 목적·입력·출력

목적은 **사람 이름 없이 데뷔 관련 공지를 발견하고, 출처·누가·언제·어디서를 근거와 함께 공개 전 후보로 만드는 것**이다. 전체 채널을 열거하거나 검색 결과를 곧바로 공개하지 않는다. 초기 최종 승인은 운영자가 한다.

입력: 활성 출처/접근 범위, 검색어 버전, 마지막 완료 시점, 미완료 조회 구간/커서, 일일 예산, 기존 원문/후보·채널·행사·차단 목록.

출력: 신규/변경 후보, 원문과 항목별 근거, 검수 범위(인물/일정), 누락·충돌 사유, 재확인 시점, 검색 성공/부분/실패·확인 공백·요청 사용량. 결과 0건·미연결·실패를 구분한다.

## 2 출처별 조회 방식

| 출처 | 조회 알고리즘 | 완료 기준·미확인 사항 |
| --- | --- | --- |
| X 공지 검색 | 고정한 시간 구간+검색어로 조회하고 지원되는 다음 페이지를 이어 읽음 | 해당 구간의 끝 페이지와 저장까지 완료해야 성공 기준점 전진. 현재 실제 권한·시간/페이지 기능·쿼터 미확인 |
| 네이버/Google 노출 검색 | 검색어별 허용된 결과 페이지를 반복 읽고 원문 키 집합의 차이를 비교 | 시간순·전수 목록이 아니므로 '그 기간 전체 조회 완료'로 표시하지 않음. 실제 자동 조회 연결 미선정 |
| 발견한 공식 커뮤니티/공지 | 확인된 주소·지원 목록의 원문 ID/내용 지문을 비교 | 허용된 조회가 연결된 범위만 감시. 원문 하나 재조회가 다른 신규 공지까지 찾는 것은 아님 |
| 공식 일정/지정 피드 | 제공되는 항목 키·변경 버전·커서 또는 날짜 범위 비교 | 실제 제공 구조·접근 범위에 맞춤. 첫 데뷔와 다른 행사 구분 |

각 출처는 기간 검색·정렬·페이지·원문 조회·접근 가능 과거 범위를 기능 설정으로 선언한다. 지원이 확인되지 않은 기능을 공통으로 제공한다고 가정하지 않는다. 비활성/미연결 출처는 조회하지 않고 그 상태를 남긴다. 이번에 이 설정이나 연결을 구현하지 않았다.

## 3 X 검색어와 시간 구간

### 3.1 이름 대신 공지 표현을 검색

기존 검색 연결을 확장할 때 사용할 검색 논리다. 아래 연산자/따옴표의 실제 이용 가능 범위는 연결 단계에서 확인한다.

```text
Q_NEW:
(치지직 OR CHZZK)
AND (데뷔 OR "첫 방송" OR 첫방송 OR 신인버튜버)

Q_CHANGE:
(치지직 OR CHZZK)
AND (데뷔 OR "첫 방송" OR 첫방송)
AND (변경 OR 연기 OR 취소)
```

실제 검색식은 출처별 어댑터가 만든다. 플랫폼 관련 표현과 데뷔 관련 표현은 후보 발견 조건이지 버튜버·본인·첫 데뷔의 증명이 아니다. 두 검색식에 동시에 잡힌 공지는 원문 키로 한 번 처리한다. 명시적 새 날짜나 변경 표현이 있으면 변경/충돌 검토를 우선한다. 재게시물은 원문 연결 단서로 사용할 수 있으나 공식 근거로 승격하지 않는다.

주소만 있고 치지직 표현이 없는 게시물, 이미지에만 있는 글, 다른 표현의 공지는 누락될 수 있다. 채널 URL 검색·표현 확장은 해당 검색 기능을 확인한 뒤 새 검색어 버전으로 추가한다. 새 버전에 이전 검색어의 완료 시점을 그대로 복사하지 않는다.

### 3.2 조회 구간을 고정하고 일부 겹쳐 읽음

초기 설정안: 수집 시각 대비 반영 지연 5분, 중복 조회 24시간, 첫 조회 최대 7일. 이는 실제 API의 허용 범위·검색 반영 시간 보장이 아니다.

```text
조회 끝 = 현재 시각 - 반영 지연
첫 조회 시작 = max(조회 끝 - 초기 조회 기간, 출처가 허용하는 가장 이른 시각)
이후 조회 시작 = max(마지막 완료 시점 - 겹침 기간, 출처가 허용하는 가장 이른 시각)
```

검색어별로 시작/끝·검색어 버전·진행 커서를 고정한다. 미완료 구간이 있으면 그 작업부터 이어 읽는다. 현재 시각만 바꾸면서 첫 페이지를 계속 조회하지 않는다. 일일 예산에서 두 검색어를 순환 배분하고 한 검색어의 실패가 다른 검색어의 완료 기록을 막지 않게 한다.

마지막 완료 이후 출처의 접근 기간 밖으로 밀린 구간은 GAP으로 기록한다. 미완료 작업을 재개할 때도 접근 기간을 다시 검사하고, 구간이 만료됐으면 읽을 수 없는 범위를 GAP으로 남겨 해당 작업을 종료한다. 이후 새 작업은 현재 읽을 수 있는 하한부터 시작한다. 접근 가능한 범위는 계속 조회하되 그 공백까지 확인했다고 표시하지 않는다. 커서만 만료되고 구간은 읽을 수 있으면 같은 고정 구간을 다시 시작하고 원문 키로 중복 제거한다. 불안정한 정렬/페이지에서는 확인 범위를 부분으로 기록하며 전수 확인을 주장하지 않는다.

## 4 페이지 조회·저장 알고리즘

09시·15시·21시 KST, 검색어별 회당 최대 2페이지는 34번의 초기안이다. 기본 12요청/일·360요청/월, 검색 재시도 여유 최대 2요청/일·60요청/월을 별도로 둔다. 합계 420은 첫 X 검색 경로만의 가정이며 추가 원문/보강/다른 검색의 요청·가격이 아니다.

```text
조회_회차(현재시각):
  활성 출처를 순회한다
  출처가 미연결/중지 상태면 상태만 기록하고 건너뛴다
  출처별 실행 잠금을 얻는다; 이미 실행 중이면 중복 시작하지 않는다

  검색어를 순환 선택한다
    미완료 구간이 있으면 복원한다; 없으면 고정 구간을 만든다
    회차 페이지 상한과 일일 예산 안에서 반복한다
      요청 예산을 예약하고 현재 구간·커서로 한 페이지 조회한다
      권한 오류면 출처를 중지한다
      일시 오류면 제한 재시도 대상으로 남기고 이번 작업을 중단한다
      응답 구조가 잘못되면 실패로 기록한다; 0건 성공으로 바꾸지 않는다

      각 원문을 원문_처리 절차에 전달한다
      원문/후보 저장과 재처리 식별이 끝난 뒤에만 다음 커서를 기록한다
      끝 페이지면 고정 구간을 완료 처리하고 해당 검색어의 기준점을 전진한다
      상한/저장 실패면 미완료 구간을 보존하고 중단한다

  소스 상태·예산 사용·미처리 범위를 기록하고 잠금을 반환한다
```

요청 실패·타임아웃도 호출 예산에서 누락하지 않는다. 예약/실제 발행/응답 결과를 분리해 장애 시 과소 집계하지 않는다. 네트워크 응답을 기다리는 동안 DB 트랜잭션을 유지하지 않는다. 재시작 시 같은 페이지를 다시 처리해도 중복 후보가 생기지 않게 저장 키를 유일하게 한다.

## 5 원문에서 후보를 만드는 알고리즘

```text
원문_처리(원문):
  원문 키 = 출처 + 출처가 제공한 게시물/행사 ID
  ID가 없으면 출처별 규칙으로 정규 원문 주소를 식별한다
  같은 원문 키·같은 내용 지문이며 후보 처리가 완료됐으면 관측만 갱신하고 종료한다
  원문만 저장되고 후보 처리가 미완료라면 그 처리 지점부터 재개한다
  차단 원문/채널이면 재공개 후보를 만들지 않는다

  명시된 방송 채널 주소·원문 연결을 추출한다
  허용된 주소 규칙으로 채널 ID를 정규화한다
  날짜·행사 표현·활동명 후보를 해당 근거 구간과 함께 추출한다
  필요한 경우 기존 채널 조회로 공식 이름·소개·연결을 보강한다

  활동 종류와 누락/충돌을 판별한다
  기존 원문 관계·채널·행사를 대조한다
  신규 인물 제안 / 기존 인물 정보 보강 / 일정 변경 제안 / 관계 확인 필요로 나눈다
  값마다 출처를 연결해 새 후보 또는 새 후보 버전으로 저장한다

  검수 가능 범위와 재확인 사유를 계산한다
  원문·후보 버전·근거·검사 결과를 저장한다
  공개 DB는 변경하지 않는다
```

URL은 실제 출처 ID와 필요한 경로/인자를 보존한다. 모든 쿼리 인자를 지우는 식의 중복 제거를 하지 않는다. 허용한 단축 호스트·리다이렉트만 제한적으로 해석하고 관계없는 임의 주소를 무제한 조회하지 않는다. 인물명 유사성이나 X 표시 이름만으로 채널 소유 관계를 확정하지 않는다.

내용 지문은 허용된 원문 텍스트·명시 링크·제공되는 행사/첨부 식별 정보로 계산한다. 관측 시각·검색 순위는 제외해 재조회마다 변경으로 인식하지 않게 한다. 읽지 못한 이미지 내부의 수정까지 감지한다고 가정하지 않는다.

원문 저장과 후보 처리 상태를 구분한다. 처리 중 실패한 원문을 '이미 본 ID'라는 이유로 건너뛰지 않는다. 추출 작업은 원문 키·내용 지문·후보 버전을 고정하며, 처리 중 더 새 원문 버전이 들어오면 오래된 작업이 현재 후보를 덮어쓰지 못하게 한다. 실패 원문의 재처리 작업이 영속적으로 기록되지 않았다면 해당 페이지의 저장 완료/커서를 전진시키지 않는다.

## 6 추출·분류·대조 규칙

| 판단 | 알고리즘 규칙 |
| --- | --- |
| 출처 | 게시물 주소·작성자·발행일·확인일·원문 연결 저장. 검색 요약과 재게시물은 공식 원문의 대체 근거가 아님 |
| 누가 | 공지의 명시 활동명과 공식 채널 ID 연결. 이름만 있으면 채널 관계 확인 대기. 여러 인물/링크의 대응이 모호하면 검수 |
| 언제 | 명시된 날짜·시각·시간대를 분리. 누락 값을 임의 보완하지 않음. 상대 날짜는 발행 시각/시간대 근거가 명확할 때만 계산 |
| 어디서 | 명시된 플랫폼·방송 채널 주소. 공식 채널 조회는 존재 확인이며 최초 데뷔·본인 인증과 별개 |
| 행사 종류 | 첫 데뷔 주장·플랫폼 데뷔·재데뷔·모델 공개·복귀·변경/취소를 분리. 단순 '데뷔' 적중으로 최초 활동을 확정하지 않음 |
| 이미지에만 있는 정보 | 본문에 없는 날짜/이름을 만들어 채우지 않음. 미디어 정보 필요 사유로 보류. OCR/AI는 첫 필수 기능이 아님 |
| 버튜버 여부 | 본문/공식 소개의 명시 근거와 공식 연결을 확인. 낮은 팔로워·시청자·캐릭터 이미지·신입 표현만으로 확정하지 않음 |

같은 원문이 수정됐으면 새 지문과 후보 버전을 만든다. 다른 원문이 같은 사람을 언급했다고 새 인물로 만들지 않는다. 여러 공지의 행사 연결은 기존 원문 참조·플랫폼·채널·행사 근거로 제안하고, 시각 변경을 새 행사로 무조건 생성하지 않는다. 날짜가 같다는 이유만으로 행사 전체를 자동 병합하지 않는다.

새 공지의 일정과 기존 공개 일정이 다르면 공개 값을 직접 덮어쓰지 않고 차이·근거를 검수 대상으로 남긴다. 영구 차단·반려 범위는 재수집 때 보존하고, 보완 가능한 후보에 새 근거가 들어온 경우에만 새 버전의 재검수 제안을 만든다.

## 7 후보의 분기와 재조회

| 결과 | 조건 | 처리 |
| --- | --- | --- |
| 검수 대기: 인물+일정 | 인물/채널·공식 근거·일정/시간대·방송 주소가 갖춰지고 중대한 충돌이 없음 | 운영자 미리보기·승인 대상으로 전달. 자동 승인은 아님 |
| 검수 대기: 인물만 | 인물 소개의 최소 조건은 있으나 일정은 미정/불명확 | 인물 공개와 행사 공개 범위를 분리. 캘린더 자동 등록 금지 |
| 재확인 대기 | 채널 주소·미디어 날짜·공식 관계 등 근거 부족 | 하루 1회·최대 3회·7일 초기안 안에서 제한 재확인 |
| 관계/변경 검토 | 동일 인물·다중 행사·기존 값과 상충·취소 등 | 원문·기존/제안 값·사유를 함께 제시 |
| 보류·만료/반려 | 재확인 종료·명확한 무관 자료·운영 판단 | 이유 보존. 매 회차 동일 후보를 새 숙제로 재생성하지 않음 |

이미 공개한 활성 공지의 수정은 지원되는 원문 조회/공식 공지에서 별도로 재확인한다. 발행일이 오래된 게시물의 수정은 겹침 검색만으로 발견하지 못할 수 있다. 해당 출처가 원문/수정 조회를 제공하지 않으면 그 감시 한계를 표시하고 새 변경 공지 검색으로 보완한다.

공개 정보는 승인 버전과 대상 상태가 일치할 때만 34번 반영 공정을 실행한다. 새 추출 결과·재확인 결과가 과거 승인을 그대로 사용하지 못하게 한다.

## 8 동작 예시와 확인할 불변 조건

아래는 실제 검색 결과/실행 시험이 아닌 명세 검토 사례다.

| 입력 상황 | 기대 결과 |
| --- | --- |
| 처음 보는 공지에 활동명·정확한 일시·공식 채널이 있음 | 신규/기존 채널 대조 후 인물+일정 검수 대기. 공개 미변경 |
| 다음 회차에 같은 원문·같은 내용이 다시 등장 | 후보 중복 없음. 관측 상태만 갱신 |
| 같은 원문 또는 연결된 변경 공지에서 20시→21시 | 일정 변경 제안·근거·새 버전. 기존 공개 일정은 승인 전 유지 |
| 채널 없이 이름만 있거나 이미지에 날짜만 있음 | 재확인/관계 검토. 이름 검색으로 다른 사람을 자동 합치지 않음 |
| 2페이지 후에도 다음 페이지가 남음 | 부분 수집·구간/커서 보존. 완료 시점 전진 없음 |
| 첫 페이지는 성공, 다음 페이지는 실패 | 저장한 페이지는 유지·다음 작업 재개. 회차 전체 완료로 표시하지 않음 |
| 접근 가능한 과거 범위 밖으로 공백 발생 | GAP 기록. 해당 기간 확인 완료라고 보고하지 않음 |
| 검색 0건 정상 응답 / 인증 실패 / 미연결 | 정상 0건 / 중지·실패 / 미실행으로 각각 구분 |
| 승인한 후보가 이후 수정됨 | 기존 승인 감사 이력 보존·새 버전 재검수. 자동 공개 없음 |

불변 조건: 같은 원문/채널의 중복 인물 없음, 추출 값에 근거 연결, 조회 범위가 미완료면 완료 시점 전진 없음, 이름/날짜 추측 없음, 검색 실패를 0건으로 바꾸지 않음, 승인 없는 공개 변경 없음, 호출 상한 초과 무제한 재시도 없음.

관리자에는 검색어/출처별 마지막 완료·현재 구간·잘림/공백·호출 수, 신규 원문/중복/변경 후보, 4항목 확보·보류 이유·검수 대기 시간을 제공한다. 검색 정기 실행과 실제 새 인물 발견 성과를 별도로 판단한다.

## 9 구현 경계·기존 자산

현재 재사용 후보는 [보고 소스 연결](../backend/scripts/debut-investigation/debut-sources.cjs), [보고 실행기](../backend/scripts/investigate_debuts.cjs), [채널 주소 규칙](../shared/portal.ts), [공개 검토 기준](../shared/contentReview.ts)다. 현재 X 연결 코드는 검색 묶음별 한 페이지·최대 20건과 일부 잘림 표시를 제공하지만, 본 명세의 고정 구간/커서 재개·후보 DB·승인 연결이 완료된 것은 아니다. 키/권한·요금·실제 응답도 새로 확인하지 않았다.

이번에 만든 것은 조회 알고리즘 명세와 의사코드다. 코드 구현·API 호출·자동화 예약 등록·실제 후보 저장·서비스/DB 변경·배포는 하지 않았다. 비용은 검색 요청뿐 아니라 반환 게시물·후보 보강·원문 재조회·DB·CPU·제공자 과금 단위로 산정해야 하며, 월 420회만으로 실제 월 금액을 확정하지 않는다.

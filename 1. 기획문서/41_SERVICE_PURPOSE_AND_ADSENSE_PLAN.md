# 41. 서비스를 만든 이유와 애드센스 재검토 계획

- 작성: 2026-11-24
- 배경: 애드센스 검토 결과 "가치가 별로 없는 콘텐츠"로 거절
- 이 문서의 목적: ① 서비스를 왜 만들었는지 다시 적고, ② 거절 원인을 그 목적에 비춰 보고, ③ **바로 고칠 수 있는 것**과 **시간을 들여 키워야 하는 것**을 나눈다.

---

## 1. 시작한 계기

VDébut은 두 가지 질문에서 시작했다.

| # | 누가 | 궁금한 것 |
|---|---|---|
| 1 | 시청자·팬 | "새로 나온 버튜버가 누가 있지? 언제, 어디서 첫 방송을 하지?" |
| 2 | 신입·소규모(하꼬) 스트리머 | "언제, 어떤 게임으로 방송해야 하지? 이런 정보는 어디서 구하지?" |

2번은 회사에 막 들어온 신입과 같다. 일을 어떻게 시작해야 할지 알려 주는 사람이 없다. 남들이 언제, 무엇을 방송하고 어디가 덜 붐비는지 보여 주면, 신입 스트리머가 **자기 방송 스타일을 잡는 데 조금이라도 도움**이 된다.

## 2. 목적별 지금 상태

| 목적 | 맡는 화면 | 지금 상태 |
|---|---|---|
| 1. 새 버튜버 찾기 | 데뷔 캘린더(홈), 버튜버 DB, 버튜버 상세 | 일정·소개는 갖춰짐. 다만 상세 312개 중 대부분이 등록 정보 몇 줄뿐이다 |
| 2. 신입 방송 전략 | 방송 통계(전체·게임·태그), 집계 기준 | 숫자는 모임(치지직 상위 100 + 등록 버튜버 직접 기록). 하지만 신입이 바로 쓸 **해석**(어느 시간·게임이 덜 붐비는지, 신입은 무엇을 많이 하는지)이 화면과 글로 정리돼 있지 않다. 게임·태그 페이지는 검색 제외 상태다 |

**정리**: 1번 목적은 "목록"은 있지만 "읽을거리"가 없다. 2번 목적은 이 서비스만의 고유 가치인데, 아직 숫자 나열에 머물러 있다.

## 3. 거절 원인 점검 (2026-11-24, 사이트맵 342개 주소를 로봇 기준으로 확인)

| 확인 항목 | 결과 |
|---|---|
| 사이트맵 구성 | 342개 중 312개(91%)가 버튜버 상세 |
| 상세 페이지 글 분량(메뉴 포함) | 중간값 310자, 300자 미만 142개, 500자 미만 287개 |
| 상세 페이지 검색 허용 | 312개 전부 허용 (얇은 페이지 기준이 "소개 30자 미만이면서 태그도 없음"이라 거의 걸리지 않음) |
| 사람이 직접 쓴 소개 100자 이상 | 74명 (200자 이상 28명) |
| 같은 틀 문장 반복 | "최근 #일 동안 #번…" 160개, "평균 시청자는 #명…" 143개, "「카테고리 없음」(#%)" 92개 |

구글 기준으로 보면 "등록 정보를 틀에 끼워 자동으로 만든 얇은 페이지가 대부분인 사이트"로 읽힌다. 이게 거절 사유의 핵심이다.

## 4. 바로 고칠 수 있는 것 (코드, 며칠 안)

목표: 검색에 내보내는 페이지를 **내용이 있는 것만** 남기고, 남은 페이지의 품질을 올린다.

| # | 할 일 | 기대 효과 |
|---|---|---|
| A1 | 상세 페이지 검색 허용 기준 상향: 직접 쓴 소개 100자 이상, 또는 소개 50자 이상 + 최근 30일 방송 5회 이상. 기준 미달은 페이지는 두고 검색 제외 + 사이트맵 제외 | 상세 312개 → 약 80개 |
| A2 | 입력 화면(/upload, /creators/register) 검색 제외 + 사이트맵 제외 | 얇은 페이지 6개 제거 |
| A3 | 상세 첫 HTML 문장 정리: "카테고리 없음" 문장 삭제, 반복 안내 문구("소개와 일정 확인하기" 등) 정리, 방송 패턴(평일·주말, 쉬는 요일)을 문장으로 추가 | 남은 페이지가 서로 다른 내용을 갖게 됨 |
| A4 | 집계 기준·가이드 페이지에서 상세·통계로 이어지는 내부 링크 정리 | 로봇이 좋은 페이지를 먼저 찾음 |

A1~A4는 운영자 결정만 있으면 바로 개발할 수 있다. 검색 허용 기준 숫자만 확정하면 된다.

## 5. 개선이 필요한 것 (기획·데이터·개발, 몇 주)

### 방향: 글이 아니라 "데이터의 깊이"로 가치를 보여 준다

- 가장 큰 참고 사이트는 **소프트뷰어**와 **치지직 방송 리더보드**다. 두 곳 모두 개인이 쓴 글이 없다.
- 이런 사이트의 가치는 글이 아니라 **다른 곳에서 볼 수 없는 데이터를 쌓아 보여 주는 도구**라는 점이다. VDébut도 같은 종류의 사이트이므로 같은 방식으로 간다.
- 참고 사이트의 실제 화면과 광고 사용 여부는 이번 작업 환경에서 접속이 막혀 직접 확인하지 못했다. 운영자 확인을 기준으로 한다.

### VDébut과 참고 사이트의 차이

| | 참고 사이트(데이터 도구형) | 지금 VDébut |
|---|---|---|
| 검색에 내보내는 페이지 | 순위·게임·스트리머별로 **숫자가 가득 찬 페이지** | 검색 허용 페이지의 91%가 등록 정보 몇 줄뿐인 상세 |
| 데이터 페이지 | 검색 허용 | 방송 통계 3개만 허용, 게임·태그 페이지는 검색 제외 |
| 쌓이는 기록 | 날마다 쌓이는 순위·기록(오래 운영할수록 가치가 커짐) | 기록은 쌓이고 있지만, 지난 기록을 보여 주는 페이지가 없음 |

정리하면 VDébut은 데이터를 모으고 있지만, **검색에 보여 주는 페이지는 데이터가 아니라 등록 정보**다. 순서를 바꿔야 한다.

### 할 일

| # | 할 일 | 목적 | 비고 |
|---|---|---|---|
| B1 | **게임 페이지를 신입용 데이터 페이지로 키우고 검색 허용**: 게임별 시간대 붐빔(경쟁도), 덜 붐비는 시간, 신입 버튜버가 하는 비율, 30일 추이 | 2 | 이미 있는 게임 페이지를 강화. 데이터가 충분한 게임만 검색 허용 |
| B2 | **순위 페이지(리더보드)**: 일간·주간·월간 치지직 순위, 신입 버튜버 순위(데뷔 90일 이내) | 1·2 | 날마다 바뀌는 페이지 = 꾸준히 운영되는 사이트라는 신호 |
| B3 | **지난 기록 보기**: 날짜별·주별 순위 기록 주소(예: /analytics/daily/2026-11-24) | 1·2 | 일일 요약 표(0066)를 활용. 운영 기간만큼 페이지가 늘어남 |
| B4 | **데뷔 기록 페이지**: 월별 데뷔 목록(예: 2026년 11월 데뷔 버튜버)과 데뷔 첫 주 성적 | 1 | 캘린더 데이터를 검색용 목록으로 |
| B5 | 버튜버 DB 목록 + 랭킹 띠(40번 문서, F) | 1·2 | 이미 계획됨 |
| B6 | (선택) 이용 가이드 1편: 방송 통계를 신입이 어떻게 읽으면 되는지 | 2 | 글은 이 한 편만. 집계 기준 페이지와 연결 |

원칙:
- 개인 글을 늘리지 않는다. **데이터 페이지가 스스로 설명하도록** 숫자 옆에 한 줄 해석(예: "이 게임은 오후 2~5시가 가장 덜 붐벼요")을 단다.
- 해석 문장은 정해진 규칙으로 만들되, 같은 문장이 수백 페이지에 반복되지 않도록 페이지마다 다른 숫자·결론이 나오는 것만 검색에 내보낸다.
- 숫자에는 출처와 기준(집계 기준 페이지)을 함께 단다.
- 평가 표현(잘함·못함)은 쓰지 않는다. 신입이 "자기 선택"을 하도록 정보를 준다.

## 6. 재검토 요청 순서

1. A1~A4 배포
2. B1(게임 페이지)·B2(순위 페이지) 배포 후 2주 이상 데이터가 쌓이는지 확인
3. Search Console에서 사이트맵 다시 제출, 검색 제외·새 페이지 색인 반영 확인(2~4주)
4. 애드센스 재검토 요청

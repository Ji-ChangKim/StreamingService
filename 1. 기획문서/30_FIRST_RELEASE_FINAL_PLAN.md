## 1 첫 출시의 목적

**사용자가 직접 등록하기 전부터 우리가 신인을 찾아 정보를 채우고, 공개된 소개를 계속 유지할 수 있게 한다.** 확인된 정보가 쌓이도록 기존 조사·등록·도감·상세를 연결한다. 신규 재미 기능이나 모든 플랫폼의 전수 발굴이 첫 목표가 아니다.

첫 집중 대상은 한국 치지직·SOOP의 데뷔 준비·최근 활동 시작 버튜버다. 외부 사이트에 공개된 모든 사람을 자동 등록하거나 첫 데뷔를 모두 입증한다고 표현하지 않는다. 기존 다른 국가/플랫폼 데이터·주소·관심 목록은 보존한다.

## 2 첫 출시의 핵심 기능 3개

1. **신규 후보 자동 발굴:** 기존 조사/CSV 재사용, 허용된 치지직 방송 목록·채널 키워드 검색 및 다른 목록 소스의 정기 확인. 채널 정규화·중복·변경·실패·누락 범위 기록.
2. **정보 자동 보강·조건부 공개:** 공식 채널의 제공 정보·확인된 소개·입문/최근 자료를 공통 템플릿으로 연결. 정형 조건 충족은 자동 공개, 충돌은 예외 검토.
3. **정보 지속 갱신·예외 관리:** 변경분·근거·보호값·소스 상태·작업 상한·삭제/철회/복구를 관리하고 기존 도감·상세에 정상 공개 데이터를 제공.

기존 보고 코드가 이미 2·3을 제공한다고 간주하지 않는다. 첫 출시 개발에 안전한 반영 경로를 포함한다.

## 3 포함·제외 범위

| 영역 | 첫 출시 포함 |
| --- | --- |
| 발굴 입력 | 기존 정본/보고·공개 시트·이용 가능한 공식 일정, 치지직 방송 목록/채널 검색의 제한된 페이지 탐색. 처음부터 다수의 사이트별 파서 구축은 하지 않음 |
| 식별·근거 | 인물/채널·원문 키·후보·항목별 근거·잠금·버전·공개/보류·재수집 차단 |
| 보강 | 기존 플랫폼 이름/이미지 참조/소개 조회와 미디어 연결, 확인된 필드로 소개 템플릿 구성 |
| 자동 반영 | REPORT/DRAFT/AUTO 분리, 허용 출처/항목만 자동 공개, 기존 검토·중복·직전 상태 비교·반영 이력·복구 |
| 갱신·운영 | 단일 예약 실행·커서·동시성 잠금·주기·상한·백오프·소스 중지·예외/표본 확인 |
| 화면 | 기존 도감/상세에 소개·공식 링크·대표/최근 자료·근거와 일정 연결. 기존 등록·제보·관심·공유 유지 |
| 일정 | 인물과 별도 행사로 관리. 정확한 날짜/시간대/시각이 있는 지원 일정만 기존 캘린더 연결 |

후속: 지정 공식 공지 연결 확대, 자발 등록/제보의 편의, 공통 활동·관심 변화, 근거 있는 도감 추천. '오늘의 발견' 화면을 이번 첫 출시 필수에서 제외한다.

제외: 유료 X/검색 계약·SSAPI·채팅 분석·워드클라우드·AI 취향 추천·주식/예측/카드깡·OBS·외주 아트·신규 계정/소유권 관리 화면·기기 간 관심 동기화·푸시/문자. 메인 하이라이트·실제 캘린더·PortalStage·PlatformMiniSpotlight·Header/Footer 개편도 제외한다.

## 4 실제로 반복돼야 하는 흐름

1. 허용된 목록/공지에서 새 채널 단서를 발견하고 원문·확인 시각을 남긴다.
2. 공개·대기·보류·별칭·차단 전체에서 중복을 확인한다. 같은 사람의 새 행사는 기존 인물과 연결한다.
3. 채널 정보·확인된 소개·자료를 자동 조회/정리한다. 모르는 소속·국가·시각은 미확인으로 둔다.
4. 출처·채널 연결·최소 소개·공개 검토·중복/충돌 조건을 충족하면 허용된 모드에서 자동 공개한다. 나머지는 사유가 있는 보완/검토 대상으로 남긴다.
5. 팬은 기존 도감·상세에서 누구인지·무엇을 하는지·공식 콘텐츠를 어디서 볼지 확인한다.
6. 이후 허용된 주기로 변경만 반영한다. 수동 확정 값과 충돌하면 제안으로 남기고 조회 실패만으로 기존 정상 정보를 지우지 않는다.
7. 본인/팬의 기존 등록·정정이 들어오면 같은 인물·근거·변경 구조로 연결한다.

인물 소개가 가능해도 일정이 미정이면 캘린더 등록과 분리한다. 작품이 부족하면 최근 자료/공식 채널을 안내하고 대표작이나 취향 태그를 만들어 채우지 않는다.

## 5 개발 순서

D0 현황·공개 기준 → D1 인물/채널/후보/근거 → D2 치지직 신규 탐색·수집 연결 → D3 자동 보강 → D4 공개 판정·반영·복구 → D5 갱신·예외·상한 → D6 기존 도감/상세 노출.

기존 보고 경로는 기본 보고 전용으로 유지하며 새 반영기는 별도 허용 모드로 만든다. 실제 자동 공개는 기존 공개 검토와 D4/D5의 안전 장치가 갖춰진 이후다. 출처별 최초 병행 검토 후 정형 항목부터 자동화한다. 개발/소스 확인을 실행하기 전까지 어느 경로도 동작 완료로 표시하지 않는다.

## 6 출시 완료 기준

| 기준 | 확인할 결과 |
| --- | --- |
| 자동 발굴 성립 | 허용된 치지직 방송 목록/채널 검색을 포함한 발견 경로에서 이전에 없던 채널 후보를 만들 수 있음. 공식 일정·시트에 없는 미등록 사례도 확인. 검색/페이지 미지원 범위는 제외·기록. CSV 읽기나 알려진 채널 갱신만으로 자동 발굴 완료라 하지 않음 |
| 공식 근거·입문 정보 | 공개된 최소 소개마다 채널·근거·확인 시각이 연결되고 보여 줄 사실 소개/공식 이동이 있음. 대표/최근 자료 구분 |
| 데이터의 실질 가치 | 실체 확인·입문 가능·지속 확인을 구분해 자료 보유율 집계. 이름/채널만 채운 페이지 증가를 입문 정보 확보 성과로 계산하지 않음 |
| 조건부 자동 공개 | 허용된 정형 사례가 매건 수동 입력 없이 처리되고, 불명확 사례는 이유와 함께 보류. 자동 처리 출처/항목·제한을 추적 가능 |
| 중복·복구 | 같은 자료 재처리·재시도·동시 실행·같은 이름 다른 채널·직전 수동 수정에서 오병합/덮어쓰기 방지. 실패 후 복구 가능 |
| 날짜·행사 | 일정 미정이 가짜 시각으로 바뀌지 않고 최초 데뷔/플랫폼 데뷔/이적/모델 공개를 혼합하지 않음 |
| 지속성·철회 | 무변화·변경·실패·삭제/철회·권한 실패·부분 수집·상한을 구분하고 차단된 항목이 다시 공개되지 않음 |
| 화면·성능 | 기존 관심·공유·등록·캘린더가 유지되고 상세→메인 복귀 시 기존 구성 동일. 수집 작업이 화면 진입마다 실행되지 않음 |
| 비용·운영 | 실제 호출·DB/CPU·예외 시간·최소 정보 보유율·현재 플랜 잔여량/청구 기준선 확인 |

위는 향후 출시 확인 기준이다. 현재 기능 시험·실제 자동 발굴·외부 정책 검증을 수행한 결과가 아니다. 특정 신규 인원·자동화율·전수 포착·유입 증가를 출시 보장으로 걸지 않는다. 접근 가능한 목록 소스가 없으면 보고/초안 기능까지만 성립하며 자동 발굴 출시라고 부르지 않는다.

## 7 비용과 이후 확장

인건비를 제외하고 기존 Worker·D1·등록/조회/관리자 기능을 우선 재사용한다. 초기 100개 관리 시나리오는 수집 약 14,800회·DB 읽기 112,512행·쓰기 35,384행/월, 신규 저장 예산 0.05~0.15GB다. 호출/행/저장 모두 가정이며 기존 전체 서비스 사용량과 별도로 합산한다.

추가 정액 서비스는 필수 도입하지 않는다. 기존 플랜 잔여량이 충분하면 신기능 순증 0원 가능성이 있으나 현재 청구를 확인하지 않았으므로 확정하지 않는다. 기존 초기 순증 월 1만원·확장 월 3만원은 검토 기준선이며 추가 탐색을 수용 가능한지 미확인이다. 공식 가격/견적이 아니다. 과금 산식·입력·제외 항목은 [24번](./24_ADVANCEMENT_BACKLOG_AND_COST.md)을 따른다.

다음 확장은 확보된 인물의 정보 깊이·신선도·예외 부담이 유지되는지 보고 정한다. 사용자가 늘면 본인 등록·팬 제보의 비중이 커질 수 있으므로 지금부터 동일한 기본 구조를 사용한다. 자발 등록이 늘어나도 누락 발굴·갱신은 계속 자동화한다.

치지직 탐색은 월 재시도 전 5,040회 상한 가정이다. 방송 전 준비생의 외부 홍보 검색은 허용 연결이 있을 때만 자동화하고 미연결이면 직접 공식 링크를 조사한다. 신규 발견과 신인 확정·전수 포착을 동일시하지 않는다.

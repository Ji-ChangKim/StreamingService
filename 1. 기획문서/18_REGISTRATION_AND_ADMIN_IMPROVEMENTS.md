## 1. 작업 범위와 결과

[PRD 점검표](./17_PRD_GAP_CHECKLIST.md)의 권장 순서 1~3번에 대한 사용자 ‘진행’ 요청을 반영했다. 기존 URL → 프로필 → 일정의 세 구역과 브랜드 자산을 유지한다. 내 등록 관리·소유권 신청 화면을 추가하지 않는다.

| 항목 | 실제 동작 | 결과 |
| --- | --- | --- |
| 등록 국가·시간대 | 한국/서울, 일본/도쿄, 미국/LA·뉴욕 선택 후 현지 일시 입력 | 서버에서 UTC로 검증·변환해 저장. 미국 서머타임의 존재하지 않는 시각 거절 |
| 신청자 구분 | 본인 직접 신청·소속사/대리·팬 제보를 선택 | 관리자 검토 정보에 전달. 본인 인증으로 간주하지 않으며 승인 후에도 미인증 상태 유지 |
| 소개 필수 | 짧은 소개를 확인·수정하고 제출 | 화면·서버에서 빈 소개를 거절 |
| 제출 재시도 | 같은 내용의 재전송에 같은 제출 키 사용 | 응답 유실·새로고침 후에도 기존 접수로 성공 처리. 새 비공개 조회 키는 재노출하지 않음 |
| 채널 중복 | 플랫폼 채널 식별자로 공개·검토 대기 대상 비교 | SOOP `.com`·`.co.kr`·구 afreecatv 주소, CHZZK 채널/라이브 주소, 추적 인자 차이를 대조. 새 접수·공개 보조 테이블의 고유 키로 경쟁 요청 방어 |
| 관리자 정정 | 관리자 로그인 → 공개 정보 수정 → 대상 검색 → 소개·일정·국가·시간대·공지 링크 수정 → 사유 작성·저장 | 기존 소개 URL·공식 채널·원래 등록 출처·인증 상태 유지. 기존 테이블을 덮어쓰지 않고 공개 프로필에 수정본을 적용 |
| 이력·복구 | 변경 전후·사유·관리 세션 해시 기록. 이력의 ‘변경 전 내용 불러오기’ 후 다시 저장 | 즉시 복구하지 않고 초안을 확인한 뒤 저장. 복구도 새 변경 이력으로 남음 |
| 동시 수정 | 목록을 열었을 때의 프로필 버전과 저장 직전/DB 갱신 조건 대조 | 다른 운영자가 먼저 수정했다면 409 응답으로 덮어쓰기 차단 |

브라우저 저장소에는 제출 내용의 해시와 난수 키만 임시 보관하며 소개 원문·연락처를 남기지 않는다. 저장소가 제한되면 현재 화면의 참조 값을 사용한다. 공개 정보와 이력 조회·저장은 기존 서버 관리자 세션 인증을 요구한다.

## 2. 변경한 파일

- `shared/portal.ts`: 신청 역할·한일미 국가/시간대 정의, 플랫폼 채널 식별 함수.
- `shared/portalTranslations.ts`: 새 등록·운영 문구의 한국어·일본어·영어 대응.
- `frontend/src/portal/PortalRegistrationForm.tsx`: 세 구역 안에 신청 역할과 국가·시간대 입력, 소개 필수 검증, KST 고정 안내 제거.
- `RegistrationRegionFields.tsx`: 등록·운영 공통 국가/시간대 선택.
- `registrationSubmission.ts`, `RequestPages.tsx`: 제출 키 재사용·서버 접수 성공 후 완료 안내.
- `PortalAdmin.tsx`, `PortalProfileManager.tsx`: 관리자 정정 진입·검색·편집·변경 사유·이력·복구 초안.
- `portal.css`: 새 선택 입력의 기존 필드 규격과 반응형 폭 유지.
- `backend/src/services/portalService.ts`: 등록 검증, 중복 접수/승인 방어, 관리자 조회·수정·비공개 이력 API, 삭제 시 채널 고유 키 정리.
- `backend/migrations/0037_portal_submission_and_history.sql`: 제출 키·대기 채널·공개 채널·변경 이력 보조 테이블과 인덱스.
- `backend/tests/portal.test.cjs`, `liveRelease.test.cjs`: 실제 Hono·SQL 기반 등록/권한/정정·기존 공개 데이터 보존 검증.
- `frontend/tests/registrationSubmission.test.cjs`: 응답 유실·새로고침 재시도와 원문 미보관 검증.

## 3. 검증 결과

- 백엔드 `portal.test.cjs` + `liveRelease.test.cjs` **13개 통과**. 국가·역할·빈 소개·DST, 제출 재시도·URL 별칭, 관리자 정정·이력·복구·버전 충돌·비인증 거절 포함.
- 프론트엔드 기존 번역·등록 조회 **7개**, 신규 재시도 **1개 통과**.
- 백엔드 TypeScript 검사, 프론트엔드 프로덕션 빌드 통과. 메인 포털 본체 36.14KB, 관리자 화면 10.76KB이며 관리자 코드는 해당 화면에서만 읽는다.
- 실제 UI에서는 로컬 메모리 DB·로컬 전용 테스트 계정으로 관리자 로그인 → 수정 저장 → 이력 확인 → 이전 내용 복구 → 공개 페이지 원문 복원까지 확인했다. 테스트 계정은 원격 DB에 만들지 않았다.
- 개발 실제 등록 페이지에서 세 구역, 신청 역할·미국 동부 선택, 일본어/영어 전환 후 선택값 유지 확인.
- PC 1280px에서 문서 폭 1274px, 모바일 360px에서 문서 폭 354px. 가로 넘침 없음.
- 개발 공개 API 309개, LIVE 공개 API 346개 유지. 개발 관리자 프로필 API는 비인증 요청에 401.
- 개발 D1에는 0037 파일만 명시 실행했다. 기존 마이그레이션 재실행·기존 프로필 갱신 없음. 새 대기 채널/변경 이력은 모두 0건으로 원격 테스트 데이터 미생성 확인.
- 개발 배포는 Wrangler 4로 수행했다. 기존 Wrangler 3의 D1 접근 오류는 버전 4로 해결했으며 프로젝트 의존성 파일을 바꾸지 않았다.

## 4. 적용 범위와 남은 제한

이번 변경의 적용 대상은 **dev.vdebut.live**다. LIVE는 기존 버전 `560522d1-f044-4e3b-9965-38497319f7a7`을 유지하며 운영 D1에는 0037을 실행하지 않았다. 이후 LIVE 반영 시 먼저 운영 DB에 0037을 명시 추가하고 동일 빌드를 배포해야 한다.

- YouTube의 `@handle`과 별도 `/channel/ID`가 동일 계정인지 외부 확인 없이 자동 병합하지 않는다. 해당 표현 간 중복은 관리자 검토가 필요하다. 영상 URL 대신 채널 URL을 받는다.
- 기존 승인 요청은 변경하지 않는다. 새 등록 필수값을 과거 데이터에 추정해서 채우지 않는다.
- 미국의 서머타임 종료 시 반복되는 시각의 오프셋을 사용자가 명시 선택하는 기능은 없다. 현 변환 규칙을 사용하며 별도 시간대 고도화 과제로 남긴다.
- SOOP 개별 페이지는 기존 요청대로 방송국 API의 현재 소개를 우선 표시한다. 관리자가 수정하는 저장 소개는 API 소개가 없을 때 표시되며 목록·SEO의 저장 소개에도 쓰인다.
- 새 API·운영 화면의 실제 원격 관리자 저장 및 실접수는 아직 수행하지 않았다. 수정·복구의 전체 동작은 원격 데이터와 분리한 실제 코드·SQL·브라우저 환경에서 확인했다.
- 다음 PRD 과제는 새 포털 프로필의 통계 역방향 연결, 특징·언어·대표 콘텐츠, 일정 변경·취소 표시, 성장 계측이다.

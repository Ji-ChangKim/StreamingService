## 1 결론·현재 문제·출시 범위

**먼저 데뷔 공지를 찾고, 확인된 정보를 기존 도감·상세에 쌓는다.** 초기에는 우리가 정보를 채우고 이후 본인 등록·팬 제보도 같은 인물·근거·변경 구조로 받는다. 서비스 가치는 신뢰할 수 있는 정보로 신인을 발견하고 활동을 계속 알아가는 데 있다.

| 현재 문제 | 업데이트 방향 |
| --- | --- |
| 신규 발굴과 데이터가 부족함. 채널 조회는 발견한 사람의 보강 수단임 | 이름을 몰라도 검색할 수 있는 데뷔 공지에서 출처·누가·언제·어디서를 확보 |
| 현재 상세의 추천 영상은 활동 중인 인물의 최근 영상 중심 | 소개·대표 자료·최근 자료를 구분하고 공식 채널·일정·원문 연결 |
| 조사·공개·변경 처리의 연결과 항목별 근거 관리가 약함 | 후보·인물·행사·출처·보호값을 연결해 반복 갱신 |

첫 출시: **공지 후보 수집·판정 → 기본 소개 보강·공개/보류 → 기존 도감·상세 노출과 변경 반영**. 기존 관심 저장·등록·제보는 유지한다. 새 추천 화면·게임·채팅 분석·새 회원/소유권 관리 화면은 첫 필수 범위에서 제외한다.

**아직 미해결:** X·웹 검색을 지속 조회할 접근 범위·쿼터·비용과 실제 발견 성과. 자동 발굴이 이미 확보됐다고 보고하지 않는다. 채널 전체 조회나 인기순 목록 확장을 핵심 발굴 해법으로 확정하지 않는다.

## 2 어디서 무엇을 조사하고 어떻게 자동화할 것인가

아래는 조사 대상과 검색안이며 이번에 실제 검색한 결과가 아니다.

| 출처 | 검색·도달 방법 | 확보할 내용 |
| --- | --- | --- |
| X 공개 게시물 | 치지직+버튜버+데뷔, 버추얼+첫 방송 등 검색 | 작성자·원문·활동명·예정 일시·방송 링크. 본인/공식 계정 관계 확인 |
| 네이버·Google 웹 검색 | site:chzzk.naver.com 데뷔 / 첫 방송 버튜버 | 검색에 노출된 공지 원문과 채널 주소. 검색 요약만으로 확정하지 않음 |
| 발견한 본인 채널의 치지직 커뮤니티 | X·검색에서 얻은 공식 채널/게시물로 이동 | 정확한 일정·공식 방송 주소·변경/연기/취소. 전체 커뮤니티 검색을 전제하지 않음 |
| SOOP 공식 버추얼 일정·공식 소속사 공지 | 지정한 공개 일정/공지의 새 항목 비교 | 인물·행사·일정·공식 연결. 출처별 허용된 수집 방식만 연결 |

조사 기록의 필수 4항목은 **출처(원문·작성자·확인 시각) / 누가(활동명·채널 식별) / 언제(일시·시간대·확정/미정) / 어디서(플랫폼·방송 주소)**다. 공지 발행일과 데뷔일은 구분한다. 재데뷔·이적·모델 공개를 최초 데뷔로 합치지 않는다.

초기 운영은 자동 검사 후 운영자 최종 승인을 거치며, 승인된 내용의 반영·공개 확인을 자동 처리한다. 세부 상태·주기·실패 대응은 34번을 따른다.

자동: 검색/지정 출처 반복 조회 → 새 공지·변경 추출 → 4항목 정리 → 채널·행사 중복 대조 → 조건 충족 공개/보류 → 재확인. 기존 보고 전용 조사·채널 조회·정정을 재사용하되 자동 반영은 별도 개발 대상이다.

직접: 첫 출처·검색어·공개 기준 설정, 공식 작성자-채널 연결과 충돌/동일 인물 판단, 표본·삭제 요청·소스 장애 대응. 부족한 후보는 제한된 자동 재확인 후 보류/만료하며 매건 운영자에게 전수 조사 의무를 넘기지 않는다.

X 검색 연결 코드는 있으나 현재 인증·권한·운영 성공은 미확인이다. 웹 검색 정기 연결과 치지직 커뮤니티 본문 수집도 아직 확보된 기능이 아니다. 허용된 검색/API 연결이 없으면 그 출처는 직접 조사로 남으므로 자동 운영 범위에 포함했다고 표시하지 않는다.

## 3 화면 계획과 이를 뒷받침할 기술

| 화면·영역 | 바꿀 내용 | 필요한 데이터/기술 |
| --- | --- | --- |
| 도감 목록 | 누구인지·확인된 데뷔 일정·플랫폼을 빠르게 비교 | 채택된 소개 요약·일정 상태·페이지 조회 |
| 상세 상단 | 한 줄 소개·공식 채널·예정 일정·관심 저장 | 같은 인물 ID와 공식 채널·확정/미정 일정 |
| 상세 본문 | 소개/대표 자료와 최근 영상 구분, 소식의 날짜·원문·변경 연결 | 미디어 역할·행사 이력·항목별 근거·발행/확인일 |
| 관심 목록 | 기존 저장 유지. 확보한 일정 변경·최근 자료를 기본형으로 연결 | 공통 활동/일정과 기기 관심 연결. 확장 피드는 후속 |
| 기존 관리자 | 후보·근거·누락·변경 전후·보류 이유를 모아 확인 | 출처별 실행 상태·예외 목록·중지·반영/복구 기록 |

기술 구조는 **공지/출처 → 후보·인물/채널 → 행사·근거·채택 → 공개 데이터 → 도감/상세/관심**이다. 인물과 행사를 분리해 시각이 미정이어도 인물 후보를 보존한다. 사람이 확정한 값은 자동 수집이 덮어쓰지 않게 보호한다.

수집은 화면 밖에서 실행하고 기존 Worker·D1·프로필·미디어·관리자 기능을 우선 재사용한다. 화면은 마지막 정상 공개 데이터·캐시를 읽는다. 변경분만 저장하고 영상/이미지 원본 대량 복제·방문별 AI 호출·수작업 아트 제작을 필수로 넣지 않는다.

메인 상단 하이라이트·실제 캘린더·CalendarPage의 PortalStage 연결·공통 Header/Footer는 기존 구성·디자인·동작을 유지한다. 정확한 지원 일정만 기존 캘린더로 연결하며 새 시안으로 교체하지 않는다. 상세/목록 스타일은 해당 본문에만 적용한다.

## 4 개발 순서·직접 할 일·비용·성과

| 순서 | 담당 제안·할 일 | 완료 기준 |
| --- | --- | --- |
| 0 입력 원천 정리 | 서비스 담당자+Codex: 검색/공지 경로·권한·쿼터·요금·기존 필드 대응 확인 | 공지의 4항목과 자동/직접 처리 범위를 실제 입력으로 설명 가능. 현재 외부 확인 미실행 |
| 1 수집·식별 기반 | 공동 개발: 출처·원문 키·후보·채널/행사 중복·실행 상태 | 같은 공지 재입력 중복 없음. 실패·신규 없음·부분 수집 구분 |
| 2 보강·공개·정정 | 공동 개발: 공식 채널·자료·4항목 보강, 공개/보류·보호값·복구 | 임의 값 보완 없음. 충돌 보류·정정·취소/삭제 처리 |
| 3 화면 연결 | 공동 개발: 목록·상세·기존 관심의 기본 정보 연결 | 소개와 공식 콘텐츠/일정 확인 가능. 기존 메인/공통 화면 보존 |
| 4 지속 운영 | 자동 갱신+담당자의 예외/표본 판단 | 변경 추적·재확인 상한·소스 중지·노후 정보·실제 비용 확인 |

현재 월 실비는 **미확정**이다. 인건비는 제외하고 아래 실제 지출 항목을 확인해야 한다.

| 비용 | 현재 계획·미확인 사항 |
| --- | --- |
| 서버·DB | 기존 환경 재사용. 공유 잔여량·추가 읽기/쓰기·CPU·로그/백업 초과료는 확인 전 |
| X·웹 검색·원문 조회 | 접근 권한·API 이용료·검색/본문 쿼터 미확정. 무료·무제한 자동화를 전제하지 않음 |
| 신규 부가 서비스 | SSAPI·채팅 서버·벡터 DB·외부 AI·외주 아트는 첫 필수 계약에서 제외 |

**이전 월 1만원/3만원과 인기 목록 탐색 기반 호출량은 이번 데뷔 공지 수집안의 견적으로 사용하지 않는다.** 실제 비용은 기존 기본료+필요 플랜 차액+공유 한도 초과료+채택한 검색/API 요금으로 산정한다. 검색 원천·페이지/기간·새 후보량이 정해지기 전 숫자를 확정하지 않는다.

성과는 유효 데뷔 공지·4항목 확보율·입문 자료 보유율·정보 최신성·예외 처리 시간·순증 비용으로 판단한다. 이름/채널만 늘어난 페이지 수나 가상의 자동화율을 성공으로 보고하지 않는다. 장기적으로 본인과 팬이 같은 소개를 보완하되 자동 발굴·갱신은 유지한다.

## 1. 구현 기준

슬로건은 **버튜버와 팬의 소개팅**, 메인의 핵심 제목은 **신규 버튜버 데뷔 캘린더**다. 방문자가 첫 화면에서 누가·언제·어느 플랫폼에서 데뷔하는지 알아보고, 소개를 읽은 뒤 공식 방송으로 이동하도록 구성했다. 버튜버는 일정과 특징을 직접 신청하고, 운영자가 관리자 화면에서 검토해 공개한다.

화면 목록 전체를 개발 도메인에 연결했다. 전체 버튜버를 수집했다는 표현, 임의의 인기도·조회수·성장 예측, MCN·결제 화면은 추가하지 않았다. 조회 대상은 개발 DB에 실제로 등록된 소개와 현재 확보한 방송 통계다.

## 3. 등록·관리 운영 절차

1. 이용자가 데뷔 또는 소개 신청을 제출하면 관리자 검토 목록에 `PENDING` 요청이 저장된다.
2. 등록 화면은 서버 접수 성공 후 완료 안내와 캘린더 복귀만 제공한다. 개인 관리 확인 키는 표시하거나 브라우저에 저장하지 않는다.
3. 관리자는 `/admin`에서 로그인하고 공개 채널·내용·중복을 검토한다.
4. 승인하면 공개 소개가 생성된다. 보완 필요 시 관리자가 사유를 기록한다. 등록자에게 개인 처리 알림은 제공하지 않는다. 운영 호스트의 데뷔 승인에는 기존 Discord 구독 채널 알림을 연결했다.
5. 내 등록 관리, 소유권 신청, 본인 소개 수정 화면과 진입 링크는 제공하지 않는다. 정보 수정·삭제는 기존 문의 화면으로 접수한다.
6. 문의만 비공개 확인 키로 답변을 조회한다. 이전 접수 조회와 서버의 기존 권한 API·데이터는 호환을 위해 보존했다.

확인 키는 비밀 인증 정보다. 서버에는 SHA-256 해시만 저장하며 URL에 넣지 않는다. 관리자 세션은 별도 난수 키로 발급하고 8시간 후 만료한다. 로그아웃 시 서버 세션을 삭제한다. 요청 크기 제한·동일 출처 확인·접속 주소 해시 기반 신청 및 로그인 횟수 제한을 적용했다.

## 4. 데이터 및 개발 환경 격리

- 신규 화면 진입점: `frontend/src/portal-main.tsx` → `frontend/src/portal/PortalApp.tsx`, 개발 HTML: `frontend/dev.html`.
- 개발은 dev.html, 운영은 portal.html을 사용한다. 사용자 요청에 따라 2026-10-11 LIVE에 적용했다.
- 신규 API: `/api/v1/portal/*`. 개발과 운영 모두 `PORTAL_ENABLED=true` 환경에서 제공한다.
- 신규 파일 `0036_portal_requests.sql`만 개발 `vdebut-db-dev`와 운영 `vdebut-db`에 명시적으로 실행했다. 전체 마이그레이션은 일괄 실행하지 않았다. 운영 기존 데이터는 유지한다.
- 신규 테이블: 공개 소개 `portal_profiles`, 신청·소유권·문의 `portal_requests`, 관리자 세션 `portal_sessions`.
- 기존 소개 테이블은 읽어서 통합한다. 소개 문구와 `00:00` 값으로 식별되는 외부 검색의 채널 등록 시각은 실제 데뷔 일정에서 제외하고 소개 목록에 보존한다.
- 확인되지 않은 방송 언어·국가·태그를 추측해서 채우지 않는다. 기존 `EN` 값은 국가로 해석하지 않는다.
- 개발 사이트는 HTML 메타·응답 헤더·robots.txt로 검색 색인을 제한한다. 메인 제목·설명은 서비스 내용을 명확히 표현한다.
- 개발 Worker의 예약 작업은 비활성화했다. 포털 활성 환경의 기존 공개 수정·삭제 API는 차단한다. 개인 관리 화면은 제거했다.
- 개발 배포는 `wrangler deploy --env dev`, 운영 배포는 `wrangler deploy --env production`을 실행했다.
- 최신 확인 배포: Worker `streaming-dev`, 버전 `5cff4273-e7a0-4861-ada2-21eb047255a4`, 라우트 `dev.vdebut.live/*`. 페이지·메모리 최적화, 기존 관리·일정 내보내기 복원, 인증 보완 및 한·일·영 전환 반영. 초기 문구 깜빡임·플랫폼별 카드 영역 간격 수정, 하이라이트 제목 제거, 소개 카드 프로필·활동명 강조 및 SOOP 상세 배너·실제 채널 소개 연동 포함. [최적화 결과](./15_PERFORMANCE_OPTIMIZATION.md) 참조.
- 운영 배포: Worker `streaming`, 버전 `560522d1-f044-4e3b-9965-38497319f7a7`, 공개 주소 `https://vdebut.live/`. 기존 346개 소개·일정 보존 및 운영 경로 검증 완료. 새로고침 초기 로딩·플랫폼 전환 간격 수정, 하이라이트 제목 제거, 소개 카드 프로필·활동명 강조 및 SOOP 상세 배너·실제 채널 소개 연동 포함. [LIVE 배포 결과](./16_LIVE_RELEASE_READINESS.md) 참조.

## 6. 현재 구현 범위와 후속 검증

- 관심 목록과 문의 확인 키만 브라우저에 저장한다. 데뷔·소개 등록은 개인 관리 키를 표시·저장하지 않고 운영자 검토로 연결한다.
- 등록 이미지는 기존 플랫폼 API에서 채널 프로필을 불러온다. 이미지 파일 업로드 저장소는 연결하지 않았다.
- 소개·채널 링크 공유를 제공한다. 홍보 조회수·전환율은 수집하지 않아 표시하지 않는다.
- 통계의 현재 지원 플랫폼은 치지직·SOOP이며, 통계 대상 전체가 버튜버인 것은 아니다.
- 개발 DB의 소개·수집 기록은 운영 DB와 다를 수 있다. 이번 작업에서 운영 데이터를 복제하지 않았다.
- 운영 데이터 보존·누락 복원·인증·다국어·적용/복구 절차는 [LIVE 준비 보고](./16_LIVE_RELEASE_READINESS.md)를 참조한다. 계정 동기화와 수집 범위 확대는 별도 범위다.

# 방송 통계 기준 정의서

작성일: 2026-11-16 (개정 1: 플랫폼 → 게임 → 채널 구조 / 개정 2: 공식 API·브랜드·소속 표기·페이지 흐름 추가)
상태: 기준 문서. 방송 통계 화면·API·디자인은 이 문서를 따른다. 화면이나 수치를 바꾸려면 이 문서를 먼저 고친다.

읽는 순서: 목적 → 컨셉 → 지향점 → 지금 가진 데이터 → 용어·판정 규칙 → 지표 정의 → 화면 구성 → 서버 작업. 앞 장이 정해지지 않으면 뒤 장을 만들지 않는다.

---

## 1. 페이지 목적

**스트리밍 플랫폼(치지직·SOOP)의 지금 판도와, 어떤 게임에 시청자가 몰리는지를 데이터로 보여 주는 조사 공간을 만든다. 개별 채널은 그 아래 단계에서 분석한다.**

| 누가 | 무엇을 알려고 오나 |
|---|---|
| 스트리머·버튜버 | 지금 어느 플랫폼, 어떤 게임에 시청자가 많고 경쟁은 어떤가 |
| 시청자·팬 | 지금 플랫폼에서 무엇이 인기인가, 내가 보는 채널은 어느 위치인가 |
| 게임·업계 관계자 | 어떤 게임이 방송에서 뜨고 지는가 |

성공 기준 (출시 후 4주 측정으로 기준값을 잡고 다시 정한다):

| 지표 | 정의 | 초기 목표 |
|---|---|---|
| 재방문율 | 통계 페이지 방문자 중 14일 안에 다시 방문한 비율 | 25% |
| 게임 검색 유입 | "[게임 이름] 방송 순위·시청자" 류 검색으로 게임 페이지에 들어온 클릭 | 월 1,000회 |
| 깊이 탐색률 | 대시보드 방문 중 게임 또는 채널 페이지로 한 단계 이상 들어간 비율 | 40% |

## 2. 컨셉

**"스트리밍 판도 대시보드" — 플랫폼 → 게임 → 채널 순서로 내려가며 본다.**

| 단계 | 질문 | 페이지 |
|---|---|---|
| 1. 플랫폼 | 지금 각 플랫폼에 몇 명이 보고, 평소와 비교해 어떤가 | 대시보드 상단 |
| 2. 게임 | 어떤 게임에 시청자가 몰리고, 방송 하나당 몇 명이 보는가, 무엇이 뜨는가 | 대시보드 중심 + 게임별 페이지 |
| 3. 채널 | 그 게임·플랫폼 안에서 누가 시청자를 모으는가, 한 채널의 기록은 어떤가 | 채널 순위 + 채널 분석 페이지 |

범용 채널 분석 사이트가 "내 채널"에서 출발한다면, 이 페이지는 **플랫폼과 게임에서 출발해 채널로 내려간다.** 버튜버는 VDébut의 강점이므로 채널 단계에서 "버튜버만 보기" 필터로 제공한다.

하지 않는 것:

- 등록 유도·홍보 문구를 대시보드에 넣는 것. 대시보드는 판도를 보여 주는 데만 쓴다.
- 기준을 밝힐 수 없는 수치, 수집 범위 밖을 추정한 수치.
- 소속사 단위 순위.

## 3. 지향점 (원칙)

1. **잰 것만 보여 준다.** 수집하지 않은 방송을 추정하지 않는다. 각 수치의 수집 범위는 "집계 기준" 페이지에 공개한다.
2. **모든 수치는 이 문서의 정의 하나에 대응한다.** 정의가 없는 수치는 화면에 올리지 않는다.
3. **같은 기준으로 잰 것끼리만 비교한다.** 수집 범위가 다른 플랫폼끼리 점유율을 비교하지 않는다(6.1 P3).
4. **평소와 비교해 보여 준다.** 숫자 하나만이 아니라 같은 요일·시각 평소 값, 지난주 값과 함께 보여 준다.
5. **데이터가 모자라면 숨긴다.** 빈 칸이나 0을 보여 주지 않는다.
6. **위 단계에서 아래 단계로 들어갈 수 있다.** 플랫폼 → 게임 → 채널로 이어지는 링크가 모든 섹션에 있다.

## 4. 지금 가진 서버 데이터 (2026-11-16 코드 기준 사실)

### 4.1 수집

| 항목 | 치지직 | SOOP |
|---|---|---|
| 수집 주기 | 10분 (UTC 10분 구간을 회차 키로 사용) | 10분 |
| 수집 대상 | 라이브 목록 `sortType=POPULAR` 50개 × 2쪽 = **시청자 상위 100개 방송** | `streamerChannel`에 등록된 SOOP 채널 중 **id 순 앞 150개**의 방송국 조회 |

| 방송 시작 시각 | `openDate` | **없음** (`started_at` 비어 있음) |

### 4.2 저장 구조

`analytics_broadcast_runs` (회차): `run_id`, `platform`, `scheduled_at`, `observed_at`, `state`, `scope`, `checked_channels`, `viewer_total`(수집한 방송의 시청자 합계 — 플랫폼 전체 시청자가 아님), `channel_total`

`analytics_broadcast_snapshots` (회차별 방송 한 줄): `run_id`, `stream_id`, `channel_key`, `channel_name`, `channel_url`, `image_url`, `live_url`, `title`, `category_id`, `category_name`, `viewers`, `started_at`

저장하지 않는 것: 태그, 버튜버 여부, 신인 여부.

### 4.4 현재 수집 경로

지금 수집은 두 플랫폼 모두 **웹 화면이 쓰는 내부 주소**(`api.chzzk.naver.com/service/v1/lives`, `chapi.sooplive.co.kr/api/{id}/station`)를 쓴다. 공개 문서가 없어 예고 없이 바뀔 수 있다. 4.5의 공식 API로 옮긴다.

### 4.5 공식 API (2026-11-16 각 개발자 센터 문서 확인)

| 플랫폼 | API | 용도 | 핵심 사항 |
|---|---|---|---|
| 치지직 | `GET /open/v1/lives` 라이브 목록 | P·G·M 수집의 기본 | **시청자 많은 순 정렬**, 1회 최대 20개, `next`로 다음 쪽. 응답: `liveId`, `liveTitle`, `concurrentUserCount`, `openDate`, `adult`, `tags`, **`categoryType`(GAME/SPORTS/ETC)**, `liveCategory`, `liveCategoryValue`, `channelId`, `channelName`, `channelImageUrl` |
| 치지직 | `GET /open/v1/channels` 채널 정보 | 채널 페이지 | 1회 최대 20개. `channelName`, `channelImageUrl`, **`followerCount`**, `verifiedMark` |
| 치지직 | `GET /open/v1/categories/search` 카테고리 검색 | 통합 게임 목록 | `categoryType`, `categoryId`, `categoryValue`, `posterImageUrl`(게임 이미지) |
| SOOP | `GET https://openapi.sooplive.com/broad/list` 방송 목록 | P·G·M 수집의 기본 | **`order_type=view_cnt`(시청자 순)**, `page_no`, 한 쪽 60개(`page_block`), 카테고리 필터(`select_key=cate`). 응답: `total_cnt`, `broad_no`, `broad_title`, `user_id`, `user_nick`, `profile_img`, `broad_cate_no`, **`broad_start`(시작 시각)**, `broad_grade`, `total_view_cnt` |
| SOOP | `GET https://openapi.sooplive.com/broad/category/list` 카테고리 목록 | 통합 게임 목록 | 상위·하위 구조. 예: `게임(00040000)` 아래 `LOL(00040019)`, `배틀그라운드(00040066)` / `토크/캠방(00130000)`, `먹방/쿡방(00330000)` |

인증: 두 플랫폼 모두 개발자 센터에 애플리케이션을 등록하고 받은 `client_id`(치지직은 `clientSecret` 포함)로 호출한다. 키는 서버 비밀 값으로만 보관한다.

효과:

- 두 플랫폼 모두 **시청자 순 상위 N개**를 같은 방식으로 받을 수 있어 5.1 공통 수집 범위를 만족한다. (N=100 기준 요청 수: 치지직 5회, SOOP 2회 / 10분)
- 게임·비게임 구분을 **공식 값**으로 한다: 치지직 `categoryType = GAME`, SOOP `게임(00040000)` 하위 카테고리.
- SOOP 방송 시작 시각(`broad_start`)이 생겨 방송 시간 계산이 정확해진다.
- 채널 페이지에 치지직 팔로워 수를 보여 줄 수 있다. SOOP 공개 목록 API에는 팔로워 수가 없다.

## 5. 용어와 판정 규칙

### 5.1 수집 범위 (커버리지)

플랫폼마다 **"시청자 많은 순 상위 N개 방송"**을 공통 기준으로 수집한다. N은 9장에서 정한다. 모든 플랫폼 수치는 "상위 N개 방송 기준"이다.

### 5.2 게임(카테고리)

- 플랫폼이 준 카테고리 ID·이름을 그대로 저장한다.
- **게임 여부는 공식 값으로 정한다**: 치지직 `categoryType = GAME`, SOOP `게임(00040000)` 하위 카테고리. 나머지는 비게임.
- 플랫폼 간 비교를 위해 **통합 게임 목록**(`analytics_category_map`)으로 이름을 맞춘다. 예: 치지직 "리그 오브 레전드" = SOOP "리그 오브 레전드" = 통합 "리그 오브 레전드". 대응이 등록되지 않은 카테고리는 플랫폼 이름 그대로 따로 집계한다.
- 게임 순위에는 게임만 올린다. "종합 게임"처럼 게임 분류 안에 있지만 특정 게임이 아닌 카테고리는 운영자가 관리하는 제외 목록으로 뺀다.
- 비게임(토크, 노래, 먹방 등)은 "게임 외 콘텐츠" 순위로 따로 보여 준다.

### 5.3 버튜버

VDébut에 **공개 소개**가 있고 소개의 방송 채널과 `channel_key`가 일치하는 채널, 또는 운영자가 승인한 채널만 버튜버다. 통계 검색 자동 등록 채널·키워드 일치 채널은 제외한다. 판정은 채널 단위로 저장한다(`analytics_channel_profile`).

### 5.4 방송(세션)

같은 `channel_key`에서 같은 `started_at`으로 관측된 회차를 한 방송으로 묶는다. `started_at`이 없으면(SOOP) 관측 간격이 20분 이하로 이어진 회차를 한 방송으로 본다.

### 5.5 유효 회차

`state`가 `available`인 회차만 기간 지표에 쓴다. `partial`은 실시간 화면에만, `unavailable`은 어디에도 쓰지 않는다.

### 5.6 평소 기준선

"평소" = **최근 4주 같은 요일·같은 시각(±10분) 유효 회차 값의 중앙값.** 4주 중 3주 이상 기록이 있을 때만 계산한다.

### 5.7 플랫폼 표기 (브랜드)

근거: 치지직 공식 브랜드 가이드("임의 변형 금지, 제휴·지원 오인 금지, 상업적 목적 사용 불가"), SOOP 개발자 약관("회사의 명시적 동의 없이 상표·로고 등 영업표지 사용 금지"), `frontend/public/BrandGuidelines/PLATFORM_BRAND_GUIDELINES.md`.

1. **통계 화면의 기본 표기는 공식 명칭 텍스트**: `치지직`, `SOOP`. `Chzzk`, `숲TV` 같은 변형 명칭은 쓰지 않는다.
2. **로고·아이콘은 플랫폼의 사용 허락을 받은 뒤에만** 쓴다. 이 사이트는 광고를 붙이므로 치지직 가이드의 "상업적 목적 사용 불가"에 걸릴 수 있다. 허락 전까지 통계 화면에는 로고를 쓰지 않는다.
3. 허락을 받아 쓸 때: 공식 배포 파일만, 변형·색 변경·배경판 추가 금지, 로고 높이의 25% 이상 여백, VDébut 로고보다 작게, 해당 채널로 가는 링크에만.
4. 플랫폼 구분 색을 쓰지 않는다(브랜드 색 오용 방지). 플랫폼은 텍스트로 구분한다.
5. "공식 파트너, 제휴, 인증" 등 관계를 오인시키는 표현을 쓰지 않는다.

### 5.8 소속 표기

- 채널 한 줄의 보조 정보는 **`{플랫폼}`** 또는 **`{플랫폼} / {소속}`** 형식이다. 예: `치지직`, `SOOP / 스텔라이브`.
- **소속은 공식 소속사가 있을 때만 붙인다.** "개인", "개인세", "개인 활동", "무소속", "indie", "소속사"(미입력 기본값)는 화면에 절대 쓰지 않는다. 저장된 값이 이 목록이면 소속 없음으로 처리한다.
- 소속 정보 출처는 VDébut 공개 소개의 공식 소속이다. 소개가 없는 채널은 플랫폼만 표시한다.

### 5.9 시간 기준

모든 날짜·시각·주차는 **한국 시간(KST)**. 하루 00:00~23:59, 한 주 월요일 00:00~일요일 23:59.

## 6. 지표 정의

표기 공통: 시청자는 정수, 천 단위 쉼표, "명". 시간은 10분 단위 반올림. 비율은 정수 "%". 증감은 "▲/▼ n%".

### 6.1 플랫폼 단계 (P)

| ID | 지표 | 정의·계산식 | 범위 | 조건 | 지금 가능 |
|---|---|---|---|---|---|
| P1 | 플랫폼 시청자 | 최신 유효 회차에서 상위 N개 방송 `viewers` 합계 | 최신 회차 | `observed_at` 20분 이내 | 치지직만 (N=100) |
| P2 | 1,000명 이상 방송 수 | 최신 회차에서 시청자 1,000명 이상인 방송 수. (상위 N개 수집에서 '방송 수'는 항상 N이라 쓰지 않는다) | 최신 회차 | P1과 같음 | 치지직만 |
| P3 | 플랫폼 점유율 | 플랫폼 P1 ÷ 전체 플랫폼 P1 합계 | 최신 회차 | **모든 플랫폼이 같은 N으로 수집될 때만 표시** | 불가 |
| P4 | 평소 대비 | (P1 − 5.6 평소 P1) ÷ 평소 P1 | 최신 회차 | 5.6 조건 | 4주 누적 후 |
| P5 | 시청자 추이 | 회차별 P1 | 24시간 / 7일 | 유효 회차. 빠진 회차는 선을 끊음 | 치지직만 |
| P6 | 피크 | 기간 내 P1 최댓값과 그 시각 | 오늘 / 7일 | 유효 회차 | 치지직만 |

### 6.2 게임 단계 (G)

| ID | 지표 | 정의·계산식 | 범위 | 조건 | 지금 가능 |
|---|---|---|---|---|---|
| G1 | 게임 시청자 | 한 회차에서 같은 게임(5.2) 방송의 `viewers` 합계. 기간 보기는 회차별 G1의 평균 | 최신 회차 / 기간 | 비게임 제외 | 치지직 상위 100 |
| G2 | 게임 방송 수 | 한 회차에서 같은 게임 방송 수. 기간 보기는 회차별 평균 | G1과 같음 | 비게임 제외 | 치지직 상위 100 |
| G3 | 방송당 시청자 | G1 ÷ G2 | G1과 같음 | G2 ≥ 2 | 치지직 상위 100 |
| G4 | 경쟁 판단 | G3 ÷ 같은 회차 전체 게임 G3의 중앙값. **1.5 이상 "여유", 0.67 이하 "혼잡", 그 사이 "보통"** | G3과 같음 | G3과 같음 | 치지직 상위 100 |
| G5 | 게임 순위 | G1 내림차순. 동점이면 G2가 많은 순 | 실시간 / 오늘 / 7일 | 비게임 제외 | 치지직 상위 100 |
| G6 | 순위 변동 | 7일 순위와 그 전 7일 순위 비교: ▲n / ▼n / 유지 / 새로 진입 | 7일 | 두 기간 모두 유효 회차 80% 이상 | 2주 누적 후 |
| G7 | 급상승 게임 | 7일 평균 G1이 그 전 7일보다 30% 이상 늘고, 7일 평균 G1 ≥ 1,000명 | 7일 | G6과 같음 | 2주 누적 후 |
| G8 | 플랫폼별 비중 | 통합 게임별 플랫폼 G1 ÷ 그 게임의 전체 G1 | 최신 회차 / 7일 | 5.1 공통 N, 5.2 통합 목록 | 불가 |

### 6.3 채널 단계 (M)

| ID | 지표 | 정의·계산식 | 범위 | 조건 | 지금 가능 |
|---|---|---|---|---|---|
| M1 | 실시간 시청자 | 최신 회차의 `viewers` | 최신 회차 | `observed_at` 20분 이내 | 가능 |
| M2 | 방송 시간 | 방송(5.4)마다 마지막 관측 − 시작 시각, 기간 합계 | 기간 | 유효 회차 | 가능 |
| M3 | 평균 시청자 | Σ 관측 회차 `viewers` ÷ 관측 회차 수 | 기간 | 방송 시간 ≥ 3시간 | 가능 |
| M4 | 최고 시청자 | 기간 내 관측 `viewers` 최댓값 | 기간 | 유효 회차 | 가능 |
| M5 | 방송 횟수 | 기간 내 방송(5.4) 수 | 기간 | 유효 회차 | 가능 |
| M6 | 주력 게임 | 기간 내 방송 시간이 가장 긴 게임과 그 비중 | 기간 | 유효 회차 | 가능 |

| M8 | 방송 시간대 | 기간 내 기록된 방송 시간의 요일×시각별 비중 | 기간 | 유효 회차 | 가능 |

|---|---|---|---|

| E3 | 1인 독주 | G2 = 1인 게임에서 시청자 5,000명 이상 | 「{게임}」은 한 채널이 {V}명을 혼자 모으고 있어요 |

## 9. 결정이 필요한 것

1. **공식 API 애플리케이션 등록**: 치지직 개발자 센터(developers.chzzk.naver.com)와 SOOP 개발자 센터(developers.sooplive.co.kr)에 VDébut 애플리케이션을 등록하고 키를 발급받아야 한다. 계정 소유자가 직접 등록해야 한다.
2. **공통 수집 범위 N**: 플랫폼별 시청자 순 상위 몇 개까지 볼지. N=100이면 10분마다 치지직 5회·SOOP 2회 요청, N=300이면 치지직 15회·SOOP 5회.
3. **플랫폼 로고 사용 허락 요청 여부**: 허락 전까지는 텍스트 표기(5.7). 로고를 쓰려면 두 플랫폼에 사용 허락을 문의한다.
4. **게임 순위 제외 목록**: 게임 분류 안의 "종합 게임"류 카테고리 중 제외할 것.
5. **경쟁 판단·급상승 수치**: 1.5배·0.67배, 30%·1,000명 — 2주 실제 분포를 본 뒤 확정.

# 방송 통계 기준 정의서

작성일: 2026-11-16 (개정 1: 플랫폼 → 게임 → 채널 구조 / 개정 2: 공식 API·브랜드·소속 표기·페이지 흐름 추가 / 개정 3: 정각 갱신·그래프 표시·태그 페이지·로고 사용 확정 / 개정 4: 지금 상황 정리(AI 요약)·화면 표현 규칙·게임 이미지 미사용)
상태: 기준 문서. 방송 통계 화면·API·디자인은 이 문서를 따른다. 화면이나 수치를 바꾸려면 이 문서를 먼저 고친다.

읽는 순서: 목적 → 컨셉 → 지향점 → 지금 가진 데이터 → 용어·판정 규칙 → 지표 정의 → 화면 구성 → 서버 작업. 앞 장이 정해지지 않으면 뒤 장을 만들지 않는다.

## 1. 페이지 목적

**스트리밍 플랫폼(치지직·SOOP)의 지금 판도와, 어떤 게임에 시청자가 몰리는지를 데이터로 보여 주는 조사 공간을 만든다. 개별 채널은 그 아래 단계에서 분석한다.**

| 누가 | 무엇을 알려고 오나 |
|---|---|
| 스트리머·버튜버 | 지금 어느 플랫폼, 어떤 게임에 시청자가 많고 경쟁은 어떤가 |
| 시청자·팬 | 지금 플랫폼에서 무엇이 인기인가, 내가 보는 채널은 어느 위치인가 |
| 게임·업계 관계자 | 어떤 게임이 방송에서 뜨고 지는가 |

성공 기준 (출시 후 4주 측정으로 기준값을 잡고 다시 정한다):

| 지표 | 정의 | 초기 목표 |
|---|---|---|
| 재방문율 | 통계 페이지 방문자 중 14일 안에 다시 방문한 비율 | 25% |
| 게임 검색 유입 | "[게임 이름] 방송 순위·시청자" 류 검색으로 게임 페이지에 들어온 클릭 | 월 1,000회 |
| 깊이 탐색률 | 대시보드 방문 중 게임 또는 채널 페이지로 한 단계 이상 들어간 비율 | 40% |

## 2. 컨셉

**"스트리밍 판도 대시보드" — 플랫폼 → 게임 → 채널 순서로 내려가며 본다.**

| 단계 | 질문 | 페이지 |
|---|---|---|
| 1. 플랫폼 | 지금 각 플랫폼에 몇 명이 보고, 평소와 비교해 어떤가 | 대시보드 상단 |
| 2. 게임 | 어떤 게임에 시청자가 몰리고, 방송 하나당 몇 명이 보는가, 무엇이 뜨는가 | 대시보드 중심 + 게임별 페이지 |
| 3. 채널 | 그 게임·플랫폼 안에서 누가 시청자를 모으는가, 한 채널의 기록은 어떤가 | 채널 순위 + 채널 분석 페이지 |

범용 채널 분석 사이트가 "내 채널"에서 출발한다면, 이 페이지는 **플랫폼과 게임에서 출발해 채널로 내려간다.** 버튜버는 VDébut의 강점이므로 채널 단계에서 "버튜버만 보기" 필터로 제공한다.

하지 않는 것:

- 등록 유도·홍보 문구를 대시보드에 넣는 것. 대시보드는 판도를 보여 주는 데만 쓴다.
- 기준을 밝힐 수 없는 수치, 수집 범위 밖을 추정한 수치.
- 소속사 단위 순위.

## 3. 지향점 (원칙)

1. **잰 것만 보여 준다.** 수집하지 않은 방송을 추정하지 않는다. 각 수치의 수집 범위는 "집계 기준" 페이지에 공개한다.
2. **모든 수치는 이 문서의 정의 하나에 대응한다.** 정의가 없는 수치는 화면에 올리지 않는다.
3. **같은 기준으로 잰 것끼리만 비교한다.** 수집 범위가 다른 플랫폼끼리 점유율을 비교하지 않는다(6.1 P3).
4. **평소와 비교해 보여 준다.** 숫자 하나만이 아니라 같은 요일·시각 평소 값, 지난주 값과 함께 보여 준다.
5. **데이터가 모자라면 숨긴다.** 빈 칸이나 0을 보여 주지 않는다.
6. **위 단계에서 아래 단계로 들어갈 수 있다.** 플랫폼 → 게임 → 채널로 이어지는 링크가 모든 섹션에 있다.

## 4. 지금 가진 서버 데이터 (2026-11-16 코드 기준 사실)

### 4.1 수집

| 항목 | 치지직 | SOOP |
|---|---|---|
| 수집 주기 | 10분 (UTC 10분 구간을 회차 키로 사용) | 10분 |
| 수집 대상 | 라이브 목록 `sortType=POPULAR` 50개 × 2쪽 = **시청자 상위 100개 방송** | `streamerChannel`에 등록된 SOOP 채널 중 **id 순 앞 150개**의 방송국 조회 |

| 게임 정보 | `liveCategory`(ID) · `liveCategoryValue`(이름) | `broad_cate_no` · `broad_cate_name` (이름 빠진 경우 많음) |
| 방송 시작 시각 | `openDate` | **없음** (`started_at` 비어 있음) |
| 태그 | 받지만 **저장하지 않음** | — |
| 보관 기간 | 90일 | 90일 |

코드 위치: `backend/src/services/broadcastStatisticsCollection.ts`, `broadcastStatisticsSources.ts`

**결론: 지금 데이터로는 "플랫폼 전체 판도"를 말할 수 없다.** 치지직은 상위 100개 방송만, SOOP은 등록 채널만 있어 두 플랫폼의 범위가 다르다.

### 4.2 저장 구조

`analytics_broadcast_runs` (회차): `run_id`, `platform`, `scheduled_at`, `observed_at`, `state`, `scope`, `checked_channels`, `viewer_total`(수집한 방송의 시청자 합계 — 플랫폼 전체 시청자가 아님), `channel_total`

`analytics_broadcast_snapshots` (회차별 방송 한 줄): `run_id`, `stream_id`, `channel_key`, `channel_name`, `channel_url`, `image_url`, `live_url`, `title`, `category_id`, `category_name`, `viewers`, `started_at`

저장하지 않는 것: 태그, 버튜버 여부, 신인 여부.

### 4.4 현재 수집 경로

지금 수집은 두 플랫폼 모두 **웹 화면이 쓰는 내부 주소**(`api.chzzk.naver.com/service/v1/lives`, `chapi.sooplive.co.kr/api/{id}/station`)를 쓴다. 공개 문서가 없어 예고 없이 바뀔 수 있다. 4.5의 공식 API로 옮긴다.

### 4.5 공식 API (2026-11-16 각 개발자 센터 문서 확인)

| 플랫폼 | API | 용도 | 핵심 사항 |
|---|---|---|---|
| 치지직 | `GET /open/v1/lives` 라이브 목록 | P·G·M 수집의 기본 | **시청자 많은 순 정렬**, 1회 최대 20개, `next`로 다음 쪽. 응답: `liveId`, `liveTitle`, `concurrentUserCount`, `openDate`, `adult`, `tags`, **`categoryType`(GAME/SPORTS/ETC)**, `liveCategory`, `liveCategoryValue`, `channelId`, `channelName`, `channelImageUrl` |
| 치지직 | `GET /open/v1/channels` 채널 정보 | 채널 페이지 | 1회 최대 20개. `channelName`, `channelImageUrl`, **`followerCount`**, `verifiedMark` |
| 치지직 | `GET /open/v1/categories/search` 카테고리 검색 | 통합 게임 목록 | `categoryType`, `categoryId`, `categoryValue`, `posterImageUrl`(게임 이미지) |
| SOOP | `GET https://openapi.sooplive.com/broad/list` 방송 목록 | P·G·M 수집의 기본 | **`order_type=view_cnt`(시청자 순)**, `page_no`, 한 쪽 60개(`page_block`), 카테고리 필터(`select_key=cate`). 응답: `total_cnt`, `broad_no`, `broad_title`, `user_id`, `user_nick`, `profile_img`, `broad_cate_no`, **`broad_start`(시작 시각)**, `broad_grade`, `total_view_cnt` |
| SOOP | `GET https://openapi.sooplive.com/broad/category/list` 카테고리 목록 | 통합 게임 목록 | 상위·하위 구조. 예: `게임(00040000)` 아래 `LOL(00040019)`, `배틀그라운드(00040066)` / `토크/캠방(00130000)`, `먹방/쿡방(00330000)` |

인증: 두 플랫폼 모두 개발자 센터에 애플리케이션을 등록하고 받은 `client_id`(치지직은 `clientSecret` 포함)로 호출한다. 키는 서버 비밀 값으로만 보관한다.

효과:

- 두 플랫폼 모두 **시청자 순 상위 N개**를 같은 방식으로 받을 수 있어 5.1 공통 수집 범위를 만족한다. (N=100 기준 요청 수: 치지직 5회, SOOP 2회 / 1시간)
- 게임·비게임 구분을 **공식 값**으로 한다: 치지직 `categoryType = GAME`, SOOP `게임(00040000)` 하위 카테고리.
- SOOP 방송 시작 시각(`broad_start`)이 생겨 방송 시간 계산이 정확해진다.
- 채널 페이지에 치지직 팔로워 수를 보여 줄 수 있다. SOOP 공개 목록 API에는 팔로워 수가 없다.

## 5. 용어와 판정 규칙

### 5.1 수집 범위 (커버리지)

플랫폼마다 **"시청자 많은 순 상위 N개 방송"**을 공통 기준으로 수집한다. N은 9장에서 정한다. 모든 플랫폼 수치는 "상위 N개 방송 기준"이다.

### 5.2 게임(카테고리)

- 플랫폼이 준 카테고리 ID·이름을 그대로 저장한다.
- **게임 여부는 공식 값으로 정한다**: 치지직 `categoryType = GAME`, SOOP `게임(00040000)` 하위 카테고리. 나머지는 비게임.
- 플랫폼 간 비교를 위해 **통합 게임 목록**(`analytics_category_map`)으로 이름을 맞춘다. 예: 치지직 "리그 오브 레전드" = SOOP "리그 오브 레전드" = 통합 "리그 오브 레전드". 대응이 등록되지 않은 카테고리는 플랫폼 이름 그대로 따로 집계한다.
- 게임 순위에는 게임만 올린다. "종합 게임"처럼 게임 분류 안에 있지만 특정 게임이 아닌 카테고리는 운영자가 관리하는 제외 목록으로 뺀다.
- 비게임(토크, 노래, 먹방 등)은 "게임 외 콘텐츠" 순위로 따로 보여 준다.

### 5.3 버튜버

VDébut에 **공개 소개**가 있고 소개의 방송 채널과 `channel_key`가 일치하는 채널, 또는 운영자가 승인한 채널만 버튜버다. 통계 검색 자동 등록 채널·키워드 일치 채널은 제외한다. 판정은 채널 단위로 저장한다(`analytics_channel_profile`).

### 5.4 방송(세션)

같은 `channel_key`에서 같은 `started_at`으로 관측된 회차를 한 방송으로 묶는다. `started_at`이 없으면(SOOP) 관측 간격이 20분 이하로 이어진 회차를 한 방송으로 본다.

### 5.5 유효 회차

`state`가 `available`인 회차만 기간 지표에 쓴다. `partial`은 실시간 화면에만, `unavailable`은 어디에도 쓰지 않는다.

### 5.6 평소 기준선

"평소" = **최근 4주 같은 요일·같은 정각 유효 회차 값의 중앙값.** 4주 중 3주 이상 기록이 있을 때만 계산한다.

### 5.7 플랫폼 표기 (브랜드)

근거: 치지직 공식 브랜드 가이드("임의 변형 금지, 제휴·지원 오인 금지, 상업적 목적 사용 불가"), SOOP 개발자 약관("회사의 명시적 동의 없이 상표·로고 등 영업표지 사용 금지"), `frontend/public/BrandGuidelines/PLATFORM_BRAND_GUIDELINES.md`.

1. **공식 명칭**: `치지직`, `SOOP`. `Chzzk`, `숲TV` 같은 변형 명칭은 쓰지 않는다.
2. **로고는 플랫폼 식별 위치에만** 쓴다(브랜드 가이드라인 §4): 플랫폼 필터, 플랫폼 현황 카드 제목, 채널 줄의 플랫폼 표시, 공식 채널 이동 버튼. 항상 공식 명칭 텍스트와 함께 쓴다.
3. 사용 파일: 치지직 아이콘(둥근형)·국문 기본형 검정 로고(`chzzklogo_kor(Black).png`, SHA-256 원본 일치), SOOP 심볼·로고(파랑). 변형·색 변경·필터·그림자 금지. 선택 상태는 로고가 아니라 버튼 테두리로 표현한다.
4. 치지직 채널 이동 버튼: `#00FFA3` 배경 + 검정 기본형 로고 높이 24px, 사방 12px 여백, 버튼 높이 50px (가이드라인 §5.6).
5. **사용 허락 완료**: 치지직·SOOP 로고는 사용 허락을 받은 상태다. 저장소의 원본 파일만 쓰고, 크기 조정·재압축한 사본을 만들지 않는다(표시 크기는 CSS로만 조절).
6. 그래프·막대에 플랫폼 브랜드 색을 쓰지 않는다.
7. "공식 파트너, 제휴, 인증" 등 관계를 오인시키는 표현을 쓰지 않는다.

### 5.8 소속 표기

- 채널 한 줄의 보조 정보는 **`{플랫폼}`** 또는 **`{플랫폼} / {소속}`** 형식이다. 예: `치지직`, `SOOP / 스텔라이브`.
- **소속은 공식 소속사가 있을 때만 붙인다.** "개인", "개인세", "개인 활동", "무소속", "indie", "소속사"(미입력 기본값)는 화면에 절대 쓰지 않는다. 저장된 값이 이 목록이면 소속 없음으로 처리한다.
- 소속 정보 출처는 VDébut 공개 소개의 공식 소속이다. 소개가 없는 채널은 플랫폼만 표시한다.

### 5.9 시간 기준

모든 날짜·시각·주차는 **한국 시간(KST)**. 하루 00:00~23:59, 한 주 월요일 00:00~일요일 23:59.

### 5.10 측정·갱신 주기 (10분 규칙, 개정 5)

- **'지금' 숫자는 수집 주기와 같은 10분마다 바뀐다**: 지금 시청자, 1,000명 이상 방송, 오늘 최고, 지금 게임 순위, 게임 외 콘텐츠, 방송 태그 순위, 실시간 채널 순위, 게임 상세의 지금 값, 채널의 방송 중 표시. 가장 최근에 끝난 10분 회차 값을 쓴다.
- **기간 통계는 매시 정각(KST HH:00) 회차로 계산한다**: 시청자 추이(오늘·어제의 시간별 막대, 7일·30일 하루 평균), 오늘·7일 게임 순위, 급상승, 시간대, 게임별 상위 채널, 채널 기간 평균·최고, 태그 추이. 같은 기준으로 기간을 비교하기 위해서다.
- 화면은 받은 값의 기준 회차를 기억한다. 다음 회차가 끝난 뒤(회차 시각 + 1분) **새로고침, 탭 복귀, 다른 요청이 일어나면** 새 값으로 교체하고, 화면을 계속 보고 있으면 한 번 조용히 갱신한다. 이번 회차가 아직 모이지 않았으면 1분 뒤 다시 확인한다.
- 화면 문구: 부제 "10분마다 새로 집계해요 · 오늘 오후 {H}시 {M}분 기준". 수치 옆에 시각을 따로 붙이지 않는다.
- 응답 캐시는 다음 회차 + 2분(수집 완료 여유)까지만 유지한다.
- 주기를 5분·3분으로 줄이려면 먼저 ① 같은 예약 작업 안의 매시 1회 작업(자동 심사·프로필 동기화·디스코드 브리핑) 분리, ② 수집 직후 요약 미리 계산, ③ SOOP 공식 API 전환이 필요하다.

### 5.11 화면 표현 규칙

- **버튜버 도감 상세 페이지와 같은 색·모양을 쓴다.** 바탕은 사이트 바탕(#F7F9FC), 섹션은 도감의 흰 패널과 같은 흰 바탕 + 1px 선(#E4EAF2) + 모서리 14px. 그라데이션, 번짐 그림자, 반짝이 아이콘, 알약 배지를 쓰지 않는다.
- 색: 글자 #19263B, 보조 글자 #6A778B. 수치 막대는 사이트 파랑(#2563EB), 보조 막대는 연한 파랑(#BCD0F7·#DBE7FB). 선 그래프(방송 수·평소)는 주황(#F08C2E) 한 가지만 쓴다.
- **단계 색(시간대 칸 등)은 한 가지 색의 명도 단계만 쓴다**: 파랑 #EEF4FF → #C9DAFB → #8FB1F2 → #4A7FE0 → #1D4FB8. 중간에 다른 색을 섞지 않는다.
- 글자 굵기는 최대 700, 섹션 제목은 17px이다. 숫자는 자릿수 폭을 맞춘다(tabular-nums).
- 같은 안내를 두 번 쓰지 않는다. 정각 갱신 안내는 통계 페이지 부제 한 곳에만 둔다.
- **게임 이미지는 쓰지 않는다.** 치지직 공식 API에는 포스터가 있지만 SOOP 공식 카테고리 목록에는 이미지가 없어서 모든 게임에 같은 기준으로 넣을 수 없고, 게임사 이미지라 권리도 따로 확인해야 한다.

## 6. 지표 정의

표기 공통: 시청자는 정수, 천 단위 쉼표, "명". 방송 시간은 10분 단위 반올림. 비율은 정수 "%". 증감은 "▲/▼ n%".

### 6.1 플랫폼 단계 (P)

| ID | 지표 | 정의·계산식 | 범위 | 조건 | 지금 가능 |
|---|---|---|---|---|---|
| P1 | 플랫폼 시청자 | 최신 유효 회차에서 상위 N개 방송 `viewers` 합계 | 최신 정각 회차 | 가장 최근 정각 회차가 있을 때 | 치지직만 (N=100) |
| P2 | 1,000명 이상 방송 수 | 최신 회차에서 시청자 1,000명 이상인 방송 수. (상위 N개 수집에서 '방송 수'는 항상 N이라 쓰지 않는다) | 최신 회차 | P1과 같음 | 치지직만 |
| P3 | 플랫폼 점유율 | 플랫폼 P1 ÷ 전체 플랫폼 P1 합계 | 최신 회차 | **모든 플랫폼이 같은 N으로 수집될 때만 표시** | 불가 |
| P4 | 평소 대비 | (P1 − 5.6 평소 P1) ÷ 평소 P1 | 최신 회차 | 5.6 조건 | 4주 누적 후 |
| P5 | 시청자 추이 | 정각 회차별 P1 (7일·30일은 일별 평균) | 오늘 / 어제 / 7일 / 30일 | 유효 회차. 빠진 회차는 막대를 비움 | 치지직만 |
| P6 | 오늘 최고 | 오늘 0시부터 최신 정각까지 P1 최댓값. **시각은 표시하지 않는다** (정각마다 함께 갱신되는 값) | 오늘 | 유효 회차 | 치지직만 |

### 6.4 태그 단계 (T)

태그 출처: 치지직 라이브 목록의 `tags`. SOOP 공개 방송 목록 응답에는 태그 항목이 확인되지 않아 **치지직만 집계**한다(SOOP은 확인되면 추가). 태그 정규화: 앞뒤 공백 제거, 내부 공백 제거, NFKC, 영문 소문자. 동의어 묶음(예: 버츄얼·버추얼)은 운영자가 관리한다.

| ID | 지표 | 정의·계산식 | 범위 | 조건 | 지금 가능 |
|---|---|---|---|---|---|
| T1 | 태그 방송 수 | 한 회차에서 그 태그를 단 방송 수 (채널당 1회) | 최신 회차 / 기간은 회차별 평균 | 유효 회차 | 태그 저장 후 |
| T2 | 태그 시청자 | 그 태그를 단 방송의 `viewers` 합계. 한 방송의 여러 태그에는 각각 더한다(태그 간 합계는 플랫폼 시청자를 넘을 수 있음) | T1과 같음 | T1과 같음 | 태그 저장 후 |
| T3 | 태그 방송당 시청자 | T2 ÷ T1 | T1과 같음 | T1 ≥ 2 | 태그 저장 후 |
| T4 | 태그 변동 | 이번 회차 T2와 7일 전 같은 시각 T2 비교 | 최신 회차 | 두 회차 모두 유효 | 7일 누적 후 |
| T5 | 함께 쓴 게임 | 그 태그를 단 방송에서 가장 많은 게임 | 최신 회차 / 7일 | — | 태그 저장 후 |
| T6 | 채널 자주 쓰는 태그 | 기간 내 채널 방송(5.4)별 태그 등장 횟수와 그 방송들의 M3 | 기간 | — | 태그 저장 후 |

화면: 통계 페이지 "방송 태그 순위" 섹션(T1·T2·T4), 태그 선택 시 태그 채널 목록 페이지(7.3-1: T1~T5와 해당 채널 목록), 개인 채널 페이지 "자주 쓰는 태그"(T6).

### 6.6 오늘의 흐름 규칙

최신 유효 회차와 직전 회차에 같은 규칙을 적용해 **정각 2회차 연속(1시간 이상) 성립**할 때만 표시한다. 최대 3개, 규칙마다 1개, 흐름이 차지하는 시청자 비율이 큰 순.

| ID | 유형 | 성립 조건 | 문장 틀 |

| E2 | 게임 급등 | 게임 G1이 1시간 전보다 50% 이상, 평소(5.6)보다 30% 이상 많고 G1 ≥ 3,000명 | 지금 「{게임}」 시청자가 평소보다 {P}% 많아요 |
| E3 | 1인 독주 | G2 = 1인 게임에서 시청자 5,000명 이상 | 「{게임}」은 한 채널이 {V}명을 혼자 모으고 있어요 |

### 6.7 지금 상황 정리 (자동 요약 문단)

통계 페이지, 게임 상세, 태그 채널 목록의 제목 아래에 1~3문장 문단 하나를 둔다. 상자, 라벨, 글머리표는 쓰지 않는다. 숫자와 이름만 굵게 한다.

1. **사실 추출 (서버, 규칙)**: 정각 회차 확정 직후 페이지별 사실 묶음(JSON)을 만든다.
   - 소속 채널 수(지금/평소). '대형·소속사' = 5.8 기준 공식 소속이 확인된 채널이다.
   - 상위 3개 채널의 시청자 비중
   - G3 방송당 시청자의 평소 대비 배수, G4 경쟁 판단
   - 덜 붐비는 시간대(G9에서 방송당 시청자가 가장 높은 연속 3시간)
   - 성립한 흐름(E1~E3)
2. **문장 작성 (AI)**: 사실 묶음만 입력으로 주고 1~3문장을 쓰게 한다. 입력에 없는 숫자, 이름, 추측을 넣지 않는다. "피해야 한다"처럼 단정하는 말 대신 "~가 상대적으로 여유로워요"처럼 근거를 붙인 표현을 쓴다.
3. **검증 (서버)**: 문장에 나온 숫자와 이름이 모두 사실 묶음에 있는지 확인한다. 실패하면 정해 둔 문장 틀(6.6 형식)로 대신한다.
4. 갱신: 매시 정각 회차 확정 후 1회 작성해 다음 정각까지 저장한다. 호출 수는 1시간에 약 31회다(전체 1 + 게임 상위 10 + 태그 상위 20).
5. 숨김: 사실 묶음에 쓸 만한 항목이 2개 미만이면 문단을 숨긴다.

| 통계 페이지 | `/analytics` (플랫폼 선택: `?platform=chzzk`·`soop`) | 플랫폼 판도와 게임 순위, 실시간 채널 순위 | 노출 |
| 게임 상세 (통계 페이지 하위) | `/analytics/game/{통합 게임 ID}` | 한 게임의 추이·시간대·상위 채널 | 7일 평균 G1 ≥ 1,000명일 때 노출 |
| 개인 채널 페이지 | `/analytics/channel/{플랫폼}:{채널 ID}` (기존 `/analytics/streamer/...`는 이 주소로 이동) | 한 채널의 기록 분석 | 30일 기록 방송 시간 ≥ 10시간일 때 노출 |
| 태그 채널 목록 (통계 페이지 하위) | `/analytics/tag/{태그}` | 한 태그의 추이와 그 태그를 쓴 채널 목록 | 7일 평균 T1 ≥ 5개일 때 노출 |
| 집계 기준 | `/analytics/method` | 4~6장을 사용자 말로 공개, 마지막 집계 시각과 수집 범위 | 노출 |

공통:
- 플랫폼·기간 선택은 주소에 남겨 공유·뒤로 가기에서 그대로 유지한다.
- 오른쪽 위 "집계 기준" 링크는 두지 않는다. 집계 기준은 통계 페이지 맨 아래 한 줄 안내와, 기록이 없을 때의 안내 문구에서만 연결한다.
- **대시보드 수치는 표 대신 그래프로 보여 준다.** 양(시청자)은 막대, 개수(방송 수)는 선으로 겹쳐 그린 막대+선 그래프가 기본이다. 순위 목록은 줄마다 시청자 막대를 함께 그린다. 표는 개인 채널 페이지 '방송 기록'처럼 기록을 읽는 곳에만 쓴다.

### 7.5 이동 흐름

| 흐름 | 경로 |
|---|---|
| A. 게임 검색 유입 | 검색 "[게임] 방송 순위" → 게임 상세 → 상위 채널 → 개인 채널 페이지 → 방송 보기 |
| B. 대시보드 탐색 | 통계 페이지 → 플랫폼 현황 → 인기 게임 순위 → 게임 상세 → 개인 채널 페이지 |

| D. 실시간 확인 | 통계 페이지 → 실시간 채널 순위 → 방송 보기 (또는 개인 채널 페이지) |
| E. VDébut 연결 | 버튜버 소개 페이지 ↔ 개인 채널 페이지 (소개가 있는 채널만) |

## 9. 결정이 필요한 것

1. **공식 API 애플리케이션 등록**: 치지직 개발자 센터(developers.chzzk.naver.com)와 SOOP 개발자 센터(developers.sooplive.co.kr)에 VDébut 애플리케이션을 등록하고 키를 발급받아야 한다. 계정 소유자가 직접 등록해야 한다.
2. **공통 수집 범위 N**: 플랫폼별 시청자 순 상위 몇 개까지 볼지. N=100이면 정각마다 치지직 5회·SOOP 2회 요청, N=300이면 치지직 15회·SOOP 5회.
3. ~~플랫폼 로고 사용 허락~~ → 허락 완료(5.7). 원본 파일 사용.
4. **게임 순위 제외 목록**: 게임 분류 안의 "종합 게임"류 카테고리 중 제외할 것.
5. **경쟁 판단·급상승 수치**: 1.5배·0.67배, 30%·1,000명 — 2주 실제 분포를 본 뒤 확정.
6. **지금 상황 정리(6.7) 도입과 월 비용 범위**: AI 호출 비용 승인.

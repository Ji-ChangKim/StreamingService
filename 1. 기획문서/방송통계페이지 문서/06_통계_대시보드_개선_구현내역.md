# 방송 통계 대시보드 개선 구현 내역

작성일: 2026-10-05  
기준: `05_대시보드_개선_기획보고서.md`의 우선 구현 항목  
상태: 로컬 구현·검증 완료, 운영 배포 및 원격 인덱스 적용 전

## 목적과 사용자 흐름

통계 메인에서는 확인된 채널들이 언제, 어떤 카테고리로 방송했는지 살펴본다. 개인 화면은 검색하거나 프로필에서 선택한 채널의 방송 이력을 조회한다. 개인 통계는 로그인한 사람의 전용 화면이 아니다.

전체 방송 통계 → 기간·플랫폼·카테고리 선택 → 시간대 또는 날짜 선택 → 해당 방송 이력 → 채널 선택 → 개인 방송 통계로 이어진다. 검색 결과에서는 플랫폼과 채널을 확인해 개인 통계로 들어간다. 프로필에서는 대표 채널뿐 아니라 각 공식 채널의 통계로 진입할 수 있다.

## 화면 변경

| 영역 | 구현 내용 |
| --- | --- |
| 메인 요약 | 활동 채널(개), 방송 횟수(회), 총 방송 시간, 방송 카테고리(개) |
| 개인 요약 | 방송일 수, 방송 횟수, 총 방송 시간, 평균 기록 시간 |
| 공통 필터 | 최근 7·30·90일, 최대 90일 직접 조회, 플랫폼, 전체 카테고리 선택기, 조건 초기화 |
| 시간대별 방송 현황 | 방송 활동·방송 시작 전환, 요일·시간 클릭으로 해당 방송 이력 조회 |
| 카테고리별 방송 통계 | 플랫폼별 고유 카테고리 구분, 시간·횟수 전환, 전체 항목 펼치기 |
| 방송 활동 추이 | 날짜 클릭으로 방송 이력 조회 |

| 방송 이력 | 최근 기록순, 25개 단위 추가 조회, 선택 조건 표시·해제, 상세 기록 펼치기 |
| 모바일 | 표 대신 방송 카드, 제목·카테고리·시간·상세 기록 표시 |
| 검색 | 플랫폼별 조회, 15초 시간 제한, 실패·재시도, 동명이인 채널 구분 |
| 복귀 | 검색 결과·전체 통계의 조건과 읽던 위치 복원, 프로필 진입 시 프로필 복귀 |

시간대·날짜 선택은 방송 이력에만 적용한다. 기간 전체의 요약과 차트는 유지하며, 새 선택이 이전 선택을 대체한다. 선택 조건은 공유 주소와 새로고침, 브라우저 뒤로가기로 복원한다.

카테고리는 선택하더라도 다른 카테고리로 이동할 수 있도록 기간·플랫폼·채널에 해당하는 전체 선택 항목을 유지한다. 같은 이름의 치지직·SOOP 카테고리는 합치지 않는다.

## 집계와 동작 원리

- 채널은 플랫폼과 채널 고유 ID로 구분하며 사람 수로 표현하지 않는다.
- 방송 카테고리 수는 플랫폼별 카테고리 고유 ID를 사용하고 미분류는 제외한다.
- 방송 활동 시간대의 이력은 실제 관측 기록으로 조회한다. 최초·최종 기록 사이의 수집 공백을 방송 활동으로 추정하지 않는다.
- 방송 시작 시간대는 실제 시작 시각이 확인된 방송만 조회한다. 최초 관측 시각을 시작 시각으로 대체하지 않는다.
- 같은 방송의 연속 기록 간격이 15분 이내인 구간만 방송 시간으로 합산한다. 한국 시각 자정을 넘는 구간은 날짜별로 나눈다.
- 평균 기록 시간은 기록 시간 합계를 조회된 방송 횟수로 나눈 값이다. 수집 공백 때문에 실제 전체 방송의 평균 길이와 다를 수 있음을 안내한다.
- 전체 플랫폼의 시간대 평균은 치지직·SOOP의 기록이 모두 있고 부분 수집이 아닌 회차만 포함한다. 누락된 플랫폼을 0으로 합산하지 않는다.
- 확인된 빈 회차는 0으로 표현하고, 기록 없는 시간·날짜와 API 실패는 구분한다. 부분 수집은 조회 범위 안내에 표시한다.
- 페이지 추가 조회는 최초 조회 시점으로 기록 범위를 고정한다. 최근 관측 시각·플랫폼·채널·방송 ID를 정렬 경계로 사용해 같은 시각의 기록도 누락·중복 없이 조회한다.

## 주소와 API

- 요약: `GET /api/analytics/activity`.
- 목록: `GET /api/analytics/activity/broadcasts`.
- 공통 조회 조건: `from`, `to`, `platform`, `channel`, `category`.
- 날짜 선택: `day=YYYY-MM-DD`.
- 시간대 선택: `weekday=0..6`, `hour=0..23`, `timeMetric=activity|starts`.
- 목록 페이지: 응답의 `nextCursor`, `asOf`를 다음 요청의 `cursor`, `asOf`로 전달한다.
- 카테고리 주소 값은 플랫폼과 카테고리 ID의 조합이다. 기존 이름 방식의 필터도 서버에서 지원한다.
- 검색 플랫폼: `GET /api/analytics/streamers/search`의 `platform=ALL|CHZZK|SOOP`.
- 개인 통계의 `back`은 검색 결과·전체 통계·프로필의 내부 주소만 허용한다.
- 채널 조회용 인덱스는 `0035_broadcast_activity_channel_index.sql`에 추가했다. 원격 DB에는 적용하지 않았다.

## 검증

- 실제 SQLite에서 운영 서비스 SQL을 실행한 집계 테스트 9개: 플랫폼 합산, 카테고리 변경, 개인 조회, 빈 기간, 날짜·채널 검증, 실제 시간대 선택, 207개 방송 페이지 조회, 자정 분리, 누락된 플랫폼·부분 수집 처리, 미분류 제외.
- 기존 검색 테스트: 플랫폼 필터, 25개 결과 제한과 추가 결과 여부, 검색어 바인딩, 채널 중복 방지.
- 프론트엔드 프로덕션 빌드, 백엔드 TypeScript 검사.
- 로컬 Chrome: 전체 통계·검색·프로필·공유 주소 진입, 플랫폼별 동명이인 선택, 7·30·90일 조회, 카테고리 선택 항목 유지, 시간대·날짜 선택, 선택 주소 새로고침, 상세 펼치기, 이전 화면 복귀, 실패·재시도, 25→50개 목록 추가 조회와 선택 변경 시 목록 초기화.
- 1440px·390px·320px 화면에서 배치와 페이지 가로 넘침 확인.

브라우저 검증에는 테스트 세션에서만 실제 집계 SQL의 테스트 데이터를 API 응답으로 주입했다. 서비스 코드에 예시 수치나 실패 시 대체 데이터를 포함하지 않는다. 운영 데이터 조회와 배포는 수행하지 않았다.

## 이후 범위

이번 구현은 P0·P1의 기본 탐색 흐름과 P2의 전체 카테고리·200개 이후 이력 조회를 포함한다. 주별·월별 콘텐츠 구성 변화, 이전 기간 비교, 독립 회차 상세 페이지는 후속 범위로 남긴다. 전체 수집 품질의 날짜별 상세 표시와 운영 환경에서의 대량 기록 성능은 운영 데이터로 추가 확인한다.

## 색상 개선

사용자 요청에 따라 색의 의미를 설명하는 문장은 추가하지 않았다. 요약 카드의 작은 상단 선과 아이콘에 지표별 강조색을 적용했고, 본문 수치는 같은 명도를 유지했다. 카테고리는 플랫폼·카테고리 고유 키에 따라 색을 고정해 기간·정렬·전체/개인 화면 전환 시 같은 색을 사용한다. 항목명 옆 점과 막대는 같은 색이며 미분류는 회색이다.

방송 활동은 청록색 농도, 방송 시작은 보라색 농도로 표현한다. 일별 활동 막대와 활동 달력도 청록색을 사용한다. 기록 없음은 회색 빗금, 일부 누락은 기존 문구의 주황색 배지로 구분한다. 선택한 필터·날짜·시간대는 공통 파란색 테두리로 표시하고, 개인 화면에는 작은 보라색 상단 선을 적용했다. 플랫폼 공식 로고와 색은 유지했다.

수정 파일은 `ActivityDashboard.tsx`, `activityDashboard.css`와 본 구현 내역 문서다. 기존 사용자 흐름의 브라우저 검사와 1440px·390px·320px 화면 검증, 프론트엔드 빌드로 확인한다.

## 실시간 방송 랭킹·카테고리 순위 추가

메인 대시보드의 기간별 통계 위에 실시간 방송 랭킹과 실시간 카테고리 순위를 추가했다. 두 영역은 조회 기간과 독립적으로 현재 방송 기록만 사용한다. 개인 화면과 검색 결과 화면에서는 표시하지 않는다.

- 방송 랭킹: 현재 시청자 수 내림차순, 동률은 방송 고유 ID 순으로 정렬한다. 순위·채널명·방송 제목·플랫폼·카테고리·시청자 수를 표시하며 방송 보기는 공식 라이브 주소로 연결한다.
- 채널명 선택: 공개 채널 고유 키로 개인 통계에 진입하고 이전 순위의 조건으로 복귀한다. 검색이나 등록 요청을 추가로 보내지 않는다.
- 카테고리 순위: 플랫폼별 카테고리 ID로 시청자 수 합계와 방송 채널 수를 계산하고 두 지표로 정렬한다. 선택한 지표의 수치를 우측에 표시한다.
- 카테고리 선택: 실시간 방송 랭킹만 해당 카테고리로 좁힌다. 기간별 요약·차트·이력은 바꾸지 않는다. 선택 해제와 추가 항목 조회를 제공한다.
- 실시간 플랫폼: 전체·치지직·SOOP 조건은 별도로 제공하며 `livePlatform`, `liveCategory`에 보존한다. 기간별 조회 조건을 바꿔도 유지하고 공유·새로고침·뒤로가기로 복원한다.
- 갱신: 기존 `GET /api/analytics/broadcast-statistics`와 `useBroadcastStatistics`를 사용한다. 화면이 보일 때 60초마다 재조회하며, 수집 시각은 KST로 표시한다. API 재조회 간격과 원본 수집 간격은 동일한 개념이 아니다.
- 기록 상태: 플랫폼별 수집 시각이 15분보다 오래되었거나 원본 조회가 불가능한 경우 해당 플랫폼을 순위에서 제외한다. 갱신 지연·확인 불가·부분 기록은 짧은 상태 배지로 표시한다. 재조회 실패 시 이전 순위를 현재 순위로 유지하지 않고 오류·재시도를 제공한다.
- 색상: 기존 기간별 카테고리와 같은 키에 같은 색을 적용한다. 색의 의미에 대한 설명 문장은 추가하지 않았다.

새 파일은 `ActivityLiveRankings.tsx`와 공통 카테고리 색상 함수 `activityColors.ts`다. 대시보드 진입점과 CSS, 본 문서를 수정했다. 새로운 백엔드 API나 DB 마이그레이션은 필요하지 않다.

검증에는 시청자 수 순위, 카테고리 합산·정렬 전환, 플랫폼·카테고리 선택, 기간 변경과 새로고침 시 실시간 조건 유지, 개인 통계 진입·복귀, 지연·오류·재시도, 60초 자동 조회, 320px·390px 배치를 포함한다. 브라우저 검증의 수치는 테스트 세션 전용 데이터이며 서비스에 포함하지 않는다. 기존 집계·사용자 흐름 검증과 프론트엔드 빌드도 실행한다. 운영 배포는 수행하지 않았다.

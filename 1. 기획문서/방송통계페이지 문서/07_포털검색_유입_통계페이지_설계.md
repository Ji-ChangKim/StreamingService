# 포털 검색 유입을 위한 방송 통계 페이지 설계

작성일: 2026-10-06
상태: 구상·계획·설계. 구현 및 배포는 이번 단계에서 수행하지 않는다.

## 목적과 목표

네이버·구글에서 버튜버 방송 통계와 특정 스트리머의 방송 기록을 찾는 사용자를 해당 정보로 직접 연결한다. 검색 상위 노출을 목표로 하되 1위나 달성 시점을 보장하지 않는다. 대표 검색어와 스트리머별 검색어를 구분해 노출·클릭·실제 이용 성과를 측정한다.

사용자는 메인에서 지금 방송 중인 채널과 시간대·카테고리별 활동을 보고, 스트리머를 검색해 개인의 방송 이력과 활동을 확인한다. 개인은 로그인 사용자가 아니라 검색·링크로 조회한 스트리머다.

## 현재 구조에서 확인한 문제

- App.tsx에서 통계 제목·설명을 브라우저 실행 후 변경한다. 초기 index.html에는 캘린더 제목·설명과 홈 canonical이 있다.
- backend/src/index.ts의 사이트맵 생성부에는 홈·언어·등록·크리에이터 주소가 있으며 통계 주소가 없다. 중복 사이트맵 라우트도 있어 통합 전 실제 활성 응답을 검증해야 한다.
- 스트리머 통계로 이동하는 검색 결과는 버튼 이벤트 중심이다. 검색로봇이 발견할 수 있는 실제 href 링크가 필요하다.
- 운영 통계가 메인·개인으로 분리되어 있지만 초기 HTML의 페이지별 본문과 검색 메타데이터는 별도 설계가 필요하다.
- 현재 보유 기록만 노출한다. 검색 노출을 위해 빈 개인 페이지나 카테고리·기간 조합을 대량 생성하지 않는다.

## 검색 의도와 진입 주소

검색어는 검색량을 확인한 결과가 아닌 초기 검증 후보다. Search Console·서치어드바이저 데이터를 확보한 후 우선순위를 조정한다.

| 검색 의도 | 후보 검색어 | 도착 페이지 | 첫 행동 |
|---|---|---|---|
| 전체 활동 탐색 | 버튜버 방송 통계, 버튜버 방송 시간대 | /analytics | 시간대·카테고리 확인 |
| 플랫폼 활동 탐색 | 치지직 버튜버 통계, SOOP 버튜버 통계 | 플랫폼 전용 통계 주소 | 해당 플랫폼 방송 확인 |
| 특정 스트리머 탐색 | [스트리머명] 방송 통계, [스트리머명] 방송 기록 | /analytics/streamer/:channelKey | 방송 이력 확인 |
| 콘텐츠 탐색 | [카테고리명] 버튜버 방송 | 카테고리 전용 주소: 후속 단계 | 방송·스트리머 확인 |

대표 /analytics를 유지한다. 플랫폼 전용 주소는 /analytics/chzzk, /analytics/soop를 제안하며 기존 쿼리·공유 주소와 호환한다. 새로운 주소는 각기 해당 플랫폼의 실제 본문을 제공할 때만 검색 대상으로 연다.

## 메인 구성

1. 헤더: 방송 통계 제목, 넓은 스트리머 검색 입력, 플랫폼 선택.
2. 실시간 방송 랭킹·실시간 카테고리 순위: 현재 방송 확인, 채널명은 개인 통계 링크, 방송 보기는 공식 방송 링크.
3. 기간 선택과 활동 요약: 7·30·90일, 직접 기간, 방송 채널·횟수·시간·카테고리.
4. 시간대별 방송 현황·카테고리별 방송 통계: 활동을 비교하고 항목 선택으로 기록 조회.
5. 방송 활동 추이·방송 이력: 날짜 선택, 기록 상세, 추가 목록 조회.

모바일은 제목→검색→플랫폼→방송 순위→카테고리 순위→기간·요약→차트→이력 순서로 쌓는다. 첫 화면은 큰 소개 영역 없이 검색과 방송 탐색을 시작할 수 있게 한다. 긴 차트는 자체 스크롤을 사용한다.

## 개인 구성

1. 스트리머명·플랫폼·사진, 채널 바로가기, 전체 통계/검색 결과 복귀.
2. 기간과 활동 요약: 방송일·방송 횟수·방송 시간·평균 기록 시간.
3. 방송 활동 달력, 시간대별 방송 현황, 카테고리별 방송 통계.
4. 방송 이력: 제목·카테고리·방송 시작·기록 시간, 상세 기록.
5. 프로필·공식 채널 연결과 현재 조건 공유.

동명이인은 이름과 플랫폼·채널 고유 키로 구분한다. 새로고침·직접 검색 유입에서도 스트리머명이 먼저 표시되어야 한다.

## 사용자 흐름

- 포털 전체 검색→메인→시간대/카테고리 선택→방송 이력→개인 통계→공식 방송.
- 포털 스트리머 검색→개인 통계 직접 진입→기간 선택→달력/이력 확인→공식 채널.
- 메인 검색→이름·플랫폼 확인→개인 통계→이전 검색 조건·위치로 복귀.
- 크리에이터 프로필→방송 통계→프로필 복귀.

선택 조건은 URL에 보존한다. 검색창 내부 검색 결과 자체는 검색엔진 색인 대상에서 제외하고, 기록이 충분한 개인 통계 링크로 연결한다.

## 디자인과 텍스트

- 여백·얇은 구분선·표 중심으로 구성한다. 둥근 외곽 카드, 큰 그라데이션 소개 영역, 플랫폼 순위는 추가하지 않는다.
- 카테고리별 색상과 지표별 색상, 선택 표시를 유지한다. 색상을 해설하는 문단은 추가하지 않는다.
- 화면은 제목·지표·단위·조건·갱신 시각 중심으로 쓴다. 수집 범위나 시스템 동작에 대한 면책성 설명은 노출하지 않는다.
- 필수 오류·기록 없음·부분 기록 상태는 짧게 유지한다. 기록 없음을 방송하지 않은 것으로 표시하지 않는다.

| 위치 | 텍스트 예시 |
|---|---|
| 메인 검색 제목 | 버튜버 방송 통계 · 치지직·SOOP | VDébut |
| 메인 검색 설명 | 버튜버의 방송 시간대와 카테고리, 방송 이력을 확인하세요. 스트리머를 검색해 개인 방송 통계를 조회할 수 있습니다. |
| 개인 검색 제목 | [스트리머명] 방송 통계 · [플랫폼] | VDébut |
| 개인 검색 설명 | [스트리머명]의 방송 이력과 활동 시간, 카테고리별 기록을 확인하세요. |
| 화면 제목 | 방송 통계 / [스트리머명] 방송 통계 |
| 검색 | 스트리머 검색 |
| 차트·목록 | 시간대별 방송 현황 / 카테고리별 방송 통계 / 방송 이력 |

검색 설명은 메타데이터다. 화면에 같은 설명을 반복 배치하지 않는다. 기간 밖 기록이 없으면 ‘전체 방송 경력’을 제공한다고 쓰지 않는다.

## 기술 설계

1. 초기 HTML: Cloudflare Worker에서 통계 주소를 식별해 실제 집계 데이터와 제목·본문·링크를 반환한다. 브라우저와 검색로봇 모두 같은 정보를 받는다. 구현 방식은 기존 React 구성요소의 서버 렌더링과 초기 데이터 전달을 우선 검토한다.
2. 인터랙션: 초기 데이터로 시작하고 필터·시간대 선택·자동 갱신은 현재 React/API 구조를 이어 사용한다. 초기 데이터와 화면 재조회 조건이 어긋나지 않게 한다.
3. 메타데이터: 페이지별 title·description·canonical·OG를 서버와 브라우저에서 일치시킨다. 메인/개인 제목을 서로 다른 effect가 덮어쓰지 않도록 한 경로에서 관리한다.
4. 링크: 검색 결과·방송 이력의 스트리머명·프로필·플랫폼 이동은 href가 있는 링크로 제공한다. 차트 지표 전환과 필터 실행은 버튼으로 유지한다.
5. 색인: 메인·실제 콘텐츠가 있는 개인·플랫폼 페이지를 허용한다. 내부 검색·임의 기간/정렬/커서 조합은 별도 검색 페이지로 늘리지 않는다. 색인 제외 쿼리와 canonical 정책은 의도별로 분리하고 크롤러가 noindex를 읽을 수 있게 한다.
6. 빈 페이지: 존재하지 않는 채널은 404. 존재하지만 기록이 없는 채널은 사용자에게 정상 빈 화면을 제공하고, 유의미한 콘텐츠가 생기기 전 noindex로 운영한다. API 일시 장애를 기록 없음으로 바꾸지 않는다.
7. 사이트맵: 콘텐츠가 있는 대표 통계 주소를 추가한다. lastmod는 실제 자료 변경을 반영한다. 개발 사이트에는 서버 응답의 X-Robots-Tag와 HTML noindex를 적용하고 운영 사이트맵에 넣지 않는다.
8. 구조화 데이터: 실제 내용과 일치하는 WebPage·BreadcrumbList를 검토한다. 개별 프로필의 Person 정보는 확인 가능한 항목만 사용한다. 구조화 데이터가 순위나 특별 검색 노출을 보장한다고 보지 않는다.
9. 성능: 초기 응답은 요약과 첫 목록으로 제한한다. 목록은 현재 페이지 조회를 유지하고 기간별 집계를 짧게 캐시한다. 자동 갱신과 90일 집계 요청을 분리한다. 이미지 크기를 고정하고 통계 전용 코드 분할을 검토한다.

## 제작 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| P0 검색 기반 | 서버 메타·초기 본문·canonical·사이트맵·링크·dev noindex | JS 없이 제목·스트리머명·실제 요약·통계 링크 확인, 페이지별 대표 주소 일치 |
| P1 화면 완성 | 첫 화면 검색, 메인/개인 정보 배치, 모바일 흐름 | 전체/개인 직접 진입과 조건 복원, 키보드·모바일 사용 확인 |
| P2 검색 유입 확장 | 플랫폼 전용 주소, 콘텐츠 있는 개인 페이지 발견 경로 | 빈/중복 페이지 제외, 각 URL 고유 데이터·메타 확인 |
| P3 성과 개선 | 검색어별 노출·클릭과 이용 행동 검토 | 실제 수치로 개선 우선순위 결정, 검색 제목·진입 흐름 조정 |

네이버 서치어드바이저·Google Search Console의 기존 연결 여부를 먼저 확인한다. 계정 소유 확인·등록 작업은 소유자의 접근 권한이 필요할 수 있다. 구현 완료와 검색 순위 달성은 별도 상태로 보고한다.

검색 성과는 검색엔진·검색어·기간을 나눠 노출수, 클릭수, 클릭률, 확인 가능한 게재 순위를 기록한다. 페이지 이용은 검색 성공·개인 통계 진입·기록 조회·공식 방송 이동을 측정한다. 초기 기준값을 확보한 뒤 수치 목표를 정하며, 추적 이벤트에는 검색어 원문을 무조건 전송하지 않는다.

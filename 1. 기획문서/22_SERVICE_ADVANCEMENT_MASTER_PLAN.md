## 1 이번 고도화의 결론

**신규 버튜버가 지속적으로 발견되고, 그 사람의 확인된 정보와 활동이 쌓이는 체계를 먼저 만든다.** 초기에는 자발적 등록을 기다리지 않고 우리가 먼저 찾아 기본 소개를 제공한다. 이후 본인 등록·팬 제보도 같은 데이터 처리 체계에 연결한다.

지금의 최우선 문제는 신규 발굴의 어려움과 데이터 부족이다. 추천·재미 기능을 먼저 만들어도 보여 줄 자료와 선택 근거가 부족하면 가치가 생기지 않는다. 우선순위는 **발굴 → 식별·근거 확보 → 기본 보강 → 공개 → 지속 갱신 → 정보 기반 탐색·재방문**이다.

장기 중심 자산은 한 사람의 공식 채널·소개·작품·활동이 계속 쌓이는 대표 페이지다. 팬은 **발견 → 알아가기 → 관심 저장 → 다음 활동 확인**을 경험한다. 정보의 질이 이 흐름의 전제이며, 재미는 새로운 사람과 콘텐츠를 이해하고 관심 대상의 변화를 확인하는 데서 생긴다.

## 4 가장 먼저 만들 정보 공급 체계

### 4.1 발굴은 우리가 먼저 수행

첫 집중 대상은 한국 치지직·SOOP 신인이다. 기존 조사 파일·공개 시트·허용된 공식 일정 외에 치지직 방송 목록과 채널 키워드 검색으로 모르는 채널 ID를 찾는다. 방송 전 준비생은 접근 가능한 외부 공개 홍보·지정 공식 공지의 채널 주소로 보완한다. 채널 조회 API는 알려진 후보의 보강 수단이며 신규 인물을 전부 찾아 주는 목록 API로 가정하지 않는다.

SOOP 공식 일정 조사에 사용한 공개 응답은 영구적으로 이용 가능한 공식 개발자 API라고 단정하지 않는다. 치지직 전체 신규 버튜버 목록이 확보됐다고 전제하지 않는다. 외부 권한·단가 확인은 향후 해당 연결 실행 시 처리하며, 현재 새 외부 조사는 하지 않는다.

현재 로컬 치지직 목록은 인기순 최대 100개·채널 검색은 첫 페이지 중심이다. 조회 범위 확대·검색어별 반복 탐색·채널 키 중복 대조를 개발하되, 검색 대상 필드·필터·페이지 지원·권한은 실행 단계에서 확인한다. 새로 발견한 채널과 최초 데뷔가 확인된 신인을 구분하며 인기순 탐색만으로 소규모 채널 전수 포착을 보장하지 않는다. 세부 경로·자동/직접 경계는 32번 3.1~3.3을 따른다.

### 4.2 인물·행사·근거·공개를 분리

일정을 모르는 신인을 버리지 않는다. 인물 후보와 데뷔/이적/모델 공개 등의 행사를 별도로 보관한다. 소개 최소 정보가 있으면 인물 공개를 판단하고, 정확한 일정이 있으면 기존 캘린더에 연결한다. 날짜·국가·소속을 기본값으로 만들어 채우지 않는다.

수집은 후보를 만들고, 정규화·채널 확인·출처 대조로 보강한다. 출처와 항목이 허용되고 최소 공개 조건을 모두 충족한 정형 후보는 자동 공개 대상으로 설계한다. 충돌·주요 변경·동일 인물 판단은 예외 검토로 보낸다. 모든 후보를 매번 사람이 처음부터 다시 조사하는 구조로 고정하지 않는다.

### 4.3 사람이 채운 정보를 수집이 덮어쓰지 않음

공식 채널 ID·근거·값·확인일을 연결하고, 수동 확정/잠금과 변경 제안을 구분한다. 자동 수집과 본인 등록·팬 제보는 동일 후보·근거·변경 이력으로 들어온다. 본인 주장과 소유권 확인은 분리하며, 기존에 제외한 소유권 관리 화면을 이번에 되살리지 않는다.

### 4.4 수집 이후의 유지가 출시 범위

출처별 마지막 성공·커서·오류·호출 한도·다음 확인, 후보 중복 방지, 반영 전 상태 재확인, 재실행 안전성, 중지·복구·삭제/재수집 차단을 처음부터 설계한다. 첫 수집만 되고 다음 달에 전부 오래된 정보가 되는 기능은 완성으로 보지 않는다.

## 5 어떤 정보를 먼저 채울 것인가

1. **누구인가:** 확인된 활동명·공식 채널·짧은 사실 소개·근거. 허용된 이미지가 없으면 공통 기본 이미지.
2. **무엇을 하는가:** 공식 소개·작품으로 확인되는 콘텐츠와 언어. 이름·외형·채팅량으로 추론하지 않음.
3. **무엇부터 볼 것인가:** 본인 지정/근거 있는 소개·대표 콘텐츠 우선. 없으면 최근 영상과 공식 채널을 정확한 이름으로 제공.
4. **무엇이 달라졌는가:** 날짜와 원문이 있는 활동·일정·수정. 과거 자료 첫 연결과 실제 새 공개를 구분.
5. **더 알아볼 것:** 설정·팬덤·제작자·공식 팀/협업은 근거가 확보되는 순서로 확장.

소개는 공통 템플릿과 확인된 필드로 구성한다. 매 인물의 아트·카피·영상 선정 작업을 운영자가 반복해야 하는 구성을 필수로 넣지 않는다. API 자료가 부족하면 미확인을 유지하며 AI 창작으로 보완하지 않는다.

## 6 첫 출시에서 제공할 모습

관리 측면에서는 후보가 유입되고, 중복이 걸러지며, 최소 소개가 보강·공개되고, 이후 변경과 예외를 확인할 수 있다. 기존 도감·상세에서는 확인된 소개·공식 채널·입문/최근 자료·일정을 같은 데이터로 보여 준다.

현재의 검색·필터·관심 저장·공유를 유지한다. '오늘의 발견' 신규 추천 화면과 관심 변화 피드 확대는 정보 공급 체계 이후로 옮긴다. 추천이 없다는 이유로 발굴·보강 기반의 첫 출시를 미루지 않는다. 반대로 수집 숫자만 늘고 볼 내용이 없으면 성공으로 보지 않는다.

## 7 단계별로 어떤 사이트가 되는가

| 단계 | 사이트의 모습 | 먼저 할 일 | 다음 단계로 남는 자산 |
| --- | --- | --- | --- |
| 1 정보 공급 | 우리가 먼저 신인을 찾아 확인된 소개를 제공하는 곳 | 발굴·식별·근거·자동 보강·조건부 공개·지속 갱신·예외 운영, 기존 상세 노출 | 안정적인 인물/채널 ID·근거·입문 정보·수집 연결 |
| 2 정보 활용 | 알아보고 관심 대상의 변화를 확인하는 곳 | 대표/최근 자료 구분 강화·공통 활동·관심 변화·근거 있는 탐색 | 활동 축적·이용 흐름·자료 보유 수준 |
| 3 참여 확장 | 본인과 팬이 같은 소개를 보완하는 곳 | 기존 등록/제보 마찰 감소·중복 방지·보호값·공식 관계·복수 채널 연결 | 더 깊은 소개·정정·장기 활동 이력 |
| 4 팬 활동 입구 | 여러 플랫폼에서 다음 최애를 찾고 계속 알아가는 곳 | 국가/플랫폼 확장·출처 있는 관계 탐색·자동 활동 돌아보기·필요 시 계정 동기화 | 팬·버튜버가 함께 유지하는 정보 기반 |

본인 등록·팬 제보의 기존 기능은 1단계부터 유지한다. 3단계는 참여를 주된 보강 경로로 발전시키는 단계이며 그전까지 신청을 막는다는 뜻이 아니다. 자발 참여가 늘어도 자동 발굴·갱신은 유지한다.

## 8 정보에서 생기는 유입과 재방문

첫 방문: 캘린더·검색·공유 주소 → 사실 소개와 작품으로 인물 이해 → 공식 방송/영상 이동 또는 관심 저장.

재방문: 좋아하는 인물의 새 작품·공식 일정·정정·기록을 확인 → 실제 콘텐츠·공식 그룹/협업의 근거를 따라 다른 인물까지 탐색. 매일 새 소식이 있다고 만들거나 방문을 강제하지 않는다.

도감 추천은 조건·특징·대표 자료의 근거가 쌓였을 때 도입한다. 날짜별 랜덤 인물 교체를 핵심 경쟁력으로 내세우지 않는다. 주식·예측·카드깡·채팅 분위기·OBS 도구는 현재 공급 문제의 해결책에 넣지 않는다.

## 9 숙제·개발 순서·완료 판단

**D0 현황/정책 → D1 인물·채널·후보·근거 → D2 수집 연결 → D3 자동 보강 → D4 공개 판정·반영·복구 → D5 갱신·예외·상한 → D6 기존 도감·상세 노출** 순서다. 상세 산출물·담당·완료 기준은 [24번 개발 목록](./24_ADVANCEMENT_BACKLOG_AND_COST.md)을 따른다.

지금 작성한 것은 계획이며 개발 과제는 미착수다. 기존 후보의 현재 상태 조회, 출처 권한·요금 확인, 실제 반영은 향후 실행 범위가 열렸을 때 한다. 일정은 착수 후 의존성과 실제 연결 난도를 보고 정한다.

성공 판단은 유효 새 인물 수·출처별 기여/중복·입문 자료 보유율·발견→공개 시간·오래된 정보 비율·직접 검토 시간·실제 비용이다. '상위 5위'는 장기 사업 목표이며 전수 포착·순위 상승·팬 증가를 현재 수치로 예측하지 않는다.

## 10 비용·성능·수익 원칙

기존 Worker·D1·조회·등록·관리자 기능을 우선 활용한다. 인건비는 비용표에서 제외한다. 유료 X 검색·SSAPI·상시 채팅 서버·벡터 DB·외부 AI·외주 아트는 첫 출시 필수 비용이 아니다. 개정 후 초기 월 수집 요청은 14,800회·확장 91,993회 가정이다. 기존 내부 순증 월 1만원·확장 월 3만원은 검토 기준선으로 보존하지만 추가 탐색 반영 후 수용 여부는 미확인이다. 실제 청구/공식 단가가 아니다. 계산 조건과 미확인 계정 항목은 [24번 비용 계획](./24_ADVANCEMENT_BACKLOG_AND_COST.md)에 명시한다.

수집과 공개 조회를 분리해 방문 시 수집이 실행되지 않게 한다. 변경분만 저장하고 목록은 요약·페이지 단위로 제공한다. 실제 성능·DB 과금 행은 향후 측정한다. 기존 비용·통계 작업을 누락하거나 신기능과 중복 합산하지 않는다.

광고는 장기 후보다. Google Ads 집행과 AdSense 수익은 별개이며 수집 자료의 이용 범위와 광고 심사는 도입 시 각각 다룬다. 자동 복제 페이지 대량 생성으로 승인을 보장하지 않는다. 유료 홍보와 일반 정보의 근거는 구분한다.

## 11 유지 범위와 연결 문서

메인(`/`) 상단 하이라이트·실제 캘린더·CalendarPage의 PortalStage 연결, PortalStage·PlatformMiniSpotlight·공통 Header/Footer의 구성·디자인·동작은 유지한다. 목록·상세 변경은 본문에 한정한다. 시안용 캘린더로 교체하지 않는다.

32번은 경로별 수집·자동화·직접 할 일, 23번은 논리 데이터 설계, 24번은 개발/비용, 30번은 첫 출시의 포함/제외·완료 기준이다. 25~29번과 31번은 과거 후보/장기 참고이며 SSAPI 문의·채팅 분석·게임 비용을 현재 선행 조건으로 승계하지 않는다. 상급자 보고는 [상세 v2.1](../output/pdf/VDebut_Data_Strategy_Executive_Report_2026-11-11_v2.1.pdf)과 [1쪽 요약 v2.1](../output/pdf/VDebut_Data_Strategy_Executive_Summary_2026-11-11_v2.1.pdf)을 따른다. 이전 v1.1/v2.0 보고 자료와 개정된 수집량을 혼용하지 않는다.

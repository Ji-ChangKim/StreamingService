- **문서명**: 운영 전환 누락 점검·검증·적용 및 복구 절차
- **버전**: v1.7
- **최종 수정일**: 2026-10-11
- **작성자/담당**: Codex 작성 · 프로젝트 담당자 운영

## 1. 운영 데이터와 개발 데이터

운영 공개 API는 346개, 개발은 309개다. 서로 다른 D1을 사용한다. 공통 식별자의 UTC 일정은 같으며 운영에만 40개, 개발에만 3개가 있다. 개발에만 있는 채널 검색 등록 3개는 데뷔 일정이 없는 소개로 분류한다. 운영 업데이트는 운영 DB를 그대로 사용한다. 개발 DB를 운영에 덮어쓰지 않는다.

배포 전 운영 스키마를 읽기 전용으로 확인했다. 공개 프로필의 식별자 누락은 없고, 기존 관리자 3계정과 기존 신청 3건(APPROVED)이 있다. 당시 새 포털 테이블은 없었으며 이번 배포에서 0036만 추가했다. 기존 통계 채널·회차 인덱스는 이미 있으므로 0035를 다시 실행하지 않았다. 0034 등 과거 데이터 SQL도 일괄 재실행하지 않았다.

실제 공개 스키마와 346개의 공개 정보만 로컬 격리 SQLite에 넣고 0036을 두 번 적용했다. 기존 이름·식별자·UTC 시각이 유지됐고 새 접수는 0건이었다. 계정 비밀번호·비공개 문의·연락처는 복제하지 않았다. 공개 스냅샷은 Git 제외 경로 `.cache/live-release/`에 둔다.

## 3. 검증 결과

- 프런트엔드 타입 검사 및 Vite 빌드 통과.
- 백엔드 TypeScript 검사 통과.
- 백엔드 23개 + 프런트엔드 10개, 총 33개 테스트 통과, 건너뛴 테스트 없음.
- 실제 Worker 경로와 격리 SQLite를 사용해 등록 → 관리자 승인 → 공개 API/소개/사이트맵 → 관리 삭제 검증. 원격 시험 신청·운영자 로그인·Discord 시험 발송 없음.
- 비인증 관리자 경로, 과거 고정 서명으로 위조한 토큰, 기존/새 로그인 경로의 제한 우회 거절 검증.
- 한·일·영 번역 키와 동적 원문 보존, 언어별 검색 정보, URL 조건 보존 검증.
- 외부 플랫폼 검색 테스트의 DNS 연결 실패는 오류 처리 경로 통과를 의미하며, 실제 외부 응답 성공 검증으로 간주하지 않는다.
- 운영 대상 Wrangler dry-run은 DB 이름·환경 변수·자산 번들 확인용이다. 실제 운영 업로드나 SQL 실행을 의미하지 않는다.
- 브라우저 실제 heap/LCP/INP 수치는 측정하지 않았다. 이를 최적화 완료의 실측 수치로 주장하지 않는다.

3개 언어 사전 추가로 메인 관련 JS는 이전 약 207KB에서 약 239KB(비압축)로 늘었다. 새 관리자 CMS 477KB는 운영자 경로에서만 내려받는다. 최종 자산 크기와 개발 배포 식별자는 아래 후보 검증 기록에 남긴다.

## 4. LIVE 적용 및 복구 절차

명령은 `backend` 디렉터리에서 실행한다. 운영 적용 직전 공개 API 식별자·이름·UTC 일정, 현재 배포 버전과 D1 Time Travel bookmark를 다시 읽어 저장한다. 현재 점검 값만 복구 기준으로 고정하지 않는다.

점검 시 운영 버전: `b3a869e3-41b3-444c-8abb-c5fc50b5e1fe`.

실제 적용 직전 D1 bookmark: `000013ea-00000000-00005101-1b25a0effb54708b4b2e19215a0588d9`.

```powershell
npx --yes wrangler@4 deployments list --env production
npx --yes wrangler@4 d1 time-travel info vdebut-db --env production
```

새 포털 테이블만 추가하고 나서 Worker를 적용한다. 0036에는 기존 데이터 UPDATE/DELETE/DROP이 없고 CREATE IF NOT EXISTS만 있다.

```powershell
npx --yes wrangler@4 d1 execute vdebut-db --env production --remote --file migrations/0036_portal_requests.sql
npx --yes wrangler@4 deploy --env production
```

운영 확인 항목: 메인/등록/소개/탐색/안내/통계/관리의 GET 응답, 공개 프로필 전체 식별자와 기존 일정 보존, 관리자 비인증 401, 개발 noindex와 운영 공개 index, 사이트맵 공개 소개 포함, 정적 자산 정상 응답, 한·일·영 전환. 관리자 계정은 바꾸지 않으며 기존 브라우저 토큰은 무효화되므로 재로그인이 필요하다.

실패 시 직전에 기록한 운영 Worker 버전으로 롤백한다. 포털 테이블과 접수 데이터는 보존한다. 이후 들어온 실제 접수가 있을 수 있으므로 테이블 삭제나 과거 DB 전체 복원으로 되돌리지 않는다. D1 Time Travel 복원은 별도 데이터 영향 검토가 필요한 복구 수단이다.

기존 `sync_live_to_dev.js`는 오래된 DB 이름과 로컬 import를 사용한다. 이번 준비나 LIVE 배포에 사용하지 않는다.

## 5. 개발 후보 검증 기록

- 개발 Worker: `streaming-dev`, 최신 버전 `3124c420-4e98-4c0f-8a8a-2d14ef7270e2` (달력 아이콘 보완 포함). 최초 후보 버전 `4bf4a4a3-f20d-4430-93bc-86a588590156`.
- 개발 공개 화면·등록·탐색·안내·통계·관리 GET 정상(200), 관리자 비인증 API 401. 관리자 HTML no-store. 개발 전체 noindex와 robots 차단 유지, 개발 사이트맵은 404로 노출하지 않음.
- 개발 소개 309개, 일정 API 306개(일정 없는 채널 검색 등록 3개 제외). 배포 후 LIVE 기존 일정 API는 346개 그대로.
- 브라우저에서 일본어 → 영어 전환 시 JP 국가 필터 유지. 영어 → 일본어 → 한국어 전환 시 등록 폼의 활동명과 소개 원문 유지. 신청 제출은 하지 않음.
- 360px 모바일 및 1280px 데스크톱에서 문서 가로 넘침 없음. 원본 로고, 하이라이트, 전체 일정 저장, 새 관리자 로그인 및 기존 CMS 로그인 진입 확인. 검토 중 브라우저 오류 로그 없음.
- 최종 메인 JS: portal-main 0.45KB + PortalApp 35.79KB + 공유 ErrorBoundary/번역 58.81KB + React 공통 143.55KB = 약 238.6KB(비압축), gzip 합 약 85.8KB. 기존 CMS 477.52KB는 lazy chunk 유지.
- 최종 운영 dry-run: Worker 527.88KiB / gzip 127.56KiB, 바인딩 `vdebut-db`, `PORTAL_ENABLED=true`. 업로드/SQL 미실행.
- 개발 배포 Worker 시작 시간 4ms. 이는 페이지 클릭 반응이나 Core Web Vitals 실측을 뜻하지 않음.
- 이 개발 후보 검증 시점에는 운영 변경이 없었다. 이후 실제 운영 적용 결과는 7절에 기록한다. 운영 시험 신청·Discord 시험 발송은 하지 않았다.
- 검증 이미지: `vdebut-live-candidate-desktop.jpg`, `vdebut-live-candidate-mobile.jpg`, `vdebut-live-candidate-registration.jpg` (이번 작업의 시각 자료 폴더).

## 6. 달력 플랫폼 아이콘 보완

사용자 참조 이미지에 맞춰 월간·주간 달력의 일정 앞 색상 점을 기존 LIVE의 플랫폼 아이콘으로 교체했다. CHZZK·SOOP·YouTube·Twitch 원본 파일을 공통 플랫폼 목록에서 참조하며, 16px 영역에서 object-fit:contain으로 비율을 유지한다. 필터·색상 가공·배경 추가는 하지 않았다. 기존 색상 점 CSS는 제거했다.

프런트엔드 타입 검사·빌드 통과 후 개발에 배포했다. 브라우저에서 월간 일정 13개와 일정이 있는 주간 보기 10개의 아이콘 로딩, 네 플랫폼 원본 아이콘 로딩을 확인했다. 검증 이미지: `vdebut-calendar-platform-icons.jpg`. 이후 7절의 LIVE 배포에도 포함했다.

## 7. 실제 LIVE 배포 결과 — 2026-10-11

- 사용자 요청: “그럼 라이브 배포”. 운영 Worker `streaming`, D1 `vdebut-db`를 사용했다. 개발 DB를 복사하지 않았다.
- `0036_portal_requests.sql`만 원격 실행했다. 기존 데이터 변경 없이 신규 테이블 3개와 인덱스 3개를 추가했다. 배포 후 기존 소개 346개·관리자 3계정·승인 신청 3건이 유지됐다. 새 포털 소개와 접수는 각각 0건이었다.
- 직전 운영 버전: `b3a869e3-41b3-444c-8abb-c5fc50b5e1fe`. 최초 LIVE 전환 완료 버전: `de90c983-c255-4eda-87b2-c783440109e8`. 이후 수정 버전은 8절에 기록한다.
- 첫 배포 후 통계 주소의 HTML이 SPA 기본 셸로 다시 매핑되는 문제를 발견했다. 포털 활성 시 지정한 HTML을 그대로 읽도록 수정했다. 실제 `serveSinglePageApp`을 사용하는 회귀 검증을 추가했고 관련 테스트 7개와 백엔드 TypeScript 검사를 통과한 뒤 재배포했다.
- 최종 Worker 549.95KiB / gzip 131.63KiB, Worker 시작 시간 5ms. 기존 예약 작업 `*/10 * * * *`, `0 22 * * *` 유지. 페이지 체감 성능 실측 수치로 해석하지 않는다.
- 운영 GET 점검: 메인·한/일/영 초기 HTML·등록·탐색·소개·안내·약관·문의·새/기존 관리자 진입·통계 3개 경로 정상(200). 통계 직접 접속도 새 포털 셸과 공개 검색 메타데이터를 사용한다.
- 공개 소개 API와 일정 API 각각 346개. 배포 전 전체 346개의 slug·이벤트 ID·활동명·UTC 일정이 배포 후와 동일하다. 사이트맵에 공개 소개 346개가 포함되고 관리자 경로는 제외됐다.
- VDébut 로고 및 CHZZK·SOOP·YouTube·Twitch 원본 아이콘 정상(200). 관리자 비인증 API 2개는 401, 관리자 HTML은 noindex·no-store 확인.
- 실제 LIVE 브라우저에서 한국어 → 일본어 → 영어 → 한국어 전환, 참조 레이아웃의 데뷔 등록 폼, 통계 메뉴 이동 및 새로고침 후 기존 통계 표시를 확인했다. 월간 달력의 플랫폼 아이콘 31개가 모두 로딩됐다. 검토 중 오류 로그는 없었다. 운영 검증 이미지: `vdebut-live-deployed.jpg`, `vdebut-live-calendar-deployed.jpg`.
- 원격 결과와 복구 기준은 Git 제외 경로 `.cache/live-release/`에 보관한다. 실제 시험 접수·관리자 승인·Discord 시험 발송은 수행하지 않았다. 등록부터 승인까지의 쓰기 흐름은 앞서 격리 SQLite에서 검증했다.

## 8. 새로고침 초기 문구 깜빡임 수정

## 11. SOOP 채널 배너 연동

사용자 요청에 따라 SOOP 채널 웹 API의 채널 아트를 조사하고 소개 상세에 연결했다. `api-channel.sooplive.com/v1.1/channel/{userId}/station`의 `channelArt.pcFilename`·`mobileFilename`을 확인했다. 강두식(`doosiki0505`)의 파일 경로를 SOOP 원본 이미지 서버 주소로 변환했으며 이미지 HEAD 200을 확인했다. 외부에 문서화된 OpenAPI 계약으로 확인한 것은 아니며 실응답에 근거한 연동이다. 자세한 규격은 [플랫폼 API 참고](../2.%20참고%20폴더문서/01_PLATFORM_API_REFERENCE.md)의 2.3절에 기록했다.
